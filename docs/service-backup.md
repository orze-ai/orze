# 已关闭服务的备份与数据恢复

`orze service backup` 为已完整关闭的注册 CPU 服务保存一致的数据副本，并可将其恢复到
一个新目录用于核验。它是迁移／回滚准备的一部分；恢复的数据保留原路径、执行代次和
预算历史，尚不支持从复制品启动新实例或跨版本迁移。

## 创建与核验

先通过原服务的注册停止流程关闭控制器和宿主，再执行：

```sh
orze service backup create \
  --service-config /absolute/project/service.json \
  --destination /absolute/backups/project-001
```

输出包含 `manifest_sha256`。将它与备份分开保存，用同一个值进行后续核验：

```sh
orze service backup verify \
  --backup /absolute/backups/project-001 \
  --manifest-sha256 SAVED_SHA256

orze service backup restore \
  --backup /absolute/backups/project-001 \
  --manifest-sha256 SAVED_SHA256 \
  --destination /absolute/restore-check/project-001
```

目标必须不存在，父目录必须已经存在且没有符号链接重定向。备份目标不得与源目录重叠。
恢复结果按 `root-000` 等名称保存各个源根，原路径对应关系见 `restored.json`。
命令不会改写配置中的绝对路径、启动服务、使用保存的 PID 或消费旧交接授权。
从复制的旧服务配置直接启动仍会被原所有权协议拒绝。

## 保存的范围

备份覆盖工作目录，以及不在其中的 results、数据库、控制目录、ideas／goal 文件、
配置、服务登记和 dotenv。外部必需路径分别列入清单；普通符号链接只保存链接文本，
不会跟随并复制其目标。原先缺失的外部已声明输入会记录并在完成前再次核对；
复制中途出现时拒绝完成。运行包保存身份清单，包安装文件、外部数据集和整机环境仍需另外准备。
备份可能含原配置及 dotenv 内容，按原项目的敏感程度保存。新备份目录权限为 0700，
对象和清单为 0600。恢复保留普通读／写／执行权限位，不复原原 uid／gid、时间戳、
setuid／setgid／sticky 位、ACL 或扩展属性；依赖这些系统元数据的部署需要另行准备。

默认总数据容量为 4 GiB，可用 `--max-bytes` 显式调整；当前最多 16,384 个目录／文件／
链接条目，目录深度最多 64。特殊文件、多个硬链接指向的普通文件、超出容量、路径或
文件身份变化均会拒绝。不会静默截断并报告完整备份。

数据库通过 SQLite 的一致备份接口生成，原库及其辅助日志文件不会被当成普通文件
逐个拼接。注册控制器现行的共享数据库策略仍要求 DELETE 日志模式；WAL 状态不属于
这个入口接受的关闭状态，不能通过备份绕过原策略。

## 完成和不确定性

创建时重新验证旧宿主／控制器关闭、历史结算和原运行版本，并持有数据库写锁，阻止
另一个后继在复制过程中取得数据库写入权。文件按捕获身份复制，源目录及关闭记录再次
核对通过后才发布完成记录。恢复也在完成前重新核对全部目标内容和目录结构。

目标碰撞不会覆盖已有文件。异常会保留已经创建的内容，返回 HOLD；不删除源文件，也不
递归清理不确定的目标。文件名已经创建但同步回复失败时，名字可能仍存在；命令失败不等于
所有名字都不存在。`verify` 校验当前可读内容与保存的摘要，不证明一个失败调用曾收到同步确认。
没有保存的摘要或缺失有效完成记录时，不将目录视作已核验备份。

备份是某个关闭时点的数据，不锁定原项目的未来。原项目随后按既有流程恢复后，新支出和
新结果不会进入旧备份。不能用旧备份覆盖当前状态并因此忘记已发生的成本。
将历史数据变成新的可执行作用域，需要单独的迁移协议和预算衔接；目前仍属于原交接的未完成项。
