# 原生研究入口的32次新任务前瞻对照

在首个研究请求之前冻结。主问题：通过更强且互补的研究模型、较小的提案批次和原生实测反馈，能否相对实际Sonnet研究角色减少至少30%的最终验收达标时间。所有原目标门槛保留。此前混合ParallelRefine的42.8796%开发收益只用于候选选择，不能继承为本轮结果；当前候选使用现有原生角色，属于新的完整组合。

## 两组与共同入口

- control：现有原生research角色，custom后端转接同一个已认证Sonnet CLI，实际主模型必须是claude-sonnet-5。每次三个方法，最多两次，共六个提案。CLI保持单轮、无工具、无hook、无自动重试；辅助Haiku用量也记录。
- candidate：两个现有原生research角色，分别为claude-opus-5和claude-opus-5-5，直接Anthropic调用，high effort、32768输出上限、900秒提供方超时，无后备或自动重试。每角色每次一个方法、最多三次，共六个提案。它们通过原生公共上下文读取同一项目已完成的源码、测量和失败。
- 两组均通过`python3 -m orze.cli`持续运行，原生接纳、GPU所有权检查、执行、数据库完成记账、反馈组装。角色cooldown900秒、控制器poll30秒、原生低积压提前触发保留，不使用人工触发。模型准备可以与GPU执行重叠；同一实例的GPU方法串行。
- 共同Core/Pro包含已验证的响应兼容、短暂入队争用、实测反馈重读修复，Slurm设备映射修复也双方共用。此对照是在当前共同修复上的实际Sonnet入口，不将旧Opus5模拟器称为部署默认，也不声称与历史版本逐位相同。
- 相同研究SOP、任务规则、共同参考和独立验收。可自由改变算法、表示、估计器或优化方法，诊断/反例可在方法内实现；不限定调参。原生提案合同为完整方法，未增加独立分析动作、评审层、任务专用模型路由或新调度器。
- 这是模型、角色并发和提案粒度的组合比较，不能将收益单独归因于某一个组成。CLI与直接API的协议差异、实际输出用量和模型身份全部披露。

## 四领域八任务、两重复

六个公开真实数据集：视觉EMNIST Balanced、SVHN；文本Banking77、DBpedia14；回归YearPredictionMSD、Online News Popularity。生成优化问题类：20工件15机器调度、512点加权4/6正则图最大割。生成实例不称为真实采集数据。

每任务两个已准备的独立划分/种子，每实例两组，共32次。完整清单绑定`prepared-reference-inventory.json`及数据、参考、源码、检查点哈希；所有新任务候选此前未运行。两重复可能共享公开数据来源，不是32个独立领域。不能声称基础模型预训练未知。

六个公开数据集沿用先前核验的分组、去重和私有行随机化；两个生成优化类已在独立校准数据确认2%目标有可行见证。校准见证不提供给模型。较密最大割校准失败、旧TSP门槛问题保留；此次新任务设计在任何候选结果前完成，不能根据本轮表现换任务、降门槛或删除优化领域。

16个共同参考已经完成32次准备、48次独立重载预测。仅按开发损失选择，确认/审计标签不提供给模型。六公开任务要求相对共同参考损失下降至少10%，两优化类至少2%。新闻指标预先为log1p分享量MSE。基线预检和校准均不计为研究成功。

## 资源与时间

同一Slurm独占八A10040GB节点，四个领域各一条成对执行通道；每对同时请求两个独占step，两者结束后该领域进入下一实例。按重复交替请求两组先后；Slurm决定实际GPU编号，记录UUID而不声称严格物理设备交换。不同领域互不读取研究结果。

每个step一GPU、两个逻辑CPU、12GiB祖先cgroup内存；PyTorch分配上限6GiB，其他CUDA分配仍受整张独占GPU约束。swap/pids无额外限额。所有方法使用相同不可变Enroot镜像，根目录只读、无宿主路径、无凭证、独立PID与网络命名空间；真实GPU计算、CPU集、显存和生命周期均记录。不同于旧80GB容器环境，不能直接比较旧墙钟。

训练加开发预测总限时900秒；单个确认/审计预测600秒。研究实例从原生初始化开始计时，7200秒最终交付截止，包含模型等待、准备、程序失败、训练、预测和宿主评分。研究前共同输入哈希检查及Slurm资源排队单独记录，不计为实例内策略时间。确认或审计在截止前启动但截止后完成仍失败计7200秒。

达到截止后禁止新提供方请求；在途请求仍结算，不重试不冒充免费。原生退出及提供方结算分开记录。goal-delivered早于completed时，只算交付时间，不隐藏后续已付费未用提案和清理代价。

## 独立验收

训练/开发、确认、最终审计四份数据隔离。宿主独立计算预测损失，不信候选自报分数或findings。仅开发分数决定候选选择；首次达到开发目标的新最佳方法有唯一确认机会，只反馈通过/不通过。确认通过才进行唯一最终审计；审计拒绝即终止。若预算/提案上限先到，开发最佳的有效改善方法有一次审计；无改善则失败。确认失败可继续探索，不能重复确认。

确认和审计同时要求相对改善达到固定目标，以及5000次配对组bootstrap的差值97.5%上分位小于0；这是描述性不确定性，不冒充严格有限样本保证。审计之后不再反馈分数、不再修改方法。模型与源码哈希绑定，重载仅在隔离worker内进行。最终计成功还要求该方法原生COMPLETE、独立核验有效且交付在截止内。控制器失败不能由宿主另跑方法补成成功。

任何无效源码、模型截断、预算未准入、提供方失败、程序失败或目标未解决均保留；未达标计7200秒。执行故障不等于科学假设被否定。先按任务两重复平均，再按四领域等权；禁止只平均成功者。

## 预注册默认决定

必须全部32次结束、所有在途请求/执行树闭合、独立评分与源码/数据绑定核验通过、所有本轮用量已知，才判断：

1. candidate四领域等权平均验收时间比control至少低30%。
2. 四个领域配对时间差(candidate-control)的双侧95%t区间上界小于0。
3. 至少三个领域时间更短，且每领域最终成功数不低于control。
4. 审阅实际代码、测量、反馈及后续决策，没有评测捷径或足以推翻能力解释的缺陷。

四个领域是统计不确定性的单位，不把32次当32个独立领域。“未观察到成功率下降”不是强统计非劣证明。未通过则不升级默认，不追着本轮结果改提示重跑。通过后还须将完整被测组合交付到产品默认入口并验证默认调用，才完成平台目标。也不据四领域一个配置宣布普遍科学创造力提高。
