# 小规模预检能力的开发对照（不是 30% 目标验收）

固定两个已观察过的开发世界 Fashion-MNIST / 电厂回归，各一组 control/pilot，共四次研究。不得据此改变默认、宣称泛化或达到 30% 目标。

两边使用相同 ParallelRefine、Opus 5 high / 32768 输出上限、两条路径×两步、两请求并行准备、每个任务串行实验、相同数据和基线。唯一干预是 pilot 提示及该 worker 的可选预检权限；不同时加入 inquiry 的跨分支证据。收益归因只能是这个组合，不能单独归因到接口或提示。

pilot 自己选择小实验；可继续复用中间模型或终止为无分数诊断。不得把自报测量当成外部得分。失败、诊断、等待、最终预测和未使用的并发请求全部保留。继续使用一份新确认及至多一次最终验收；开发世界的验收通过只表明该世界成功，不是新候选的独立泛化证据。未达目标仍按 7200 秒计。

GPU 0/1 用于 Fashion，GPU 2/3 用于电厂；旧冻结试验剩余优化任务固定 GPU 6/7，本开发对照不抢占这些卡，不修改任何旧输入或服务。模型准备与旧任务可能同时进行；服务排队会记入实际时间，不能把开发结果当独立速度估计。

每次研究保守预留上限 $4.50，总池 $18，最多 16 次模型请求。取自现有未分配授权，不释放正在运行的 $160 池；累计保守已分配 $4998.938525，不超过 $5000。没有自动模型重试或人工候选注入。

需要保留：原始提案和用量、预检 observations、继续/终止决策、开发得分、独立验收、请求和容器闭合；监督进程完成后独立重新计算结果。验证程序强制 development_only=true 和 default_criteria=false。没有新建定期监控。

后续：分析是否主动用了预检、预检是否有信息价值、是否误杀好方向、以及本次真实墙钟/成功率。候选修改只能在下一次试验中采用。最终 30% 目标仍需候选冻结后的新跨领域前瞻对照。
