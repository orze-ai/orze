# 内部验证单位的固定源码诊断

将错误反馈开发对照中已结束的 control 最终方法、evidence 最终方法各运行两份：原始按行切分，以及只把内部 StratifiedKFold 替换为 GroupKFold 并传入训练组身份。随机种子、折数选择、模型候选、特征处理、预算和训练/开发数据保持各方法原样。四项并发运行在 GPU 0–3 的独立容器，每容器 2 CPU、12 GiB RAM、900 秒；方法主要使用 CPU，不把占用 GPU 槽位当作 GPU 计算量。

变换通过 AST 只替换 sklearn 导入、给 skf.split 添加训练 groups 参数及所需 json/Path 导入；原始方法不修改，源码和输入在首次执行前冻结。GroupKFold 使用各方法原有的 shuffle/random_state 参数。选择按主题组划分会自然改变各折样本组成，这属于被检验的干预。

目的：检验内部验证单位是否改变模型选择和已观察开发集效果。只读训练标签/组、任务 seed 及开发特征；宿主重算已观察开发损失。没有确认/最终审计调用、没有研究模型请求，不写入原冻结实验。

这是人工设定的事后机制诊断。它不证明 orze 自主发现了修复，不证明最终验收、跨任务收益或研究效率提升 30%；耗时不能替代完整研究达标时间。若诊断没有选择收益，不把“切分更规范”包装成已证明的效率能力。
