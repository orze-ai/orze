# 三模型开发筛选结束：选择 Opus 5.5 进入前瞻验证

九次均通过原冻结协议最终验收，全部请求结算；47 份预测独立重算、42 个执行容器闭合，验证进程退出 0。这里只包含三个已经观察过的开发任务、每模型每任务一次，没有优化领域。**选择下一轮研究模型为 `claude-opus-5-5`；产品默认不变，30% 目标未完成。**

## 源码、测量与研究行为

完整九条被交付方法的源码说明、实际运行 findings、独立审计和文件哈希见 `method-review-final.json`。方法名称本身不构成创造力证据。

- Fashion：Opus 5.5 确实加载一个参考成员，只新增三个各 90 epoch 的成员，训练 137.4 秒，最终审计错误率 7.84%→6.96%，达到目标。control 交付方法训练八个各 246 epoch 的成员，训练 532.6 秒；整条探索到预算末交付更久。Fable 复用三个父成员并新增四个 220 epoch 成员，训练 547.5 秒。没有复用机制的单因素消融，不能将全部时间差归因给复用。
- Newsgroups：三模型都使用训练组信息评估文本方法。Opus 5.5 用内部组留出检验 word/char、NB 混合与自训练，独立审计错误率 28.65%→21.31%，但交付比 control 慢。更好的最终预测与更快达标是两个指标。
- Power Plant：Opus 5.5 首轮就测试“平滑低维物理响应更适合平滑模型”的假设；五折组验证测得 GP MSE 8.933、HGB 12.880、MLP 16.661，最终保留 GP/HGB。审计 MSE 9.834→6.640，下降 32.48%。control 第二轮得到 Laplacian 核回归为主的组合；Fable 第二轮才加入 GP，其单调约束树的内部结果较差且权重为零。三模型最终均通过，说明方法选择和探索路径有差异，不能声称只有某组具备研究思维。

按实际进程区间拆分，control/Opus 5.5/Fable 平均容器执行为 16.81/4.20/13.50 分钟，无容器执行时的模型等待为 4.62/1.11/2.26 分钟。区间重叠去重并截止到交付；这是占用 GPU 的容器时间，内部也可能执行 CPU 工作，**不是 GPU 利用率**。拆分支持继续检验方案效率，而不只是比较模型响应延迟。

## 下一步与论文原则

筛选后的模型固定为 Opus 5.5，下一轮只改研究模型；相同提示、执行方式、数据、参考和验收保持成对一致。继续四领域八任务、每任务两次、两组共 32 次，不删除优化领域。六个新真实数据集尚无研究候选结果，优化校准与共同参考预检不计入能力成绩。

这延续现有文献审阅的具体取舍：以失败证据定位能力缺口，保持改动可归因；保留完整方法和负证据；开发选型与独立后续任务分开。暂不增加评审器或新的搜索机制。完整四领域前瞻结果仍须同时满足至少 30% 更低均值、领域配对区间上界小于零、至少三领域更快、无观察到的领域成功率回退和独立核验闭合，才支持默认升级。
