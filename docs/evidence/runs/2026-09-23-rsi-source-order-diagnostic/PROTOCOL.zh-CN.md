# 完整源码选择诊断：运行前协议

前一确认选择开发对照已 16/16 完成并核验、结算。平均时间只改善 6.7164%，不晋级。下一问题是：不先执行全部方法，模型能否从完整源码中优先识别实际可执行、具有泛化依据且较快达标的方案？

运行前由 `freeze.py` 在离线检查通过后核对旧实验闭合、输入、15 份检查点与预算链。`plan.json` 为 frozen 且全部哈希/预算检查通过才允许入口发请求；冻结前不能启动。预算池上限 $24.3608，沿最新结算账本分配，历史 25 条未知费用继续保留。实际冻结、启动和闭合以相应 JSON 原始记录为准。这是一次性有明确终点的实验，不创建定期监控或修改现有服务。

## 固定输入与盲评边界

- 使用上一轮 candidate 组首批的全部八对源码：KMNIST、Abalone、TREC、生成 TSP-320，各两次重复；不按成败或分数筛选。选这一完整集合是因为该组原本执行了首批两份，能够复用已有检查点而不重新训练。
- 每对分别按 A/B 与 B/A 展示，共 16 次计划评审。两次调用独立，没有先前评审结果或对话记忆；保留顺序不一致与 tie，不能挑更有利的顺序。
- 输入仅有当时可见的任务契约、资源/软件版本、共同参考与开发分数、调用接口源码和两份完整方法源码。不给候选执行结果、候选开发损失、确认/审计结果、隐藏标签或按结果撰写的评价。
- 初始提案只引用共同参考作为 parent；本诊断不评后续迭代方法，避免隐藏不同父模型训练历史后误比代码。
- 评审使用同一明确模型 Opus 5.5、high effort、4096 输出 token，无重试/后备；只返回 A/B/tie、具体理由和不确定性。理由不能当作真实测量。

## 固定测量，不改写旧研究

先关闭并保存全部评审，再在独立目录内对全部已有有效初始检查点做特征限定预测，使用相同资源和固定审计数据；原执行失败而没有检查点的方法仍保留为失败，不修复或重训。共 15 份有效检查点和一份原执行失败，实际字节及清单必须在新请求前核实冻结。原始实验和其最终统计保持不变。

这是已经观察任务上的事后开发诊断：可以测量偏好顺序稳定性、是否优先选中独立达标方法及对应计算成本，不能重建改变执行顺序后的探索轨迹、模型等待或最终达标墙钟时间。重新预测可能因按时间预算运行而产生差异，必须保留，不择优挑原预测或重测预测。

比较采用：优先比较方法的独立验收资格；两者都合格时，再比较原开发执行加本诊断预测的计算时间。两者都失败不能算有意义的能力排序胜利。源码评审时长、未知用量、解析失败、无检查点、未使用提案分别记录。此指标是选择诊断，**不是平台研究达标时间**。

### 晋级条件（首个评审请求前固定）

同时满足以下条件才支持进入新的真实在线开发对照；独立核验通过仍是必要条件：

1. 16 次评审响应全部满足约定 JSON 格式、模型身份和已知用量；无重试。解析失败和 tie 的主选择回退到原先首先执行的方法，但解析失败使本诊断不晋级。
2. 至少 7/8 对在正反展示中映射到相同方法（tie/tie 计稳定，但不算正确的明确偏好）。正向偏好始终作为主选择，反向仅检验一致性，不能择优。
3. 至少 6 对存在真实可比方向：一份独立审计合格而另一份不合格，或两份都合格但执行成本相差至少 10%。两者都失败、或两者合格且成本近似相同，不计可比胜利。明确主偏好至少选对这些可比案例的 75%，向上取整；不足即不晋级。
4. 每个任务类的主选择合格数不低于原先首先执行方法；还须至少多一份合格首选，或下述计算成本代理均值降低至少 30%。小样本“无观察退步”不是强统计非劣证明。

计算成本使用原开发容器从启动至闭合的时长，加本次审计预测容器从启动至闭合的时长；主选择再加同对两次评审的最早启动至最晚结算跨度。未合格计 7200 秒，合格成本也截于 7200 秒。这只是固定已有方法上的选择成本代理，不包括后续探索、首次开发门槛/确认路径或全队列等待，不能称为真实研究目标达标时间。

### 请求与执行资源

- 两并发、16 次固定评审，high effort、4096 输出 token；单请求 provider 超时 300 秒、进程外层 360 秒，超时保留全部预留，无自动重试/后备。只有所有评审进程结束且用量已知后才开始补充预测；未知用量时停止进入预测阶段并保留原始失败。
- 预测保留固定四对 GPU：KMNIST 0/1、Abalone 2/3、TREC 4/5、生成 TSP 6/7；每对的 b0/b1 分开执行，第二重复交换 GPU。每对完成后再运行下一重复，同 GPU 不重叠。
- 沿用相同固定镜像、每容器 2 CPU/12 GiB/约 6 GiB PyTorch 显存、离线只读环境；只挂载方法自身的既有检查点、源码和 audit 特征，隐藏标签只在宿主评分。监督预测限时 600 秒、优化 1800 秒，不训练、不加载检查点到宿主。
- 原模型方法的代码/检查点、共同参考、数据、评审输入、研究运行器与评分规则在新请求前哈希冻结。旧研究不重启，不修改旧文件。所有新增输出只进入本诊断目录。
- 评审资格使用固定目标幅度与同一分组 bootstrap 上界小于零规则；这是复用旧 audit 数据的开发诊断，不能冒充新的未见评测。模型返回解释只作待核查理由，不当实测事实。

晋级只允许新的在线对照，不能直接改默认。原跨领域 30%、新任务、配对不确定性与实际入口集成要求完全保留。

## 文献与简化

[SIFT 第 4.2–4.3 节](https://arxiv.org/html/2609.19526v1) 使用完整源码提供相对排序信号，仍需要真实评估，其大部分加速还来自异步执行。这里先检验最小的两方法选择，不复制 Bradley–Terry、整棵树或多级评审。论文中代理程序排序的结果不能直接推出研究方法排序有效。

[RRSI 第 3 节](https://arxiv.org/html/2609.24972v1) 强调可归因改动、保留已失败机制及后续迁移。本诊断保留“比较越多不一定越快”的负证据，使用已有源码与检查点降低验证成本；不把事后挑选推广成通用能力。
