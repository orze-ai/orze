# 开发错误证据对照：不支持升级默认

一对已观察的 Newsgroups 任务，采用修复后的组隔离与随机行序，重新训练共同参考。两组的模型、ParallelRefine、提示和验收相同，evidence 仅增加总体/类别错误、混淆、随机反例和正确对照。它是开发试验，不能用于证明跨任务平均提升 30%。

## 最终结果

| 指标 | control | evidence |
|---|---:|---:|
| 最终验收通过 | 1/1 | 0/1 |
| 最终审计错误率 | 24.9224% | 26.2034% |
| 相对共同参考的最终改善 | 13.0081% | 8.5366% |
| 最终交付时间 | 6.71 分钟 | 15.46 分钟，未达标 |
| 协议达标时间（失败记 120 分钟） | 6.71 分钟 | 120 分钟 |
| 已发模型请求 | 2 | 3 |
| 预算未准入 | 0 | 1 |
| 已付费未使用提案 | 1 | 0 |
| 无效程序尝试 | 0 | 0 |

共同参考最终错误率为 28.6491%。evidence 确实降低了错误，其配对差不确定性门槛也通过，但改善幅度没有达到固定 10% 目标，所以最终失败；不能把开发改善或统计显著当作完成目标。

独立核验通过：12 份预测重算、12 个容器闭合、5 次模型请求用量已知，验证进程退出 0。一个开发任务不足以估计跨任务置信区间。结论是不升级当前候选，不是证明“错误证据永远无效”。

## 实际使用了什么证据

evidence 第一批确实引用了类别混淆和稀有类别错误，提出字符特征、多种线性分类器集成、类别先验调整；后续进一步提出文本近邻图传播。这证明信息被看到并影响了解释，不证明解释正确或因此提高效率。

模型内部测量否定了若干想法：自训练和早期先验匹配未启用；最后一次图传播系数实际选为 0，仅保留较弱的先验调整。不能把“提出并实现了图传播”写成它带来了最后的改善。也不能把词袋证据弱、同主题文档几乎同标签等猜测当作已证实的机制。

control 的最终方法是词/字符特征与 LinearSVC、ComplementNB 的小型组合，训练内部交叉验证中拒绝自训练。复杂度较小的这次实现最终更早达标；这不是“所有小模型都更好”的一般结论。

## 新诊断：内部验证的单位与最终目标不同

四个已执行方法均在训练数据内部按行随机切分。使用同一个固定容器镜像、相同源码所声明的切分规则重建后，三个 3-fold 方法的验证行中约 **64.67%–65.25%** 与内部训练共享主题组；另一个 20% 留出方法为 **67.34%**。最终外部评价要求主题组隔离。对照的 GroupKFold 划分交叉组重叠为 0，但本次没有重新训练或评价它。

这只证明验证单位不匹配，不证明它造成了本次失败或修正后会提速。两组都受影响，不能把它当作 evidence 独有问题。内部准确率高于外部结果也可能来自数据量、类别组成等其他差异，不能直接把全部差值归因于主题组混用。

原执行器已只读挂载 `/train/groups.json`，没有证据显示缺少数据权限；API 与提示未显式说明该路径，也未把组身份列为训练属性。下一候选应检验把现有验证单位和可用组信息明确提供给研究程序，是否改善内部实验选择，而不是继续叠加未证实的反思流程。保持研究者可选择分析方法，不强制某个算法或固定诊断配额。

重建只读取训练 groups/labels 与任务 seed；未读取确认/审计文件，没有模型请求、方法训练或修改原冻结试验。相关计划、源码、结果和容器闭合回执一并归档。
