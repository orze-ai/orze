# 混合模型开发对照：首批闭合实例的研究过程复核

这是运行中的只读诊断，不是最终结果或晋级决定。快照时间为 UTC epoch 1790154510.4102955：16 次中 6 次结束，5 次最终验收通过。其余实例仍运行；不能平均这些先结束的实例来宣布胜出。输入是已观察开发任务，不能证明新任务迁移。

`closed-episode-review.json` 覆盖当时全部六个已结束实例。直接读取保存的预测和标签，独立重算 25 份预测的损失及确认/审计改善幅度，均与原记录一致。没有执行候选源码或在宿主反序列化检查点。完整冻结核验、全部调用结算和最终均值仍待整轮结束。

## Abalone：能利用反馈，但不能把组合改动当单因素证明

- control 的 b1-s0 开发改善 11.37%、确认改善 20.68%，最终审计仅改善 **9.595%**，未达到固定 10% 门槛。虽实际约 5.44 分钟退出，按协议仍计失败 120 分钟。
- candidate 的 Opus 5.5 分支 b1-s0 报告高斯过程交叉验证耗时 395.97 秒、组合权重为零，总训练 419.10 秒。这些分项是候选报告；宿主执行记录为 420.49 秒。
- b1-s1 的实际请求含上述自身分支记录。新源码删除高斯过程、增加两轮分组交叉验证和其他模型，只重训非零权重成员。宿主执行 124.60 秒；开发改善 10.15%，确认改善 19.88%，最终审计改善 **11.456%**，12.50 分钟验收交付。
- 这表明模型实际使用了已测成本和效果来修改方法。但多项改动同时发生，不能把通过验收归因于删除高斯过程，不能把约 296 秒的单步差异当作整轮或通用研究提速。首次高斯过程成本已经发生，仍全额计入研究时间。
- 新方法所谓的 “nested” 分数只在共用折外预测矩阵上重新拟合组合权重；底层模型没有针对外层留出折重新训练。不能据此宣称整个选择过程有完全独立的嵌套验证。最终独立验收仍由外部预测评测决定。

## KMNIST：两个模型互补不保证更早交付

- control 的 Opus 5 方法训练六个网络，各最多 120 个 epoch；记录训练 355.07 秒，最终验收交付 **8.37 分钟**，审计错误率 1.28%。
- candidate 先执行的 Opus 5.5 方法在源码中固定 `total_budget = 740.0`，三个网络按时间结束，分别跑了 507 / 567 / 565 个 epoch；记录训练 745.05 秒，交付 **13.64 分钟**，审计错误率 1.50%。两者都通过。
- candidate 的另一份已付费提案没有执行。这次更快返回模型响应没有带来更快交付；先返回的长训练方法占用了该实例串行执行位置。不能从这个案例推出缩短训练必然仍合格，也不在运行中改变顺序或时间限制。

## 与最近 RSI 论文的对应

[ScienceBuddy §2.3–2.5、§7.2](https://arxiv.org/html/2609.17523v1) 将固定模型的程序修改与模型训练分开，并在模型变化后重新评估继承的程序。其固定模型案例只改指令和 scoped skill 文本，执行循环和预算不变；独立验证正确率 31.1%→51.1% 不是研究达标墙钟时间。具体单项技能效果没有单独消融。

本地推论：记录真正进入下一次请求的测量、实际源码改动及外部结果，才能判断反馈是否被使用；模型更换后不能沿用旧程序收益承诺。当前 Abalone 提供一条有用过程证据，KMNIST 同时提供反例。先等固定资源对照结束，不据先完成案例追加提示、评审层或 RL 流程。

[Recursive Criticality §3.3](https://arxiv.org/html/2609.00137v1) 区分基础生产率与递归反馈放大；其关键参数和时间轨迹是条件示例，尚无直接经验校准。这里只用于澄清概念，不能当作 orze 已提高 30% 的经验依据。

## 后续决策保持不变

按原门槛结算全部 16 次，包括无效、未准入、付费未用和失败。即使开发对照晋级，仍须在新任务及实际研究入口验证 30% 达标时间收益。保留全部反例，不根据这些中途观察更换默认或冻结实验。
