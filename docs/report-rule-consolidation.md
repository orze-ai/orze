# 报告只读规则收敛（S1）

本片只有三个生产文件变更，不引入新模块、持久状态或外部依赖。

- 数据列选择统一使用现有 `orze.reporting.evidence.dataset_metric_keys`；原顺序、重复列和 WER 兼容行为不变。
- 旧归档数值过滤统一归 reporting 层的 `legacy_archive_metric_value`。它保留原函数算法与输入异常，不是当前产物、生命周期、benchmark 或科学资格检查。
- `engine.rebuild_state._report_dataset_keys` 和 `_eligible_metric` 为兼容别名，指向同一公共函数对象，不保留代理函数或第二套算法。Pro 不再导入这两个引擎私有函数。

不能混合的语义：旧归档在已声明列的有效计数为零时仍可回退历史 WER 字段；当前资格规则并非如此。此次没有“统一”这两个不同的契约。Pro 的 `qualified_entries=None` 仍表示显式旧归档查询，`[]` 仍是当前资格集合为空，不退回缓存分数；正常研究上下文继续使用同一合格证据集合。

基线行为测试应为绿色；四个新架构要求在旧代码失败，在收敛后通过。这些结构红测不是四个历史运行缺陷。所有旧测试原文件保留，新测试只描述现有行为并约束新的调用关系。

简化指标：列选择函数体 2→1，Pro 对重建引擎私有函数依赖 2→0，归档算法仍只有一份；计入解释性文档字符串后，生产源码净减 4 行。整个技术栈的规模和维护成本没有据此被宣称大幅下降。

这里只验证固定配对开发分支。没有发布新版本、部署、生产授权或真实科研收益声明；原先的执行、预算、恢复和跨领域测试作为兼容回归重跑，不把这次重跑称为新的独立留出实验。
