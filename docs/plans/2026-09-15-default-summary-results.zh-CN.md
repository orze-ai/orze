# 默认研究上下文摘要与数据库作用域修复

基于 Core `bf4880fc559d54c236afade2807d985637819b85`、Pro `c960df76382fc882a3ecbc06e70215e8623482e3`。默认研究上下文原先保留全部合格报告，实际只展示前十／后五并分析最多 5,000 个配置样本；现在逐条核验全部候选，只保留这些消费者需要的数据。实际 HTTP 验证同时发现并修复默认调用未把配置数据库传给完整去重和谱系检查的问题。

## 保留范围与次序

新摘要保留精确合格总数、完整 Objective 次序的前十／后五报告，以及只含 ID／主指标的最多 5,000 个配置样本。展示保留原全局行号、最佳记录的错误分析和中间省略数，小于等于十五条时不重复首尾。配置样本遵循原始主指标排序，并用完整 Objective 次序保持并列关系；测试覆盖大于浮点精确整数范围的值，不能仅以转换后的 Objective 主键替代原配置排序。

每个候选仍核验当前生命周期、声明指标及来源身份；完整退出才发布摘要，晚期数据库提交、结构／路径变化丢弃整份临时结果。旧 Core 缺少分批生命周期接口时明确不可用，这比旧全量入口更严格。公开完整排名接口、已有前十消费者和显式分页保留；配置统计使用同一批当前合格证据选出的样本。

这些限制针对保留的记录数量。单条 ID／报告／配置字节、作者源、其他上下文步骤，以及实际研究的完整去重和谱系集合仍可能增长。展示标题缓存沿用原有 2 MiB 文件读取限制，其临时 JSON 对象也计入 tracing。资格核验仍读全部历史，来源文件并非在一个联合原子快照中读取；配置元数据也仍是单独读取阶段。内存组件改善不等于全流程或 RSS 的硬上限。

## 实际消费路径暴露的默认数据库问题

首个 5,500 条历史项目中，实际 provider 正确读到合格最佳 B、配置模式和 B 的错误分析标记，但提案被谱系检查拒绝。默认上下文内部已解析配置数据库，后续完整去重／谱系却仍接到空路径；显式分页原先通过 pager 传递了正确路径，默认路径遗漏这一处理。原现场保留了两个 CLI 退出 0、一次 HTTP 请求、业务结果 genealogy_rejected 和零 CPU 执行，不能把 CLI 退出码当作产品通过。

现在在上下文构建前统一解析当前调用的数据库，并继续传给完整 ID 去重与谱系读取。配置相对路径、显式相对／绝对路径及默认推断路径均按项目根解析；缺失数据库不创建。过滤规则保持原件。这会恢复默认调用原先漏掉的全量读取，不把旧错误拒绝与新成功调用作为同质量速度对照。

## 基线、失败和定向验证

既有基线 140 项通过、15.81 秒。固定夹具在 262 条真实合格观察上各附加一个 64 KiB 未展示字段，旧完整上下文 traced peak 为 23,027,168 bytes，超过该夹具的 8 MiB 阈值；保留 1 项失败、3.33 秒。这个阈值只验证固定输入，不是任意报告或进程预算。

新增摘要测试 23 项，首轮定向 163 通过、23.24 秒。实际路径失败后，新增五项默认作用域测试；第一次为三项真实谱系失败加一项测试的 Markdown 字段预期错误（4 失败／1 通过）。修正预期后，旧源码三项失败、绝对路径与缺失数据库两项控制通过。修复源码后最终定向 217 项通过、31.50 秒；原测试和两轮失败日志均保留。

最终源码差分保存 26 组排序／抽样完整输出、16 组完整上下文原文一致，并检查四组明确的失效行为变化。修复作用域前的差分也单独保留。一次差分脚本组装的路径断言在写文件前失败，未执行候选；首次正式计时脚本调用了辅助函数迁移前的位置，在第一组输出比较时退出，零计时样本。原脚本和失败夹具保留，修正版另存。

## 实际 HTTP、CPU 和重放

两个独立默认研究项目，各导入 5,500 条历史及真实本地报告文件，不启用显式分页。只有末尾十六条提供 A／B 配置元数据，关键来源位于后部；普通项目合格数 5,500，污染三条关键 B 后为 5,497。每次配置样本为 5,000 条，完整去重仍单独读取全部 5,500 个历史 ID。

真实 research CLI 经 custom HTTP backend 调用 loopback 确定性 provider。provider 从实际提示词读出前十／后五的全局行号、省略数、配置模式及最佳记录的错误分析标记。污染后配置偏好由 B 变 A，parent 从 idea-history-5495 变为 idea-history-5484。真实 CPU 产物携带来源、变体、合格数、展示行号和错误分析标记。

最终共两个 CPU 动作、八次新进程 CLI、两次 HTTP 请求。正常决策合约、源锁、准入、TREE_CLOSED／ECHILD_WALL、结算、产物引用及重放四张表均核对；实际 HTTP 请求／响应、prompt 和原生 manifest SHA 关联。前述失败项目另计，不能混作成功执行。

导入历史与确定性 provider 不代表真实模型或科研收益。非流式模式显式配置，许可证替身仅在 Pro 子进程；Core-only 子进程禁用 Pro 导入时的可选扩展诊断保留。没有真实账户、GPU、既有服务或部署变更。

## 回归与封存

首次机械预核验错误地假定被拒绝、尚未执行 CPU 的原项目已创建 execution_attempts 表，因此检查器退出。原失败日志保留；新版检查器先只读检查表是否存在，再核对零执行状态，预核验通过。此修正仅涉及检查器。

Core 一次全量 5,046 通过、7 可选跳过、2 既有 warning，1070.16 秒；Pro 1,263 通过、322.16 秒；配对 31 通过、0.75 秒。集合有重叠，不能相加。完成运行的源码／测试输入冻结。15 份归档含 183,547 个文件，逐个核对压缩件、成员 SHA 与原目录字节。预核验 SHA-256：`8d38aacf024dbe7a2747045eb76b151ca5a6e0a0172dfb6d98b78817c2847d57`；最终机械核验通过，verification.json SHA-256：`c8b9b8811c0ded66c8618a11012ccc8593c30cce021a9990fb70708bdce6bb78`。独立进程机械检查不是另一位审阅者。
