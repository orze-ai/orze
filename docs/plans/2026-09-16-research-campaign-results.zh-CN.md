# 固定对照执行、采集与失败成本

## 结论

固定调度对照现在可以从完整协议执行到逐样本核验：按预先指定的 AB/BA 顺序运行，
调用正常 Pro 研究 CLI，执行原生 CPU 候选、独立评价和最终复验，保留失败及未知结果。
这是对照工具的进展，**没有新增真实模型研究收益证据**。

本次运行仅使用自有回环 HTTP 替身和 CPU，真实模型／账户／GPU／现有服务调用为零。
替身知道公开候选；A、B 使用相同代码，两类任务也用于验证采集接口。
这些数据不能充当有效的新旧版本科学对照或未见任务。

## 实现与边界

- 新增单样本采集器、独立子进程入口、调度工作流和成对批量入口；现有 CLI 增加 describe、execute 和 audit 命令。
- 在首次启动前核验完整计划和输入；子进程在执行前后观察实际 Core/Pro、公共采集代码及环境身份。
  核验同时匹配冻结模型参数与实际进程命令绑定，拒绝只改记录中的模型名称。
- 固定研究轮数；以实际候选字节复算分数，按声明种子排列评价顺序并复验最终选择。
  种子不控制远端模型采样。该入口不是任意研究任务适配器，也不是密闭执行沙箱。
- 外层时钟包含请求落盘、进程启动、模型与 CPU 工作、采集和进程树关闭。
  正常失败保留可核实的原生成本；超时／原件缺失／环境不符继续未知，不推定零调用或零费用。
- 所有计划样本保留分母。美元费用、GPU 用量、首次证据消费和确认选择延迟仍未知；
  因此当前 prospective 配对不会因其他列有数值而通过全部预算门槛。
- 现有 `src/` 产品代码和 Pro 源码未修改。采样设置、远端模型修订、真实账单、旧版本兼容性、
  多领域公平任务与真实研究收益仍需分别验收。

使用方式及输入格式见[固定研究对照执行指南](../research-campaign.md)。
总体收益判断仍见[研究进展评估](2026-09-16-research-progress-assessment.zh-CN.md)。

## 实际验证

| 检查 | 最终结果 |
| --- | --- |
| Core 新执行器、调度核验及既有比较器 | 88 通过，137.95 秒，1 个既有 pytest 导入 warning |
| Pro 研究／prompt／用量相关回归 | 636 通过，117.27 秒 |
| Core/Pro 配对集成 | 31 通过，0.70 秒 |
| 独立机械核验 | 18 次外层运行，50 个实际 CPU 动作 |

三组最终回归使用相同冻结源码。**本片未重新运行两仓全量测试**；此前全量结果不作为
新执行器的覆盖证明。这里选择直接受影响的研究、调度和计量链路，测试范围在原命令中完整保留。

两个有效／无效夹具各执行：一个单轮样本、四个两轮成对样本、实际导入路径不符、
首轮供应商失败、第二轮供应商失败和外层超时。有效候选价值为 30；重复作业候选被判无效。
两轮成功样本各有 5 个 CPU 动作、2 次替身调用和 10 个替身 token；缺失账单仍为未知。
第二轮调用失败时保留第一轮的 2 个 CPU 动作／4 秒预留，完整供应商成本仍为未知。
故意移走原始 run 文件后，该计划样本变为 unknown，四样本／两配对的分母保持不变。

## 原始失败与证据

- 初始缺少 campaign 模块：1 项失败，表示功能尚未实现。
- 首版接受改写后的模型命令：6 通过、2 失败；修正实际命令绑定后通过。
- 首个批量夹具重复提交同一配置被去重，且把无效任务误当 completed：82 通过、2 失败。
- 改成两个候选后，第二轮缺少父结果引用而被谱系规则拒绝；同时超时直接核验抛出缺失 worker 字段：
  84 通过、4 失败。夹具补充实际提示中的父结果引用，核验器先分类未完成样本，再读取完成文件。
