# Orze 通用 autoresearch：第一版实施方案

日期：2026-09-10。状态：方案定稿，实施与验收逐项记录；本文本身不代表功能已完成。

## 目标与基线

V1 交付一个可验证、可恢复、可替换研究策略的最小闭环，不把某个研究项目的调参规则、排行榜或算力限制变成产品默认值。

本轮从 core `5ca2680dbd0139e63cd35a4f83da438b5b47ab99` 开始。既有主干已经包含大量生命周期、执行身份、配额和研究反馈改进；历史审计是查找风险的线索，不是当前缺陷清单。每项先在最新源码证明缺口。已有能力通过验收则记录为“既有实现已核实”，不得冒充本轮修复。

所有实现使用独立分支 `feat/autoresearch-v1`。保护既有工作区及运行状态；不执行真实训练、付费 LLM 调用、线上迁移或部署。提交和推送代码不等于发布或生产验收。

## 不可变的产品边界

- Core：任务/尝试状态、持久交接、幂等、资源与预算、来源及产物引用。不能按领域指标名猜有效性，不能把算法经验写入全局调度。
- Executor：执行声明的动作，报告退出、耗时和产物；CPU/GPU 是资源选项，不是研究的定义。
- Domain adapter：参数校验、物化、评估协议、有效性及比较语义。
- Research policy：据目标、证据及剩余预算选择检查、实验、复验、分析、等待或停止；命名角色只是可选预设。

这些是同一 Python 产品里的逻辑接口，不要求微服务、分布式消息总线或向量数据库。复用现有 SQLite、subprocess、FSM、账本和适配器；旧配置经兼容路径继续工作。

强制每项任务有用途、输入、预算/执行界限和输出契约，不强制所有任务有假设、对照、统计检验。科学判决由领域协议或策略产生并引用证据，core 不承诺自动判定科学真理。

区分 specification fingerprint、task ID、唯一 attempt ID、artifact ID、evaluation/observation ID。同种子复验不等于意外重复；一个任务可以没有测量或产生多个测量。比较必须能表达缺测、无效、不可比、未知及领域定义的关系，不能把它们全部压成“统计平局”。

## 实施顺序与完成条件

按下表顺序推进。一个条目只有在目标回归、相关集成、独立复核和提交证据齐全后才关闭；后续条目可先做只读检查，不并行修改相互依赖的行为。

| ID | 交付 | 必须成立的验收 |
|---|---|---|
| V1-00 | 固定主干基线与测试环境 | 记录两仓 SHA、源码导入位置、测试命令与基线结果；环境/授权测试替身与产品功能测试明确分开 |
| V1-01 | 一致的 Objective/有效性入口 | 最小化/最大化、零/负数、缺测/非有限数、partial、协议不匹配都按声明处理；历史上下文与排名不互相矛盾；无全局领域哨兵；无依据不宣告统计等价 |
| V1-02 | 状态与任务交接 | 合法终态保持一致；重复请求幂等；并发追加不丢提案；触发 payload 到达真实消费者；启动失败可恢复；过期尝试不能覆盖新尝试 |
| V1-03 | 错误与背压 | 共享账户的配额失败阻止同账户空转，不冻结健康账户或实验执行；空输出/拒绝/崩溃可区分；持久队列而非空 inbox 决定需求；无新证据不无条件启动角色组 |
| V1-04 | 有界、有状态的研究上下文 | 退役/未证实方法不作为已证实配方注入；反馈保留来源与原因；必需契约不静默截断；上下文预算可检查，项目 A 的知识不污染 B |
| V1-05 | 执行、评估与来源 | 产物完成不等于测量有效；评估失败后可补评，不重复昂贵生成；显式复验保留独立尝试；清理不搬动项目源码或其他任务的产物 |
| V1-06 | 策略/领域/执行的最小接入闭环 | CPU 动作不必伪装为 GPU 训练；策略可选择 wait/stop/复验/分析；通过已有调用路径验证，不接受未接线的接口或仅增加 dataclass |
| V1-07 | 跨领域、兼容与证据汇总 | 两个异构 CPU 任务及一个冻结方案后独立选择的任务用同一 core；旧配置回归通过；故障注入覆盖恢复与负结果；每个完成声明链接测试及 commit |

固定 schema 的校验可在入队做；资源、依赖、授权、撤销等动态条件必须在派发时再检查。恢复既包括启动检查，也包括运行中的租约超时与 worker 丢失处理。

文件可以存放不可变产物；权威生命周期与派生视图的语义必须明确。视图一致性以相同事件版本/查询条件核对，不要求不同过滤条件的 completed 数相同，也不把最终一致的 UI 当作原子事务读。

租约不能让任意外部副作用获得 exactly-once 语义。承诺持久任务、幂等消费及可恢复尝试；副作用已发生而 ACK 丢失时，能核验的产物可以接管，不能核验的非幂等任务应显式标为不确定，不能盲目重做。

## 每项的证据流程

1. 在冻结基线或前一项提交上添加目标回归，先看到预期行为断言失败。依赖缺失或 import 错误不是有效红测。
2. 最小修改接入真实消费者；运行同一红测得到绿测，同时覆盖反例与兼容路径。
3. 对状态/并发/恢复使用临时数据库、barrier、假时钟或本地子进程故障注入；不要只 mock 掉被检验的核心行为。
4. 由未编写该修复的审查者检查 diff、测试是否可能假阳性及遗漏的负例。
5. 明确文件暂存，独立 commit，推送本项分支；核对远端 ref 与本地 SHA。证据记录基线、命令、退出码、测试数量、限制与修复提交。
6. 每项更新独立的实施账本。发现新缺口应新增条目或明确未完成，不能降低已冻结的验收标准。

生产 license、付费 provider、GPU 和网络服务不在离线测试中伪装为已验证。可使用明确的测试替身验证框架边界，但不能修改生产授权逻辑或借此声称真实集成通过。

## 验证矩阵与非目标

- 确定性算法任务：输出正确性与操作次数，避免用微秒耗时做脆弱断言。
- 系统任务：如编码/压缩，最小化大小并约束解码完全一致；合法负结果仍是有效观察。
- 留出任务：方案提交后由独立审查者选择，不为它修改 core 或调领域规则；若需要修改接口，该轮不再算留出验收。
- 故障：重复提交、旧 attempt 回报、进程中断、评估失败、部分产物、无效观测、配额窗口、退役知识、不同协议。

V1 不交付全领域科学平台、远程集群重写、统一信息增益估计器或自动论文结论。判决数与调用数只是诊断量，不是统一优化目标。记录运行效率、有效证据延迟、决策如何改变下一步，以及任务定义的效果。

测试能证明指定机制正确及故障下的行为，不能证明研究收益普遍提高或节省某个百分比 GPU 小时。真实收益需要另行授权、冻结协议和预算、逐 run 去重计量及重复对照；没有这类证据时状态只能是“机制已验证，研究收益未验证”。
