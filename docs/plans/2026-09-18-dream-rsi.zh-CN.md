# Dream-RSI 分析与 Orze 探索能力升级

2026-09-18。交付是可调用的 Core 探索／回放接口与 Pro 策略改进循环。它增加了检验和改进研究方式的能力；**尚未证明新的在线科研收益或创造性提升**。没有新增付费调用，没有将未经验证的策略设为全局默认。

论文 §3 的关键是让探索策略成为可执行程序：先在线积累带父子关系的尝试，再让其他策略只根据已揭示的结果选择后续路径，最后将胜者用于新一轮在线探索。优化的是研究过程中的分配决策，底层研究模型和评估器保持固定。其“不退化”保证只针对同一历史池上的平均回放目标，不是对新任务或新生成结果的保证。[论文 §3](https://github.com/zhengkid/Dream-RSI/blob/4149ea9181ab1db80f85717ffda2c9f0f130e85b/papers/Dream-RSI.pdf)

### 对实现最重要的细节

| 观察 | 对 Orze 的判断 |
| --- | --- |
| 正文是根／已揭示叶节点接口；附录 B.2 是预先声明的分支×尝试网格 | 实现采用明确网格，深度包括首个尝试；没有声称复现作者未发布的完整运行时。 |
| 正文目标组合最好质量、调用数惩罚、并行奖励；附录开发提示使用 beta 扫描、attainment AUC 与并行惩罚 | 两处描述不完全一致，不能声称逐字复现。按用户目标选择质量优先，费用与延迟另报。 |
| 附录强调完整轨迹、成功历史、失败的可修复性和动态探索组合 | 保留失败源码／产物；实现错误不产生负科学分数；后续成功结束当前失败段。 |
| 作者在 ConvDiv 上发现方向性历史提示可能压制探索 | 这是局部消融证据，不意味着所有经验都应删除。策略开发侧保留探索轨迹，移除科学源码与自由文本方向建议；研究分支仍保留原始证据。 |
| 在线生成是随机的，而回放读取固定结果 | 只能验证历史支持范围内的分配决策。改变生成器、共享上下文或父工作区后，旧结果不能自动沿用。 |

## Orze 原有缺口与本次改变

旧 `meta_research` 根据方法族统计生成自然语言研究建议，能够保存与回滚规则，但不能检验一套新的探索算法究竟会怎样分配实验。此前研究例程主要沿单条共享历史推进，不能据其结果推算任意独立分支的反事实成绩。

本次增加四项相互连接的能力：

1. **共享在线／回放接口。** Core 的 `run_online` 和 `replay` 共用决策循环。策略自由实现 `decide(view)`，选择新根、延伸现有路径、组成并行批次或停止；不局限于内置参数网格。实际执行仍交给调用方已有执行器。
2. **分支上下文与可恢复探索。** 每次生成只获得固定根状态和自己的完整祖先路径，同批结果在下一决策前一起揭示。成功分析可以没有质量分数；失败也可以保留待修复的程序。不会用伪造的零分代替未测质量。
3. **有支持边界的历史池。** 未探索的后续动作使该回放失去选拔资格；合法动作列表不偷看隐藏树的覆盖。未知成本／耗时保持 `null`。接口拒绝标记为回放的结果作为在线世界，实际在线来源仍由调用方证据链核验。
4. **可执行策略改进。** Pro 让开发回调根据训练回放提出新策略；正常 LLM provider 路径可生成策略源码供已有审查流程消费。坏策略保留错误供后续修订。训练胜者只验证一次，验证结果不反馈给这一轮开发者；保留现役策略作为比较对象。

选择规则刻意简单：相同调用上限内，训练平均质量必须严格提高，每个独立验证世界都不能退化；少花钱本身不能换来晋级。质量由任务事先固定的评估器定义，不由模型自己宣布；本轮未加入科学新颖性评估器。通过后返回供下一次真实在线运行使用的策略对象及选择记录，在线收益仍须另外测量。

这是显式 API 能力；旧 daemon、GPU 排程及旧文本规则模式没有自动切换。也没有增加第二套进程执行器、强制反思阶段或每轮总结。`execute_batch` 必须恢复所给分支的实际程序／工作区，并继续使用原有准入、预算和证据验证。Python 策略与回调是受信代码，这些数据接口不是沙箱。

使用与完整契约见 [探索接口说明](../research-exploration.md)。

## 已有真实历史告诉我们的反例

仅转换上一轮 Bike Sharing **最终测试之前**的四条开发历史：每条三项初始参照、六次研究动作。每个源文件哈希、完整动作和原始发现均保留。没有重新运行模型、拟合程序或最终评估。

用相同六次调用上限比较完整推进与一个试验性的轨迹组合策略；后者在连续有效尝试不再改善时可能主动停止：

| 历史路径 | 完整推进：调用／最佳开发 RMSE | 试验策略：调用／最佳开发 RMSE |
| --- | ---: | ---: |
| Opus-A | 6 / 51.8782 | 6 / 51.8782 |
| Opus-B | 6 / 47.1333 | 3 / 55.9673 |
| Fable-A | 6 / 59.9764 | 4 / 59.9764 |
| Fable-B | 6 / 54.0093 | 2 / 59.9934 |

**省下调用的策略会扼杀延迟出现的好方向。** Opus-B 的短暂平台之后才出现天气上下文／季节参照探索，Fable-B 的两个负结果之后才出现改善。该 `Portfolio` 仅作为待验证起点，未获得晋级或默认地位；不能把减少尝试数当作能力提升。

这四条历史只有单路径，且共享同一数据划分。它们支持停止／前缀检验，不支持新兄弟分支的结果，更不能拆成独立任务的训练／验证证据。回放改善也不能替代最终迁移质量。没有将这些路径伪装成多棵独立探索树。

原件见 [回放汇总](../evidence/runs/2026-09-18-dream-rsi/history/summary.json)；同目录保留转换后的历史、逐决策回放和转换程序。未知费用没有计为零。

## 验证与边界

- 通过共享循环验证因果可见性、父子顺序、同批隔离、重复／越界动作、未记录继续路径、未知成本、分析动作、修复和早期弱结果。
- 通过实际 Orze CPU CLI 验证四个分支动作的准入、执行、产物、观察和预算结算；随后回放没有产生新的执行。没有绕开原生执行路径。
- Pro 验证训练／验证分组隔离、只按质量晋级、验证退化回退、坏策略修订、源码提议不执行及 provider 入口保留。闭环测试将选出的不同 Python 算法用于一个新在线夹具；这是功能验证，不是 LLM 科研收益。
- 完成目录和失败目录都不能被重用。在线请求在执行前保存；异常不自动重试。已知失败产物是一个可继续推理的研究结果，未知执行状态则由原有执行器处理。

测试汇总与源码身份见 [验证记录](../evidence/runs/2026-09-18-dream-rsi/verification.json)。新增模型调用 0，新增科研执行 0；测试执行不计科研成果。累计已知费用估算仍为 $166.393752，21 次费用未知，有效保守预留仍为 $4994.531375 / $5000，没有释放旧覆盖。
