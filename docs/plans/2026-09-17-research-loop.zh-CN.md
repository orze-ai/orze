# 实际计算反馈：入口已打通，判断质量仍需提高

## 结论

本轮让模型实际编写 CPU 分析、读取不可变输入、执行后再研究。两份分析均完成，
四个项目的第一步结果均以完整原生观察进入第二轮真实提示；来源和结果字节已复核。
这证明分析反馈链可用，**没有证明加一次计算会稳定提高研究判断质量**。

计算组在 effort 案例中保留了正确的首次达标与费用缺失判断；直接复核组错误地改用“每个成功轮次的平均时间”。
但计算组在 memory 案例中延续了错误的跨任务均值，最终响应也未能解析。
两组最终成功记录均为 1/2，且成功记录仍有科学错误。不能把 CPU 执行成功、出处合格或返回率当作研究成功。

## 实验与保留的失败

使用两个此前未用于决策校准的真实案例：已完成的可选记忆研究（8 个项目），以及 high／medium effort 研究（4 个项目）。
案例来自现有原件，未修改 ASR 项目、GPU 或生产服务。

- A：第一次给出暂定判断，原生动作记录为未验证观察；第二次复核决定。
- B：第一次生成 `analyze(data)`；检查代码的执行安全后，由实际 CPU worker 执行；第二次读取计算结果决定。
- 相同 Opus 5 high、每步 16,384 输出上限、每步最多一次请求和 100,000 token 预留。
- 最终阶段每案例／组各一个项目，共 8 次调用。它是修复后的探索，不能当独立盲测。
- 模型没有看到人工评分细则或独立计算答案。计算代码原样执行；人工检查允许执行，不赋予科学正确性。

| 阶段 | 真实调用 | 结果 |
| --- | ---: | --- |
| 内联复制输入 | 8 | 5 次提案通过，3 次超时；第二步未开始 |
| 改用不可变输入引用 | 4 | 2 次超时，2 次被训练父节点规则拒绝；第二步未开始 |
| 修正 CPU 父节点规则、显式 300 秒等待 | 8 | 全部返回；第一步 4/4 执行，最终 2/4 记录；另 2 次为原始 JSON 损坏 |

第一阶段把 task1 目标手抄成 37。检查源结果后，在任何 effort 项目创建／调用之前改为 45，
保存原计划、原数据及带时间与哈希的修正记录；已运行的 memory 案例未改变。
后续从权威结果派生目标。不要把人工案例转写错误归咎于模型。

前两批发现问题后明确停止第二步，失败和未使用预留全部保留。最终批两份坏 JSON 未修补、未重试、未计作完成决定。
300 秒是此批显式请求设置；旧默认仍为 120 秒。最终返回 8/8 不能单独归因于超时设置：输入形式、源码和运行时段也变了。

## 科学核验

| 案例／组 | 最终记录 | 核心判断与残留问题 |
| --- | --- | --- |
| memory／A | 是 | 正确不默认启用记忆、先看已有日志；把样本范围当噪声边界，捏造 75% 使用门槛，并拟删除负对照 |
| memory／B | 否 | 知道所有记忆为空，却把两个不同任务的原始分差合为均值 2；第二轮照抄，未发现与“不跨任务汇总”的冲突 |
| effort／A | 否 | 初稿正确区分 113 秒与 199 秒首次达标；复核改除以成功轮次，错误声称差异消失；还假定未知费用最多等于一次已返回费用 |
| effort／B | 是 | 保留首次达标、整轮时间与未知费用区别；却把“一个任务有结果”写成“四个任务×effort 单元仅一个有结果”，实际是两个单元 |

独立复算核对 memory 24 项组内／配对数值、effort 24 项逐项目数值一致。
这不认可跨任务分差均值，也不证明完整分析正确。模型的错误可能发生在聚合、解释或最终转述，而非算术步骤。

effort 的原始事实是：task0 两种配置都达到 39；high 首次达到约 112.703 秒，medium 约 199.327 秒；
整轮时间分别约 239.543／201.022 秒。task1 均无新评价。
high 有 3 次、medium 有 2 次原始费用未知，不能用返回费用排列完整成本；不能通过除以成功轮次消除真实等待。

memory 的原始事实是：8/8 项目条目数为零，B 未发生持久记忆内容复用；组间差异不能归因于这一机制。
目标题 A 得分 19、27，B 为 27、27；负对照全为 10。
负对照仍有检查成本与伤害的价值，不能因为本次同分就从后续设计删除。

## 最小产品修改

1. **独立 CPU 工作不再被训练谱系配额阻断。** 数据导入完成不等于已有训练得分。
   全部为 `native_cpu_action` 的提案可无父节点；显式父节点仍检查存在性与扇出，混合／训练批次保留原规则。
   正常 CPU 提示同步说明：完成动作提供谱系，不表示科学有效。
2. **Anthropic 请求等待可显式配置。** 新增 `ORZE_ANTHROPIC_TIMEOUT_SECONDS`，整数 1–3600，缺省 120；
   仅控制 HTTP socket 等待，不替代外层研究预算，token 上限与预留继续生效。

没有新增领域适配框架，也没有改变全局模型／effort 默认。研究数据只保存一次，通过已有 artifact 引用消费。

相关回归 **93 项通过，74.11 秒**，覆盖真实 native consumer、谱系、设置、预算／终态与联合快照。
首次检查为 92 通过、1 失败：新测试重复注册 domain；将注册移入模块 fixture 后通过，首次失败原件保留。
离线回归使用许可替身；上述真实模型研究使用正常 Pro 许可和真实 CPU worker。

## 效率与费用

最终阶段 A 两项目合计 322.53 进程秒、返回用量估算 $0.878810；B 为 303.29 秒、$0.861525。
这是各阶段进程时间之和，不是并发批次的实际经过时间，也不是等质量速度比较；每组最终都只记录一个决定。
两份 B 分析的实际计算仅需毫秒，模型生成和复核占主要时间。额外叙述和重复复制协议比算术本身昂贵。

本轮全部 20 次准备、15 次返回、5 次费用未知；返回用量估算新增 **$3.473785**。
累计 **291 次准备／272 次返回／19 次费用未知**；返回用量估算 **$10.621312**，保守预留 **$571 / $5000**。
未知不按零处理，预留不等于扣费，终止批次的未使用预留未重置；原案例中的历史未知费用不重复累计。

## 下一步

已发现的损耗是长篇解释掩盖分母错误，以及重新抄写整个动作结构造成最终提交失败。
下一轮优先在新的逐条数据问题上检验**简短、可逐项核查的结论与实际计算**，以正确比较对象、合理下一动作和首次可靠决定时间评价。
固定动作参数应由现有入口提供，模型只生成必要的分析与结论；先检查已有入口能否做到，再决定是否需要最小改动。
不继续在这两个已知案例上堆提示模板，不把多写笔记、增加重试或删除负对照当作研究能力提升。

原定长历史利用、记忆收益、跨领域等质量改进及受控上线验收仍未完成。
