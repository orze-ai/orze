# 已有提案 ID 的展示摘要

基于 Core `e0487d23565f5ffb01bd6bfe2036120a9b37cbbf`、Pro `d194c22f165992d5764001c8b4211e2ec0c47e17`。研究上下文只展示已有 ID 的总数与末尾 50 条，却原先保留全量 ID 列表和去重集合。本片为这个展示消费者增加计数／尾部摘要；提案去重继续使用原有完整 ID 接口。

## 实现与边界

普通 SQLite 连接、标准行／文本工厂、已核实的单列 idea_id 主键允许流式计数，只保留源文件中的 ID 集合与末尾 50 个展示 ID。主键结构与 ID 读取处在同一事务；并发 WAL 改表不使读取混用新旧结构，DELETE 模式阻止冲突提交。函数关闭本次连接后，下一次读取能看到已提交数据。

作者源与数据库的重叠、重复 ID、原查询迭代顺序、计数和尾部顺序保留。自定义连接／工厂、非匹配主键或无法核实结构时保留完整 seen 集合。SQLite 读取错误沿用原日志和已读取的部分提示；源文件 UTF-8 错误继续抛出。公开的 get_existing_idea_ids、实际提案重复过滤、指标资格、配置统计和其他消费者保持原件。

50 限制 ID 数量，不限制单个 ID 字节。作者源文本和 ID 集合、兼容回退、默认全量合格排名、完整提案去重及其他上下文步骤仍可能随历史增长。Python tracing 不等于 SQLite 或整个进程的总内存统计。本片没有缓存历史数据、扩大提示词上限或赋予展示 ID 任何证据／执行权。

## 基线与行为验证

既有基线 103 项通过（9.93 秒）。旧成本失败保留：20,000 条 Lake ID 加一条作者源 ID，只需显示总数和末尾 50 条时，隔离进程 traced peak 为 3,958,935 bytes，超过本夹具的 256 KiB 组件阈值。这个阈值只检验固定短 ID 的展示组件，不是全进程或任意大小输入的预算。

新增 20 项测试，最终定向 123 项通过（10.80 秒）。正式差分保存 20 组完整摘要／错误结果及两组完整上下文原文，覆盖空／边界长度、作者重叠、重复数据库行、行／文本工厂、模式权限拒绝、查询中断、缺失表／列、坏数据库与坏源文件。另有 DELETE／WAL 并发改表的定向测试；原型的底层 SQLite 探测也保存结构读取、提交结果和两代查询输出。

## 实际产品路径

四个独立项目组合分页 v1／v2 和合格／污染反例，各有 260 条导入历史。真实 research CLI 经 custom HTTP backend 向 loopback 确定性 provider 发送完整提示词。provider 读取“已有 260 条、末尾 50 条”的实际展示提示，从中选末尾 16 个 ID，再以 select_evidence 定向核验这些记录。

完整合格情况下偏好 B；三条关键 B 记录被标为污染后，当前合格集合从 16 变为 13 条，偏好变为 A。正常决策合约、源锁和 ingress 接受提案后，真实 CPU 动作的产物携带实际展示总数、定向选择的 ID、合格来源、观测模式和最终变体。每个项目新进程重放后，ideas、attempts、reservations、artifacts 四张表一致。

共四个 CPU 动作、16 次 CLI、8 次 HTTP 请求。观察器核对每个项目两次展示摘要均为 260／50，同时实际提案重复过滤仍另外读入完整 260 个 ID。每份实际 HTTP 请求／响应、prompt、原生 manifest、来源和产物引用都有对应记录。提示 ID 只是检索线索，污染记录仍不能成为合格证据；未见历史也没有被当作负证据或收敛。

这些历史是导入元数据，provider 是本地确定性协议夹具，没有真实模型或科研收益验收。许可证替身仅在 Pro 子进程，非流式 HTTP 为显式配置；Core-only 子进程禁用 Pro 导入产生的可选扩展诊断保留。没有真实账户、GPU 或既有服务变更。
