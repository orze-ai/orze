# 数据库记忆的当前来源解析、修订检查与旧文件干扰

## 结果与改动

新增 Pro `resolve_stored_memory_sources(results, cfg, *, rules_sha256)`，将已有持久记忆读取与当前报告来源校验连接起来。数据库缺失、待发布、损坏或不合格时明确不可用；同目录即使存在有效的旧 JSON 记忆，也不会被选作替代。来源有效只表示引用当前合格原件，所有作者声明仍返回 `claim_verified: false`。

基线为 Core `efd4bba2426c8d074527d5acfb5387af849f9ffd`、Pro `3ebdc4a485e1e5ae197ae99967a4aa7a95b4e1d3`。本片只修改 Pro 的 `agents/memory_sources.py`（194→241 行），增加 37 个测试；Core 产品代码及测试未修改。

旧文件接口与新数据库接口共享原解析主体。机械 AST 比较确认，共享主体只替换三次文档读取，并增加可选修订标识；既有来源捕获、原生阶段资格语义和 `QUALIFICATION_CONTRACT=1` 未变。三个作者状态、八种成本夹具均独立加载固定基线旧模块，比较完整旧／新文件输出，以及去掉新增修订字段后的数据库输出。

新接口使用报告生命周期所选的同一数据库路径，在三次数据库读取前后检查完整传入配置的规范 JSON 哈希，并在两次完整来源捕获之间比较文档 SHA、修订号和操作 ID。相同字节的新发布、A→B→A 发布以及待提交操作都会阻止旧快照被当作稳定当前结果。成功结果携带 `revision`、`operation_id` 和 `document_sha256`。缺少 Core 存储 API 时新接口明确不可用，旧文件接口仍可独立使用。

这仍是读取时快照。调用方须提供当前可信规则和配置，并在实际消费前重新校验；传入配置哈希不能代替调用方刷新配置。新增接口没有接入研究提示词、自动写入、语义压缩或旧执行接管。当前发布的原子性、保留规则、崩溃重试和存储边界沿用前片。

## 测试与实际 CPU 产物

固定旧代码的基线 174 项通过（27.78 秒）；旧功能探针在完成 Core 持久发布后，因缺少新 API 失败一次（0.41 秒），原始失败保留。候选 v1 定向 211 项通过（38.07 秒），其中新增 37 项包括新进程恢复、三种作者状态、来源与规则变化、数据库不可用、旧 Core 缺 API、相同字节／ABA 修订、prepare 竞争、零引用笔记、配置变更、非法配置及异工作目录下的相对数据库路径。

Core 全量 5,148 通过、7 可选跳过、2 既有 warning，1100.38 秒；Pro 1,357 通过，361.43 秒；配对 31 通过，0.76 秒。测试集合重叠，不能相加。两仓输入冻结，Core 既有源码／测试及 Pro 未改文件与基线逐个 Git blob 核对，改动模块与新增测试均与候选快照一致。

实际产物驱动使用两个隔离 CPU worker、四次 CLI、38 次 Core 记忆子进程（14 读／14 prepare／10 publish）、八次来源捕获，以及 16 次数据库来源解析和两次旧文件解析；provider 调用为零。`confirmed`、`refuted` 为夹具作者声明，未被系统认证为结论。

每个项目先写入有效但内容冲突的旧 JSON。旧接口读到该声明，新数据库接口在数据库记忆缺失和待发布时均不可用。首次发布后，新进程返回修订 1 的当前来源；改动实际报告后来源降级；恢复字节并显式重新绑定、发布修订 2 后恢复当前；修订 3 附加无引用的 unknown 笔记，其状态为 unconfirmed。最后仍能读到旧文件的冲突声明，但其旧引用已失效。没有借助文件回退掩盖数据库状态。

核验检查 CPU 程序 AST、真实产物哈希与 producer、原生 action 的 `TREE_CLOSED`／`ECHILD_WALL`／`SETTLED`、四张既有表内容、全部子进程输出和修订。两次退出 73 保留了提交后丢失确认的精确重试路径。每次来源解析前后，数据库、报告和旧 JSON 的文件 SHA 均保持一致；最终另起核验进程重新解析当前数据库与旧文件，结果与记录一致。

## 证据与仍开放的工作

六份归档共 2,725 个普通文件，覆盖实际产物、四轮成本及候选／生成器快照，无链接条目。归档逐成员 SHA、原路径字节、原始冻结记录、源码 Git blob、CPU 输出及成本结果由同一代理的独立 Python 进程机械核验；这不等于独立人工审查。执行过的脚本和归档原目录均保持不变。

预核验 SHA-256：`b7dfde6d5f8ec245d1c0f05baa8d66facbfcc195f42de41f4e6acd31f21ce0ab`；最终 verification.json SHA-256：`4fd65b05101787c47a7d08bc52cdff99711f9fa3d7f8dec6c1cd1d3686ce1228`。候选源码、私有基线快照、配对清单、原始日志和归档均留在 Pro；Core 只发布本仓回归、结果文档与[私有证据索引](../evidence/2026-09-15-stored-memory-sources-pro-private-index.json)。
