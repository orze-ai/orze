# Orze 产品 TODO

更新：2026-09-14。通用研究最小闭环和最近一轮修复已验收，整个产品目标尚未完成。

## 目标与原则

- 面向通用 autoresearch，不对 ASR 单个任务过度优化，不把领域名或 WER 写回通用决策。
- 不设研究总时限；继续、等待、暂停或停止由 Orze 的策略与证据决定。保留单动作超时、运行租约、资源约束和人工 Stop/HOLD。
- 不把未知结果当成功，不以牺牲资格校验、所有权或故障恢复换取速度。
- 逐项实现、验证、独立核实并提交；用可复核证据区分局部修复、研究收益和产品整体完成。

## P1：降低长历史开销

- [ ] 分别量化预算校验中的重复 JSON 解析／规范化，以及一次 Policy 只读决策中的重复全历史审计。
- [ ] 减少重复工作；若复用 snapshot，先证明完整失效条件，不直接增加全局预算缓存。
- [ ] 覆盖并发写入、回滚、版本变化、Stop/HOLD、损坏历史、槽位冲突、精确累计与执行前复核；不能仅凭 `data_version` 授予执行权。
- [ ] 继续处理非空 ingress 的全局配置缓存、源文件／sidecar 总量和全循环重复扫描。
- [ ] 在递增长度的历史上做新旧交替对照，记录耗时分布、内存／I/O与实际行为，不只统计 SQL 次数。

现状：5,000 条预算行的汇总中位数约 999→931 ms，但完整审计仍为 O(N)。这不是整体研究提速证明。

验收：合法结果不退化、坏输入仍拒绝，成本改善可重复测得，预算和恢复语义不变。

## P1：Pro 长程合格证据检索与上下文容量

- [ ] 将有界查询／分页／定向检索接入真实 research consumer，避免全历史 qualification 后再简单截断。
- [ ] 保留 Objective、比较范围、覆盖声明、协议／来源版本和当前 attempt 身份；invalid／unknown 不能被排序或缓存变成 valid。
- [ ] 设计 evidence／proposal／预算联合 snapshot 的总载荷控制，明确大记录、跨页遗漏和不可用证据的处理，不靠无限增加 prompt 上限。
- [ ] 用关键证据位于后页、后页存在反例／冲突、来源变化等场景验证策略决定；分页结束不能当作研究收敛。

验收：真实策略能找到并使用关键历史证据，仍保持资格与来源校验。Core 已有分页不等于 Pro 消费链已经完成。

## P2：持久研究摘要与记忆

- [ ] 定义有版本、有容量限制、可失效的研究记忆：问题、假设、决策理由、已证实／被反驳／未确认事项及原始来源。
- [ ] 区分研究者笔记、派生摘要和合格证据；摘要不能自我认证，必须能回到当前原件核实。
- [ ] 支持跨轮和重启后的研究上下文恢复；来源换代、删除、损坏或资格规则改变时失效／降级，不因此获得旧执行接管权。
- [ ] 用真实多轮研究验证不丢关键反例、不重复已确认无效尝试，不以不断堆积全文替代有界记忆。

现状：已有 digest 是当前证据的派生视图，首尾笔记读取也已修；它们不是完整的持久研究记忆。

## P2：生产存储兼容与上线

- [ ] 解决角色释放／GC 所需原子操作的存储兼容问题，包括尚未解决的 CephFS 兼容；不能把提前拒绝当作支持。
- [ ] 保留目标碰撞、身份变化、同步失败、Stop/HOLD和未知副作用等边界；不能退化为可覆盖操作，或误禁无关的 CPU-only 功能。
- [ ] 完成服务隔离、状态兼容、旧所有者闭合、备份与回滚方案。
- [ ] 验证真实 Pro 许可、模型调用及所需资源授权；测试替身通过不能代替生产验收。
- [ ] 完成受控上线，以及启动、停止、重启、故障恢复和回滚验证。

验收：实际服务与研究链正常运行，失败可安全处理和回退；构建、安装或单个 CPU canary 成功不能代替上线完成。

## P3：端到端研究提速验证

- [ ] 冻结跨领域、等质量的对照，测量到有效证据／确认选择的延迟、调用与资源成本、失败率和未知结果。
- [ ] 保留负对照、无收益任务及覆盖代价，不用任务名称或预知答案制造收益。
- [ ] 用真实研究链验证，不将少几次查询、元数据夹具或测试通过数当作科研收益。
- [ ] 将有限验收运行的停止规则与 Orze 自主研究决策分开，不重新引入产品研究总期限。

已有一次 48 项目／24 配对的有限 CPU 对照：两个默认示例少一次分析，两个反事实没有同样收益。待补的是更广泛、端到端的验证，而不是声称此前完全没有对照。

## 推进与交付标准

优先完成两项 P1，再推进持久记忆、生产兼容和端到端验收。每片按“保留基线／失败 → 实现 → 定向与真实产品验证 → 两仓回归 → 独立核验 → 提交推送”闭合。

保留原始记录，不覆盖失败，不弱化业务断言；元数据测试与真实执行、局部性能与研究收益分别报告。涉及真实账户、费用、设备或现有服务的变更，先明确必要授权。
