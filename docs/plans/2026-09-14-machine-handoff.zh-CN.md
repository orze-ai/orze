# Orze 产品 TODO

更新：2026-09-15。通用研究最小闭环和最近一轮修复已验收，整个产品目标尚未完成。

## 目标与原则

- 面向通用 autoresearch，不对 ASR 单个任务过度优化，不把领域名或 WER 写回通用决策。
- 不设研究总时限；继续、等待、暂停或停止由 Orze 的策略与证据决定。保留单动作超时、运行租约、资源约束和人工 Stop/HOLD。
- 不把未知结果当成功，不以牺牲资格校验、所有权或故障恢复换取速度。
- 逐项实现、验证、独立核实并提交；用可复核证据区分局部修复、研究收益和产品整体完成。

## 推进与交付标准

优先完成两项 P1，再推进持久记忆、生产兼容和端到端验收。每片按“保留基线／失败 → 实现 → 定向与真实产品验证 → 两仓回归 → 独立核验 → 提交推送”闭合。

每次验证运行使用唯一的短 `--basetemp` 路径（例如 `/tmp/ov-c1`），避免 controller 夹具的 Unix socket 路径超限；首次失败及修改运行参数后的复跑均保留。

保留原始记录，不覆盖失败，不弱化业务断言；元数据测试与真实执行、局部性能与研究收益分别报告。涉及真实账户、费用、设备或现有服务的变更，先明确必要授权。
