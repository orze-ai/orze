# 简化研究动作输入，并检查真实收益来自哪里

## 本轮交付

- 新增默认关闭的 `research_action_template`：项目固定命令、输入引用、协议、输出与资源限制，模型只填写指定输入。
  展开后再计算内容 ID，并走原来的提案、来源与执行检查。使用说明见 Pro 仓库 `docs/research-action-inputs.md`。
- 修复重复 CPU 提案再次通过的问题：完成的 CPU 动作没有训练路径的 `idea_config.yaml`，旧代码因此误判哈希碰撞、换 ID。
  现在按候选 ID 读取已有 Lake 配置，相同配置保持 ID，真实碰撞仍换 ID；没有新增全历史扫描。
- 完成两组新真实 ASR 逐条比较，实际模型写分析、CPU 执行、下一轮读取结果。工程畅通与科学判断分别验收。

**局部简化有效：四对中简写响应都更短，平均少 14.3%。但稳定提速、费用优势和整体研究判断改善仍未证明。**

## 固定对照

8 个项目 = 2 组实际历史候选比较 × 2 种提案格式 × 2 次重复；每项目分析、决定两步，共 16 次真实调用。
A 复写完整动作，B 使用固定动作简写。两组均用 Opus 5 high、16,384 输出上限、每步一次请求、100,000 token 预留及显式 300 秒等待。
任务、输入、指标定义与简短内容要求一致，按预定顺序交替运行；模型未获得独立答案或评分细则。

每组数据含 82,185 条配对记录、8 个语料。192 个源文件只读，前后哈希一致；配对参考文本及位置一致。
模型分析只读取数字计数，不发送转录正文。历史音频身份、checkpoint、解码及归一化来源仍未核验。
两组比较共享基线和样本，属于相关的同领域探索，不是跨领域或独立泛化证据。

## 结果与效率

| 指标 | A：完整动作 | B：输入简写 |
| --- | ---: | ---: |
| 分析执行／最终记录 | 4/4，4/4 | 4/4，4/4 |
| 每项目平均响应字节，两步合计 | 12,495.5 | 10,704.0 |
| 每项目两阶段进程秒之和 | 116.50 | 112.66 |
| 含代码检查与批次等待的实际经过秒 | 349.06 | 353.90 |
| 四项目返回用量估算 | $1.399790 | $1.375425 |

四对的时间与费用均为两对更低、两对更高。不能从平均进程时间约降 3.3% 宣称实际研究更快；
代码检查与批次等待仍占很大比例，也不能把它们省略。价格估算包含返回的推理／输出用量，不是账单。
计算本身约 0.08–0.10 秒。仅一份代码满足“争取 80 个非空行”的软目标，其余为 86–130 行，模型仍会扩张无必要分析。

8 份原生观察完整进入实际下一轮提示，产物字节和来源绑定通过核验。
独立复算核对 **416 项**语料计数、分母及宏／微平均数值一致；容差为 0.00011 个百分点。
此检查不认证附加 z 值、标准误、符号检验或模型后续新算的数字。

## 仍有科学错误

8 份决定都选对声明的主指标方向，且注意到收益集中于一个语料。
但只有一份提出了输入齐全、与当前问题相符的独立计数检查；其余下一步存在实质问题。人工复核不盲，不能由 1/4 对 0/4 推断格式优劣。

- 一份把去掉主要贡献语料后的均值算错，尽管前一步 CPU 主指标正确。
- 多份承认存储分片不是说话人簇，随后仍用分片 bootstrap／jackknife 作采纳门槛。
- 区间跨零不能证明收益仅属于某个语料，也不能据此决定模型只用于金融领域。
- 过滤或截断最大的错误会改变目标；真实收益集中在少数长重复输出上，不等于收益无效。
- 10,000 次重采样在 5 秒内完成的估算没有实测，不能当成已可执行承诺。

核验脚本最初只接受嵌套的 pooled 字段，一份结果使用顶层字段，因此第一次读取失败。
修正读取位置后全量通过；模型内容、数据和数值容差未变。这是核验器假设错误，不是模型计算失败。

## 真正改变下一步的研究证据

随后执行了单独的 CPU 贡献诊断，保留全部行和原来的主指标，再只读检查贡献最大的三行。
**三条样本贡献了目标语料约 77%–81% 的净改善，并贡献两组总体宏平均改善约 52%–58%。**
这些行的基线预测明显过长，连续重复模式覆盖数百个词；两个候选对应预测短得多。
该证据来自实际词级编辑操作与重复计数，未导出转录正文、未重新推理，也未修改原研究项目。

因此下一步应核对这些已定位输出的权重／解码／处理来源，区分真正减少重复输出与流程口径差异。
继续套用没有正确分组依据的置信区间不能解释机制。这里没有证明训练方法的因果收益，也没有把大错误从评分中删掉。
具体候选、样本位置和错误分解保存在 Pro 私有说明与原件。

## 验证与费用

真实实验前相关回归 **114 项通过，75.16 秒**，包括简写通过真实 CPU worker、固定字段拒绝、展开后身份与去重、源变更拒绝和已有研究路径。
首次检查 99 通过、1 失败，暴露了完成 CPU 动作缺少训练配置文件造成的重复提案问题；修复后通过，原始失败记录保留。
离线回归使用许可替身；16 次真实研究调用使用正常 Pro 许可，8 份生成代码先检查执行安全再原样运行。
最终提交另将配置相等判断改为与内容哈希相同的 YAML 表示，避免 Python 把 `True` 和 `1` 当作相同配置；
新增类型碰撞用例后，完整相关检查再次 **114 项通过**。真实实验原件保留在前一冻结源码，
[最终源码验证](../evidence/runs/2026-09-17-research-actions/final-validation.json)单独记录此一行语义修正及源码哈希。

本轮 16 次准备／16 次返回，无新增未知费用，返回用量估算 **$2.775215**。
累计 **307 次准备／288 次返回／19 次费用未知**；已知用量估算 **$13.396527**，保守预留 **$611 / $5000**。
贡献诊断与三行检查新增模型调用为零。预留不等于消费；未知费用继续保留，原案例历史花费不重复累计。
