# 真实研究执行效率：先减少浪费，再验证交付时间

上轮 16 个真实 ASR 回合已完整验收。两种探索策略均完成 5/8 个目标，
ParallelRefine 的平均封顶达标时间为 60.38 分钟，组合策略为 73.63 分钟。
保留 ParallelRefine 默认；当前证据不支持组合策略平均更快。

本轮保持研究策略、模型能力与验收标准相同，只比较执行改进：

| 项目 | control | improved |
|---|---|---|
| 策略 | ParallelRefine | ParallelRefine |
| 同时准备方案数 | 1 | 2，独立分支，完成一个即可开始 GPU 执行 |
| 提案格式 | JSON 内嵌 Python | 直接返回完整 Python |
| 解码输入 | 原 NumPy 接口 | NumPy / CPU Tensor / CUDA Tensor 兼容 |
| GPU 执行 | 每回合串行 | 每回合串行 |

不削减研究模型的推理强度：均为 claude-opus-5/high，最多 32768 输出 token。
每回合最多 14 次调用、4 分支、深度 6；已发出的并行调用全部计数和计费。
直接交付后仍关闭并记录其他已发出的请求，未用提案单列，不冒充无效实验。

四项任务：LibriSpeech other、AMI far-field、TED、FLEURS English。
每项 2 次重复 × 2 种执行方式，共 16 回合，使用全部 8 张共享 A100。
不停止现有服务。每项任务的两个执行组都结束后，即可进入该任务的下一次
重复并交换 GPU；其他任务不必等待最慢一项。此调度对双方相同，其吞吐收益
单独描述，不能算作两组间随机对照得出的收益。

沿用上一轮冻结的音频、特征、Whisper-small.en 和强共同基准，避免重复准备。
这是已知任务套件上的前瞻执行对照，不是新任务泛化证据。科学家只能看到
训练数据、开发反馈和本分支历史；不提供上一轮研究方案或保留集结果。
改动来自运行错误分析，执行组合的结果不能归因给某一个改动。

主指标：每项任务先平均两次重复，再等权平均四项任务的最终验收达标时间。
目标仍是 WER 至少改善 10%，配对分组 bootstrap 上界小于 0。
每回合两个新鲜确认集机会，最终审计仅一次；两小时内未交付统一计 7200 秒。
保留模型等待、无效尝试、训练、确认、审计时间。立即写入真实交付事件后才
结算剩余请求；全批清理时间另报。最终独立 CPU 重算与进程关闭检查通过前，
不宣称均值胜出。四任务样本较小，报告问题级区间和精确符号翻转检验。

预算：上一轮 106 次调用全部关闭且用量已知，保守保留 $89.686025，释放原
$300 池中的 $210.313975。本轮预留 $250 后，全局有效保留 $4979.867950，
低于用户 $5000 上限；历史 25 条未知费用仍足额保留，不声称账户账单核对。
不重试失败的付费调用，不自动重开回合。

上线前零付费验证：54 项 Core 相关测试、18 项 Pro 相关测试、9 项真实控制流程离线测试；8 张 GPU
类型转换全部通过；4 个历史 CUDA-to-NumPy 失败候选保持原源码与原权重，
各自恢复生成完整 96 条开发预测。这证明输入修复有效，尚不证明研究更快。
