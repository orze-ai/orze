## 不变的验收标准

相对已部署默认（Core `fda61cc` / Pro `d5ca768`），在**新的前瞻对照**中，将跨领域平均最终验收达标墙钟时间至少降低 30%，成功率不下降。包含模型等待、失败、诊断、执行和独立验收；未达标按共同截止时间计入，不只平均成功者。任务/领域等权，报告配对不确定性及领域退步。

默认决策还须满足：完整独立核验与请求结算；配对领域时间差的双侧 95% t 区间上界小于零；各领域成功率不低于 control；至少三个领域更快。小样本的“未观察到下降”不能包装成强统计非劣证明。不能以 token、费用、程序有效率、最快轨迹、回放估计或基线预检替代研究效率证据。

最终确认/审计只使用一次，预测由宿主独立评分，不采信候选自报分数。原始失败、未准入、未用付费提案和实现错误都保留。新任务、候选、共同资源、目标及决策规则须在双方首个研究请求前冻结；已观察的开发任务不得重新包装为独立验证。


四个领域是配对不确定性的单位，不把 32 次运行当作 32 个独立领域。开发筛选或事后诊断不能完成目标；胜出机制还必须落到实际研究入口，并核验默认调用确实使用了被测实现。

## 最近论文带来的具体取舍

以下都是作者原文，论文数字不是 orze 的实测收益。十一篇已阅读；机制采用以本地对照结果为准。

| 文献 | 采用的研究原则与限制 |
|---|---|
| [RRSI，09-21](https://arxiv.org/html/2609.24972v1) | 小范围可归因改动、保留负证据、按迁移表现和复杂度选择。其约 30% 节省是 policy tokens，不是研究达标时间；不移植整套 critic/pruner。 |
| [SIFT](https://arxiv.org/html/2609.19526v1) | 异步探索和评估贡献主要加速；成对源码评审仍只是排序信号，且最佳配置用更强评审模型。orze 已有批次内并行准备，不能重复计收益；先检验真正提出方法的模型，不先增加评审层。 |
| [MedRSI](https://arxiv.org/html/2609.24838v1) | 根据反复失败定位缺失能力，快速实验和独立后续注册分离。论文开发成本高，临床成绩不等于研究速度；不把更多工具当能力进步。 |
| [SoL-Pi，09-17](https://arxiv.org/html/2609.20519v1) | 合并连续动作、保留可检索原文。Efficiency 配置 Opus 5 平均分保留 94.3%，不能当能力无损；不删当前模型无法另行取回的证据。 |
| [RSIAgent，09-14](https://arxiv.org/html/2609.15364v1) | 针对知识缺口做区分实验，同时保留适用条件和反例。作者披露的练习未命中弱点、验证不足、错误记忆固化和非匹配重试限制要保留。 |
| [Dream-RSI，09-14](https://arxiv.org/html/2609.14858v1) | 回放仅能揭示真实记录过的节点；改了模型、上下文或代码必须在线重测。已有回放能力保留，不能据回放赢家直接升级默认。 |
| [ASPIRE，08-31](https://arxiv.org/html/2608.31111v1) | 隐藏后续任务、冻结检查点再检验迁移。final-only 24 次演化仅 3 次超过起点，运行循环不等于能力增长。 |
| [Meta-Harness，03-30，基础工作](https://arxiv.org/html/2603.28052v1) | 检索完整源码与轨迹优于不可核查摘要；当前调用无交互检索工具，不能换成不可解引用的句柄后声称信息等价。 |
| [The Last AI Built by Humans，09-10](https://arxiv.org/html/2609.11873v1) | 区分当前任务输出改善与持久系统能力；必须在未来独立任务取得收益。 |
| [ScienceBuddy，09-15](https://arxiv.org/html/2609.17523v1) | 从执行证据诊断有限的程序改动；模型改变后重新验证继承程序。固定模型案例的 31.1%→51.1% 是验证正确率，不能当作研究墙钟收益或单项技能消融。 |
| [Recursive Criticality，08-31](https://arxiv.org/html/2609.00137v1) | 区分基础生产率提高与递归放大。关键参数尚无直接经验校准，条件模拟不是 orze 实测或默认升级依据。 |

### 效率数字的比较对象复核

再次核对 [RRSI 表 2](https://arxiv.org/html/2609.24972v1)：workspace 消融中，每次 trial 的 policy tokens 为未演化起点 1.56M、无约束演化 3.80M、RRSI 2.42M。它减少的是无约束演化的消耗，相对未演化起点仍增加约 55%；伴随更高迁移分数，不能解读为相对当前默认免费获得 30% 研究加速。采用可归因改动、负证据和迁移验证的原则，额外 critic/pruner 是否值得增加仍须本地计入总时间验证。

[SoL-Pi 第 3.1 节和表 1/2](https://arxiv.org/html/2609.20519v1) 报告分数、token traffic 和每单位分数 API 费用。Sol 后端完整 Efficiency 配置将均分从 44.833 降到 42.003；Performance 则是按各后端结果选择的最高分单机制，不能把它与完整栈的最大节省拼成同一方案。本文未提供与 orze 当前“最终验收达标墙钟时间”相同的主指标。本地推论：保留独立验证漏斗，暂不因 token 数字引入完整栈或削减无法取回的研究证据；若后续要组合机制，必须冻结整个组合再验收。

## 本次源码排序学到的限制

- 四次生成 TSP 评审均在 4096 输出 token 截断，费用已知；这是当前配置失败，不是 TSP 研究能力不可能提高。非截断案例也有错选与换序不一致，因此不只提高 token 上限后重试。
- 原首选审计合格 7/8，评审首选 8/8，计算成本代理均值 1175.900→416.480 秒，下降 64.58%。但原无效首选仅约 8.44 秒失败，真实控制器随后继续研究；代理把它计成 7200 秒，不能声称节省了这段研究时间。
- 排除该例仅作敏感性检查，其余七对代理 315.314→464.314 秒，增加 47.25%；原分母、全部失败和晋级门槛保留，不能把事后子集改成新的试验。
- KMNIST-1、TREC-0 两份方法均外部合格，评审选中明显更慢的方法。TREC-1 虽选对，但理由没有指出另一份实际发生的 API 错误。Abalone-1 换序后选择不同，且把共享 OOF 上的 stacker 交叉拟合称为完整嵌套验证。

[源码与测量核查](../evidence/runs/2026-09-23-rsi-source-order-diagnostic/method-choice-review.json) 保存所有八对及哈希。解释文字、内部验证自述和正确首选次数均不能替代独立验收及研究墙钟时间。
