# 再降低 30% 研究达标时间：论文、瓶颈和首个候选

状态：首个候选开发对照已完成并核验，结果不支持升级；30% 目标未完成。当前跨领域试验保持冻结，预检能力默认关闭。

## 成功标准

相对当前已部署默认（Core `fda61cc` / Pro `d5ca768`），在新的前瞻对照中，将**跨领域平均最终验收达标墙钟时间至少降低 30%**，同时成功率不下降。失败、模型等待、诊断、执行和独立验收全部计入；按问题/领域等权、报告配对不确定性和领域退步。不能用 token、费用、程序有效率、单任务最快轨迹或事后挑出的成功者均值替代该目标。

正在运行的 `cross-domain-research-20260922` 只评估此前冻结的 control/inquiry。它不能验证此后写出的 pilot 能力。其操作日志用于定位下一轮的开发瓶颈；新机制的验证任务必须在机制冻结后评估。当前已看过的结果不能重新包装成该机制的独立验证。

## 实际瓶颈审计

`rsi-efficiency-20260922/bottleneck-audit.json` 固定了一次只读快照及每个输入的 SHA256，包含当时已结束的 27 次研究；它是部分轨迹诊断，不是两组最终胜负比较。

- 总 episode 墙钟 26322.57 秒中，仅实验容器执行占 16870.31 秒，约 **64.1%**；仅模型等待占 7790.76 秒，约 **29.6%**；二者重叠 1606.53 秒，其余 54.96 秒。
- 此处为各 episode 时长之和，不是全机器经过时间；容器时长包含 CPU/GPU 运算、加载和保存，不等于 GPU 利用率。等待和执行重叠没有重复计数。
- 对当时 118 份提示做完整 source 字符串检查，**单份提示内重复 source 字节为 0**。没有据此实现“源码去重能提速”的空优化。
- 共享全历史使后续提示和保守预留增长，但删除过去反例也可能伤害研究选择。最终需要能力对照，不用提示长度下降代替验证。

即使把“仅模型等待”全部消除，该快照的直接墙钟空间也只有约 29.6%，且不能解决最终未达标的任务。首要候选因此放在实验执行和信息价值上。

## 首个候选：可继续的小规模预检

新增 Core `orze.research.pilot.run_training`，显式 `allow_pilot=True` 才启用。默认仍执行原来的 build/train；未修改冻结试验读取的任何源码。

研究模型可在原 build/train/predict 程序中增加 `pilot(api)`，自行选择训练数据内部的小规模测试、相互区分的预期以及是否值得继续。不固定算法、不规定先调哪些参数、不强迫每次都做 pilot。

```python
def pilot(api):
    # 执行程序作者选择的小规模测量；这里不写研究答案。
    return {
        "continue": measured_decision,
        "findings": measured_findings,
        "model": optional_partially_trained_model,
    }
```

- `continue=False`：跳过 build/train/预测/模型保存，返回无分数诊断，保留实际 findings；仍消耗一次提案及真实时间。
- `continue=True`：可以接着训练原来的部分模型，避免重复训练；没有部分模型则正常 build。pilot 的测量快照不会被后续训练改写。
- 数据权限、总资源/超时、模型请求数和最终评估器不变。小规模检验默认只用允许的训练输入；没有新增确认/最终标签访问权。
- pilot 抛异常是实现失败，不是对科学假设的反证；没有自动重试。内部 findings 不具有外部得分/验收权。
- 隔离 worker 根据实际结果 kind 将终止的 pilot 标成 analysis。本开发对照的控制器按实际 kind 跳过开发评分/模型资格检查，不能仍因源码具备 train 函数而把它当完成的方法。
- 最终预测只重载已保存模型，不重做 pilot。完整训练与 pilot 都在同一个原有时限内，没有额外免费计算。

预检程序是人工编写的接口测试，验证了停止、继续复用、旧方法兼容以及无标签独立重载。最终版本的四个隔离 CUDA 容器均正常闭合；32 项 Core 测试及 11 项控制器集成测试通过。它们不能作为 30% 收益的实验数据。

## 后续验证与费用边界

1. 现有 32 次前瞻对照继续运行，结束后按它原来的规则核验和处理默认决策。开发对照只使用它已结束的 Fashion / 电厂世界，以及空闲的 GPU 0–3，不修改其冻结输入。
2. 在开发任务验证 pilot 是否真的减少无信息的长实验；失败和漏掉的好方向都保留。随后冻结候选，再做新的跨领域在线配对，不能用旧轨迹回放估算出的时间宣称真实收益。
3. 如果共享证据和 pilot 一起测试，必须明确是组合效果；不能把收益单独归因给任一部分。较小的预检也可能误杀好方向，最终成功率必须检查。
4. 继续遵守累计 $5000 授权；当前 $160 池保持原账本。新一轮发请求前必须释放已有确实结束且可核验的未用预留，或从已确认余额分配，不能以计划金额当作新增授权。
5. 已复核 [Anthropic 官方定价](https://platform.claude.com/docs/en/about-claude/pricing)：标准 Opus 5 的输入、缓存和输出单价不同。后续可在确认请求模式及完整用量后改进过于宽松的成本上界，但不修改当前试验预算规则，也不把这项账务变化冒充研究能力提升。

目标只有在完整前瞻结果、最终验收、来源/费用/执行闭合核验共同支持时才算完成；目前仍缺这部分证据。

四次研究比较当前默认与“预检提示＋可选预检权限”，两边都是 ParallelRefine，未同时加入 inquiry 共享证据。每次最多四提案、两路径各两步，独立验收规则相同。预算池 $18，直接取自现有未分配额度；累计保守分配 $4998.938525，旧试验 $160 池未释放。任务此前已被观察，开发通过不能用于默认升级或 30% 泛化验收。详见私有运行目录 `rsi-efficiency-20260922/PROTOCOL.zh-CN.md`。

## 新发现：当前能力评测存在顺序线索

源码审阅及六次独立预测证实，sentiment-1 的一条 inquiry 高分依赖类别排序；只打乱输入行顺序，其错误率由 0.67% 变为 11%，不再通过相同目标。旧原始结果保留，不能用这条收益作为通用能力/30% 目标证据。后续切分修复已在原始语料验证，详见 [有效性诊断](2026-09-22-cross-domain-validity.zh-CN.md)。候选的最终验证仍需新的前瞻任务，重排旧语料仅为开发预检。

## 开发结果与下一步取舍

四次研究已全部结束，21 份预测独立重算、15 个实验容器闭合、11 次模型请求用量全部已知，验证进程退出 0。

| 开发任务 | control 最终验收 / 达标时间 | pilot 组最终验收 / 达标时间 |
|---|---|---|
| Fashion-MNIST | 通过 / 5.47 分钟 | 通过 / 13.64 分钟 |
| 电厂回归 | 通过 / 14.42 分钟 | 失败 / 按协议记 120 分钟 |
| 两任务均值 | 2/2 成功，9.94 分钟 | 1/2 成功，66.82 分钟 |

这是两个已观察的开发任务，不能作通用均值结论或精确因果估计。它足以拒绝把当前候选升级为默认。5 次 pilot 组付费提案均未定义 `pilot()`，所以更不能把差异归因于预检执行本身。Fashion 的两条候选采用了相近的增广与集成；control 实测训练 202.2 秒，pilot 组 657.8 秒，后者每个成员训练约 347–401 epochs，花满时间上限的行为没有带来更快达标。

本轮另有 1 次无效提案、1 次预算未准入、2 个已付费未使用提案，全部保留。不得因为机制未被采用就强加固定预检配额来制造 adoption；不再扩展该接口。下一候选优先使用**已有的实测训练/预测时长与原模型**指导实验规模、继续条件和复用决策，先检验更小的决策改动，避免再叠加新执行协议。这是由负结果提出的下一假设，不是已证实收益。
