# 组合收益具有任务边界；额外比较组会错过有益替换

## 结论与后续选择

**已有组合工具的局部收益得到更具体的支持，但没有形成通用提升。** 新冻结的24个CPU项目完成，三个任务各8个分组划分：两个真实任务和一个标签打乱负对照。固定20候选的最佳两两组合Mfull，相对同池最佳单模型Bfull，在坍落度上 **7好、0同、1差**，逐划分误差比的中位数为0.9400，约下降6%；硬件性能为 **4好、0同、4差**，最差误差比达3.49。上一轮两个真实案例都退化，不能据此否定组合在其他划分上的用途；本轮7/8也不能外推为普遍胜率。

实际检验的新增步骤是：从开发数据中分出一组，只比较搜索已冻结的组合与初始单模型，再决定是否替换。它在坍落度上拒绝了4次后来在留出有益的替换；相对利用全部开发数据的Bfull为2好、1同、5差。**保留轻量的解析组合能力，不把这层额外比较加入默认流程。** 小样本拆分会损失选择信息，独立也不等于足够可靠。

还发现训练池扩大可以改变相对排名：硬件有2个划分，组合在原训练集拟合时优于单模型，扩大训练池重训后反而更差。最终确认必须覆盖实际要交付的训练过程，不能只确认开发阶段保存的预测。负对照也出现3次排名反转。

下一优先级回到真实多轮研究：在新任务中验证模型能否从长历史里找到这些具体反例、利用现有计算工具并作出有效下一步实验，同时计入完整成本。继续增加通用折数、统计字段或确认步骤没有得到本轮支持。原交接六项验收继续开放。

## 与已有多折实验的区别

[先前多折对照](2026-09-17-research-folds.zh-CN.md)改变评价折数及候选覆盖，没有稳定改善质量。本轮固定实际候选和拟合预测，检验**数据用于搜索还是仅用于比较**，并分开检查最终重训的影响。零模型调用，没有提示词微调或新生成训练代码；Core／Pro运行时未改。

| 方案 | 冻结的选择定义 |
| --- | --- |
| Bsmall | 前20候选，在发现组上取最小MSE单模型 |
| Msmall | 相同20候选，在发现组上取最佳两两凸组合；含所有单模型 |
| G | 在读取比较组标签前冻结Bsmall/Msmall；比较组上Msmall严格更好才接受，同分保留Bsmall；不再搜索或改系数 |
| Bfull | 前20候选，在发现＋比较两组上选择单模型 |
| Mfull | 前20候选，在发现＋比较两组上选择最佳两两组合 |
| R128 | 预先冻结128候选，在发现＋比较两组上选择单模型 |

每任务使用[上轮](2026-09-17-research-mixtures.zh-CN.md)task0的同一候选列表，8个划分间不重新随机搜索。初始20项仍为16配置和4个已审查程序；R追加108配置。整个列表先冻结，再获得任何本轮结果。精确重复身份复用拟合；不同身份仍实际拟合。方案搜索遵循原行加权MSE和较早同分规则，不使用留出结果决定选择。

每个候选仅在训练行拟合，一次预测发现组和比较组特征；此时工作器只有发现组标签。先记录并原生捕获Bsmall/Msmall，之后才捕获单独的比较组标签。G只能在两个已冻结算法中取其一；Bfull/Mfull/R128则明确允许使用所有开发标签做搜索。最后冻结全部六项，再捕获留出输入。G的留出结果没有参与其比较判据或阈值设计。

在同一个留出集分别评价两种实际训练过程：`keep_training`仍用原训练行重新拟合确定性组件，`refit_full`用训练＋全部开发行重训；候选、组件、系数、随机种子不变。各方案在同一模式内共享相同组件的拟合，所以本轮是**共享拟合的策略敏感性研究**，不是六条独立计时的完整autoresearch轨迹。

## 数据与边界

- [UCI Computer Hardware](https://archive.ics.uci.edu/dataset/29/computer+hardware)：Jacob Feldmesser（1987），DOI `10.24432/C5830D`，CC BY 4.0。沿用209行、六个输入预测PRP，排除厂商／型号及ERP；30厂商分组。
- [UCI Concrete Slump Test](https://archive.ics.uci.edu/dataset/182/concrete+slump+test)：I-Cheng Yeh（2007），DOI `10.24432/C5FG7D`，CC BY 4.0。沿用103行、七种原料预测SLUMP，排除ID／FLOW／抗压强度；按完全相同原料向量归组，共103组，未验证物理独立。
- 全部行从已归档官方CSV重建。唯一组按新种子字符串`stability-split-20260917:{task}:{rep}:{group}`的SHA排序，前向上取整20%留出、再20%开发、其余训练。开发组按该顺序交替分给比较组与发现组，不用标签。
- hardware发现／比较各3个厂商；slump发现10组、比较11组。组大小不同，得分按行加权，不给各组等权。负对照在训练／完整开发／留出内按冻结种子独立打乱标签，之后再分开发子组。划分99仅用于预演。

独立审核逐行重建所有25例的数据、标签、分组和来源，确认排除其他目标、无组跨集合、无留出标签进入选择。这里仍是熟悉公共数据的重叠划分，**不是8次独立总体重复**；相同原始行在不同划分会改变角色，跨旧混凝土来源的物理重叠也未验证。胜负、中位误差比用于敏感性描述，不作总体显著性或泛化保证。
