# 当前来源绑定、原生执行代次与记忆降级

基于 Core `c581d24f26a0290b58e7c0e12a62b632f75c4699`、Pro `31b52e5cb1233fb1509334e2f1cb93c548bf2424`。Pro 新增 `agents/memory_sources.py`；Core 格式与既有产品源码保持不变。

本片实现当前报告引用的捕获和持久声明的来源解析。作者的 confirmed／refuted／unknown 原样保留，`claim_verified` 始终为 false；当前来源资格不能证明自然语言结论。持久写入、自动发布、研究 prompt 消费和真实多轮研究继续开放。

## 接口与失效合同

`capture_report_bindings(results, cfg, idea_ids, *, rules_sha256)` 为当前合格报告生成 schema 1 引用，不可用来源返回原因。`resolve_memory_sources(results, cfg, *, rules_sha256)` 新鲜读取 Core 记忆文件，检查预期引用，再为每条声明单独给出 current／unavailable／unconfirmed 来源状态；无来源的 unknown 声明仍是 unconfirmed。

调用者必须提供可信的当前项目配置和已经核对的研究规则 SHA，不能从记忆声明中取得这些可信输入。绑定包含完整配置策略／报告目标、当前报告记录、来源文件和全部父目录代次、results 与数据库及其父目录身份、当前原生阶段引用与 binding／terminal 哈希。只改变文件内容、同字节替换、规则或策略、当前执行代次、数据库父目录，都会使旧绑定失效。污染、删除、损坏和不成功／未知执行状态不能保留当前来源资格。

内部 `QUALIFICATION_CONTRACT=1` 是需要维护的资格语义修订号，语义变化须递增；它不自动检测任意未声明源码热编辑。完整配置哈希采取保守策略，单独改变一次调用的请求预算也会使旧引用失效。

最多 64 个不同来源，按 8 个一组读取；全部组重新核实并检查最终文件／目录代次与数据库、配置。每个来源最多 16 个当前原生阶段，第 17 个使该来源明确不可用；被接受的各阶段均须 TERMINAL／completed。完整解析含三次记忆读取和两次完整来源捕获，以识别解析中的记忆或来源变化。

这些数量界限不约束既有资格器的文件数量、文件大小、YAML／配置、历史模式验证、总 I/O 或 RSS。现有报告分页器还需要一次初始页面读取，可能访问未被记忆引用的报告。返回值是读取时核实的快照，实际消费者仍须在使用前复核规则与来源；它不能提供 permit 或旧 attempt 接管权。

## 基线、候选缺口与修正

既有报告分页与 Core 格式基线 68 项通过、6.25 秒。旧版本缺少新接口的失败保留：1 项、0.36 秒。首候选与 20 个新用例合计 88 项通过、10.83 秒。

后续原生代次反例发现首版只继承报告分页器的 training／evaluation 引用：6 个阶段中 2 通过、4 失败，2.44 秒；action、posthoc、pre_script 和新增阶段的换代没有使旧记忆失效。这是候选缺陷，不能以原有 88 项通过代替修正。补充所有当前阶段的有界检查后，94 项通过、13.01 秒。

扩展容量与终态用例时，2 项因验证夹具的终态 JSON 未使用合同要求的规范序列化而失败，101 项通过、16.71 秒。只读诊断保留两个原数据库的字节副本与原／规范 JSON；产品当时已将这两份坏记录整份判为不可用。仅修正两处测试序列化调用后，35 个新用例与既有集合合计 103 项通过、16.68 秒。原断言及产品代码未因此改变，所有失败原件保留。

## 实际 CPU 报告、恢复与重新绑定

两个隔离项目各运行一个真实 CPU 动作，产出完全相同的合成报告数据。验证程序明确模拟操作员，将产物字节导入报告路径，捕获当前引用，再写入分别标为 confirmed／refuted 的记忆声明。两个相反作者状态不会因同一报告合格而被机器认定为真。

每个项目执行 CLI → 捕获引用 → 两次新进程解析 → 污染或同字节替换后的解析 → 恢复原字节后的解析 → 重新捕获并显式更新引用 → 解析 → CLI 重放。合计 2 个真实 CPU worker、4 次 CLI、10 个解析进程和 4 个捕获进程，无 provider 调用。TREE_CLOSED／ECHILD_WALL、SETTLED、产物 producer／SHA、当前 action 引用及规范终态／绑定哈希均核对。四张执行相关表在所有读取、操作员文件更新与重放前后相同。

污染或替换后旧引用不可用；恢复原报告字节也不会恢复旧文件代次绑定。显式重新绑定后来源再次 current，作者结论仍未验证。这里没有自动记忆发布器、研究角色的真实多轮消费、模型或科研质量验收。Core CLI 子进程禁止导入 Pro，许可替身只用于隔离验证中的 Pro 进程。

## 探索与封存

早期分组原型保留了：错误相对导入路径导致加载已安装 Pro 占位包的失败；只复核最后一组遗漏早期来源变化的反例；全配置哈希的保守失效；数据库父目录替换但文件 inode 不变的遗漏。后续原型处理组间变化和父目录身份，最后 15 个场景通过。它们尚未包含正式候选后来补上的所有原生阶段检查，不能与正式接口或真实 CPU 验收混算。

Core 全量 5,086 通过、7 可选跳过、2 既有 warning，1078.78 秒；Pro 1,320 通过、345.15 秒；配对 31 通过、0.86 秒。集合重叠，不能相加。输入冻结，既有源码和测试与基线提交逐一核对；12 份归档共 2,742 个文件逐个核对成员哈希和原目录字节。预核验 SHA-256：`bb22b783cf11bf717953e414f5f38f6443fc7883f474b576a8946a695907256a`；最终 verification.json SHA-256：`44afb6f7de7045a781aafc99625be43cf17400d97b08a0fb96efe6ef7b6546f6`。独立进程机械核验不是另一位审阅者。

原生阶段四项失败及终态夹具两项失败的 stdout.log／junit.xml 含 pytest 原始行末空白，只对这四个已确认原件设置暂存检查例外。

Core 保存自身回归、此说明和[私有证据索引](../evidence/2026-09-15-memory-sources-pro-private-index.json)；实现、测试、配对证据和原型保留在 Pro。下一步按[交接清单](2026-09-14-machine-handoff.zh-CN.md)继续持久更新、容量与反例策略、研究消费、存储兼容和真实研究验收。
