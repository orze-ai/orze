# 真实研究效率验证：相同成功率，平均达标时间缩短 23.0%

## 结论与默认决定

16/16 回合完整结束，冻结验证通过。两组均通过 5/8 个最终目标；
改进执行组平均封顶达标时间为 **54.98 分钟**，control 为 **71.44 分钟**，
减少 **16.46 分钟（23.0%）**。主指标先平均每项任务的两次重复，再等权平均
四项任务；未达标统一计 120 分钟，包括已提前结束的失败回合。

按开始前公布的“均值更低且成功率不下降”规则，将并行准备执行路径作为新
研究集成的默认入口。探索策略仍为 **ParallelRefine**。本轮两组都使用该策略，
因此这里没有证明 Dream 策略胜出，也没有改变上轮保留 ParallelRefine 的决定。

问题级差值（improved − control）的 95% t 区间为 **[−37.82, +4.89] 分钟**，
精确双侧符号翻转检验 p=0.25，仅四个问题。采用实测均值更好的默认方式，
不等于已经证明它在所有新研究任务上的总体期望更优。

## 核验与交付

- 117 次模型请求、132 个 GPU 容器全部关闭；107 份预测独立 CPU 重算一致。
- 冻结源码、模型/数据输入、确认集/审计集分离、单次最终审计与费用均通过验证。
- 全部 8 张共享 A100 参与实验；没有停止现有服务。当前研究请求及容器均已结束。
- 研究请求费用估算 $70.182335，保守保留 $91.070575，无本轮未知费用；均在 $250
  授权池内。启动时全局有效保留 $4979.867950，历史未知费用未释放。不是账户账单核对。
- accepted=true 的交付事件才算通过；completed.json 表示包括剩余请求结算在内的结束。
  TED 第二轮 improved 在 4.85 分钟交付、5.60 分钟结算完毕，两种时间均保留。
- 已有定期监控在终态自动停止；实验未重启，没有追加付费研究请求。

## 效率损耗

| 指标 | control | improved |
|---|---:|---:|
| 已发出模型请求 | 57 | 60 |
| 无效提案/执行失败 | 30 | 3 |
| 纯模型等待，累计回合分钟 | 296.22 | 102.63 |
| 仅 GPU 容器执行，累计回合分钟 | 77.70 | 95.28 |
| 模型与 GPU 重叠，累计回合分钟 | 0.00 | 28.17 |
| 已付费但未使用提案 | 0 | 3 |

control 的失败为 17 次 CUDA→NumPy 错误和 13 次被截断输出导致的 JSON 解析
错误；improved 为三个不同的源码/运行错误。未使用提案不算无效实验：三个请求
估算共 $1.75444，仍完整计数计费。上述时间分区避免重复计算重叠；累计回合时间
不是整场历时，也不是 GPU 核心利用率。整场实验历时约 152.87 分钟（不含准备）。

AMI 第二轮两边均未达到最终 10% WER 改善门槛。FLEURS 第一轮两边虽有约 7%
改善，但仍未达标；第二轮 improved 最终仅改善 0.36%，control 没有有效开发提升
候选，因而未执行最终审计。不能把这六个失败回合从均值中删除。

## 落地与经验

1. **按验收目标的真实时间优化。** 保留相同研究模型、high 推理强度和 32768 输出
   上限。提前准备独立方案，让 GPU 更快拿到可执行候选；避免只比较每次调用价格。
2. **简化代码交付，修复数值输入边界。** 默认指导直接返回完整 Python，并在评估
   回调中检查完整性；格式失败正常消耗一次尝试并反馈给原分支。数值接口兼容
   NumPy/CPU/CUDA Tensor，避免训练结束后因输入转换而整次报废。
3. **及时交付，同时结算所有已提交请求。** Core `run_prepared` 与 Pro
   `run_discovery(prepare=..., evaluate=...)` 默认准备两个独立分支，按就绪次序
   串行评估。省略 workers 时默认 2；显式限制保持有效。finished/unused 配对
   回调记录真实终态与未使用提案；不自动重试。已有自定义 execute_batch 继续
   负责自身调度，已有服务不会因为新增 API 自动改变行为。
4. **有价值的科学探索仍需独立证明。** 候选实际探索了解码修复、训练内留出比较、
   LoRA/增广、权重插值及多解码投票，并允许纯诊断。LibriSpeech 第二轮两边最终
   WER 分别改善 40.77% 和 43.03%，均通过；但部分 TED 收益来自转录格式对齐，
   不能全部称作声学能力提高。模型写出的“声学极限”等解释也不是实验事实。
5. **确认的不确定性也消耗时间。** LibriSpeech improved 第二轮的早期候选在新鲜
   确认集有较大点估计收益，但区间上界仍略为正，继续到固定调用上限后才最终
   验收。未来应研究如何更快取得足够证据；本轮不放宽门槛、不把开发提升当成功。

默认入口通过 main 工作区的 72 项相关测试，包括真实 CPU 执行、ECHILD_WALL
进程关闭、资源结算、分支隔离、无效源码反馈和交付后剩余请求计费。Core 4.6.3 / Pro
0.13.2 的候选 wheel 已检查新入口及依赖下限；本次不发布 PyPI 版本。
宿主 CPU 测试仍有已有的 Torch/CUDA 驱动警告，真实 GPU 验证使用冻结容器环境。

下一阶段仍应在新问题族上检验探索质量与创新收益。当前证据限于四个已知 ASR
语料、两次重复、一个预训练模型和一个研究模型；组合执行改动的收益不能拆分
归因给单个组件，双方共同使用的按任务推进调度也没有独立随机效应估计。
