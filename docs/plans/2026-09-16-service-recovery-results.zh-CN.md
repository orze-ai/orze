# 已关闭服务的新宿主恢复：结果与边界

已完整关闭的本地 CPU 服务现在可显式创建新宿主，沿用原控制器历史、数据库及累计预算。
旧宿主退出后无需删除登记或重置研究状态。这是运行延续能力的改进，尚无新增研究收益对照。

基线 Core `ca87d08a3d534a067de6b29b8af43eb76888ba8d`、Pro
`941fec078b822ea7ba3c22123a2ee84dce41fd11`。Pro 产品源码未改。
范围限于同一配置、执行作用域和运行包的 `local_cpu_handoff_v1`；未完成非正常崩溃修复、
跨版本／跨机器迁移、真实 systemd、机器重启、旧 PID 迁移、备份回滚或生产上线。

## 新行为

`orze service recover --source-service-config OLD --service-config NEW --request-id KEY`
先生成新配置，固定来源服务文件、关闭快照和控制器身份。新宿主启动时重新核验，
复用已有一次性交接协议，持有自己创建的后继进程及 pidfd。可选 `--install` 接入现有
项目级 systemd 安装器；本片只对管理器属性和命令使用隔离替身。

旧宿主和控制器必须按本机／启动身份确认已经退出，旧服务 unit 必须退役，所有动作和
关闭 ACK 必须完整，停止标记继续生效。历史 PID 不获得发信号或收养权限；原文件与登记
保留，不自动修复未完成请求。新宿主正常关闭后可再次作为恢复来源。

## 实际 CPU 验证

最终定向与 Core 全量各自运行相同的 11 个独立恢复作用域：3 个正向作用域、16 个实际
控制器、13 个原生 CPU 动作。两份静态独立核验均通过，集合重复，不相加为新实验数量。

- 连续两次恢复形成三代控制器。120 秒有限预算只允许原先的两次 60 秒预留动作；
  第三代按 `wall_envelope_exhausted` 停止，没有重置额度。
- 版本 2 的 `wall_budget_seconds: null` 同样恢复三代，并实际完成第三次动作。
- 两个新宿主在完成来源核验后同时竞争，只产生一个 STARTED grant 和一个后继。
- 准备后改动服务文件、关闭记录、配置、预算、ACK 或停止标记，均在新控制器创建前拒绝。
- 有真实关闭记录但旧宿主仍存活时拒绝；新配置路径碰撞不覆盖原字节。

管理器七种状态和 CLI 两种路由另有隔离检查。静态检查器核对数据库、出生父进程记录、
关闭 ACK、预算与原生产物，不能重现过去的内核观察，也不等于另一位人工审阅者。

旧行为运行在实际关闭 CPU 服务后因缺恢复模块失败。定向 v1 的夹具过早把动作 TERMINAL
当成预算 SETTLED，改为等待独立结算。v2 错误期待耗尽有限预算后仍执行第三次动作，
修正为验证拒绝，并增加无总期限配置的第三次实际执行。未放宽产品预算约束。

Core 全量唯一失败来自既有 `test_runtime_lease_publication` 夹具：文件已创建但 JSON
尚未写完，读取产生 `JSONDecodeError`。原目录保留最终完整内容。夹具改为先写临时文件
再发布标记，所有进程、关闭与预算断言保持不变；该文件和相关 lease recovery 回归
43 项通过。**没有第二次 Core 全量运行**，不得把首轮结果写成零失败。

所有运行前后源库存一致。最终 candidate-v5 相对全量、配对与定向 v4 仅改变上述一份
测试夹具；产品源码完全相同。Pro 全量与配对使用原有测试级许可替身，不代表真实许可验收。
