# 配对计算：事实读取改善，实验设计仍未解决

## 本轮交付

新增可选 Core CPU 工具 `orze.research.paired_comparison`，把实际参照、声明的配置差异、按样本配对的分差、按组等权的分差及已知历史重用量算出来，再通过正常观察交给研究模型。
没有增加新的研究策略、域、默认提示词或默认复验次数。工具使用现有产物绑定、原生执行和预算检查。
Core 实现提交 `4810905`，正常 Pro 研究入口为 `60a2a1d`，使用正常签名许可。

**局部能力已有实测改善：本诊断中，可记录判断从 2/8 增至 7/8，后者的八项结构化事实均正确。**
但这检验的是“计算后读结果”相对于“直接手算原始逐样本值”，不是相对于最佳现有分析流程的完整研究能力对照。
后续实验方案仍有不支持的参数、不存在的新样本及过强归因。没有运行这些后续建议，不能据此宣称发现更好方法或整体研究效率提升。

## 四个来自历史实际测量的案例

这些案例按诊断价值有意选取，不是随机抽取的基准。没有按模型本轮回答挑选样本。
原预测文件、数据、观察与配置均核验哈希；从预测和标签独立重建逐样本误差后再核算比较。

| 案例 | 已有测量事实 | 要识别的研究问题 |
| --- | --- | --- |
| heldout-regression | 混凝土单划分：候选 MSE 37.2872，参照 34.5447；194 样本、86 组；候选减参照 +2.7425，组等权 +4.9788 | 开发阶段选出的候选在确认划分上退化；同时变更家族与参数，不能随意作单因素归因 |
| different-weighting | 混凝土新划分：196 样本、86 组；样本均值分差 −2.9311，组等权分差 +1.8068；历史已用样本重合 196 | 两种聚合方向相反；选择哪种目标必须有研究依据，历史重用不能自动解释方向反转 |
| actual-reference | 翼型：参照为 learning-rate-only，候选为 min-leaf-only；实际同时改变学习率与叶大小；327 样本，分差 -0.8503，组等权 -0.7050；全部重用 | 名称不是本次比较的归因，参照改变后实际差异也改变 |
| incompatible-splits | 电离层不同划分：59 对 63 样本，仅 8 个 ID 重合；scope 不同；两种配对效果均为 null，历史使用未知 | 不得把重合子集或不同总体的均值差冒充完整配对效果；重合的 8 行两侧误差实际全部为零 |

历史划分在生成时的 holdout 标签不证明其此后仍未被查看。这里只计数明确提供的使用记录，不认证历史完备性。

## 预先固定的对照

- 4 案例 × 2 模型 × 2 组，共 16 次真实请求；Opus 5 high、Sonnet 5 medium；每项一次请求、8192 输出额度、300 秒超时，无回退或重试，4 个项目并发。
- A：正常捕获同一输入产物，把完整逐样本 JSON 放入项目规则，要求模型给出事实和下一步。A 没有调用分析工作器，只能提交记录判断的动作。
- B：正常捕获后，用新增 CPU 工具计算，再从实际 research 分页读取结果；不在规则中堆入原始行。B 同时改变计算和呈现，不能隔离成压缩或文案收益。
- 双方问题、结构化输出要求和研究默认提示一致。原生预算均为 15 秒；每个动作预留 5 秒。B 为比较多付一个动作，全部计入项目耗时。
- 调用前要求参照 ID、候选 ID、配置差异路径、完整配对状态、重合样本数、两种分差和已知历史重合数，共八项；数值容差 0.001，不可比时效果必须为 null。
- 解释和下一步分别人工核对，不把八项事实分数当科学质量评分。所有返回、截断和错误原件保留。

## 读对之后还会犯什么错

| 实际回答 | 审查结论 |
| --- | --- |
| Sonnet B 识别确认集退化后，建议在 trees 家族中只改变 learning_rate | 实际树工作器不支持该参数；近零变化也不能证明家族切换是退化原因 |
| Sonnet B 读对 196/196 重用后，建议去掉重合样本再比较 | 当前产物会剩零样本；组权重反转与重用是不同问题 |
| 两个模型 B 读对实际参照和两参数变化后，用单因素无效果来判定另一因素造成收益 | 单因素试验可提供信息，但交互与变异仍在，排除一个条件不能直接归因另一个 |
| Opus B 对不可比案例返回正确 null，却在解释里把部分重合称为 disjoint | 结构化事实正确不保证自然语言解释正确 |
| Opus B 建议一次共同划分比较后按正负号直接采用 | 需要与选择过程、效应不确定性及实际目标一起判断 |

这些是保留的研究缺口，没有用解释文字修饰成通过。记录判断的 CPU 动作不会执行其中的建议。
下一优先级应让有限、可执行的对照设计获得真实反馈，并考核最终选择与完整成本；不继续在这四题反复加提醒。

## 预检、证据与边界

初版私有驱动遗漏 JSON 域必填的 `payload.specification`，CPU 预检在执行前拒绝；当时无原生预留、无执行尝试、无供应商调用。
新驱动补齐字段，复用原来的 16 个尚未调用额度；两次正常预检分别覆盖方向反转与不可比输入，干跑提示后通过正常 ingress 记录并读回人工结果。
没有放宽产品校验，没有重试已返回请求。B 的不可比观察保持科学 invalid，同时作为合格来源实际进入模型提示，二者含义不同。
