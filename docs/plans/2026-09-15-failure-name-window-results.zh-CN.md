# 失败历史：有界选择名称，保留实际回退路径

基于 Core `2f548d28690636cf088b34fed7b1b08ecc3e785f`、Pro `55d7742e1d910f5569d8e9ad0a7d8b8244b5fcbb`。Core 失败读取默认只消费名称末尾 200 个目录，Pro 模式分析默认消费末尾 2,000 个；原先都先保留并排序全部名称。本片仅对 1–4,096 的普通整数上限选择有限名称，再按原来的升序读取。两轮 20,000 目录完整演进上下文约快 10%，小规模与 Pro 模式读取仍有退化。

## 实现与兼容边界

目录依旧全部枚举，`is_dir(follow_symlinks=False)` 和名称前缀检查的顺序不变。读取范围、JSON 解析、结构化失败优先级、分类、分组、例子、近期顺序和异常处理保持原件；枚举中途失败仍丢弃整个选择，不发布部分结果。名称顺序没有改成时间顺序。

零、负数、bool、整数子类、大上限和其他类型保留原来的列表／排序／切片行为。例如零仍读取全部，负数仍按原切片去掉一段，某些浮点上限在无需切片时仍可返回结果。该兼容路径没有新的名称容量上限。正常小整数路径限制名称保留，并不限制单条报告大小、目录枚举总量或整个进程内存。

研究上下文通常先用 Core 的 200 条结构化失败，为空时才调用 Pro 的 2,000 条模式分析。普通路径和实际回退路径分别测量；没有靠少读取旧反例换取收益。

## 行为与实际执行

- 既有基线：Core 31 通过、3 可选跳过，0.60 秒；Pro 90 通过，17.15 秒。
- 正式旧成本检查：Core、Pro 各三组失败，均因同时保留全部 5,000 个名称；分别 0.24／0.15 秒。失败日志与当时的测试原件保留。
- 新增 Core 16、Pro 17 项检查。定向 Core 47 通过、3 可选跳过，0.81 秒；Pro 107 通过，17.34 秒。名称生命周期检查独立于具体堆实现，并核对完整枚举和尾部失败仍可见。
- 50 对正式差分覆盖特殊上限、Unicode 名称、映射插入顺序、结构化优先级、损坏／非字典 JSON、非法 UTF-8、缺失源、读取与枚举失败。双方完整输出或异常一致，输入原件保留。测试链接只在运行结束后移除，精确目标单独保存供重建。
- 私有探索保留一处观察器误计：它把 `Counter.most_common` 的内部堆选择也算成目录选择。该轮的 30 对完整输出相同，但最终观察器断言失败；原代码、日志及缺少运行前后清单的限制如实保留。后续观察器修正和名称保留量检查的指纹补充复跑另存。

真实 research CLI 的两个独立项目各有 2,300 个目录，最近 200 个没有失败，同一反例分别放在 2,000 条模式窗口内边界 `0300` 和外侧 `0299`。确定性进程内 provider 只读取实际 prompt：内侧反例进入 prompt／CPU 产物，外侧不进入失败上下文。正常原生结果清单、提案源锁、ingress 和 worker 路径完成两个 CPU 动作；六次独立 CLI 含新进程回放，关闭／结算／产物 SHA 一致，回放四张表没有新增执行或扣记。

每次 research 调用中，两次名称选择都遍历 2,300 个有效名称，分别保留 200／2,000。实际 prompt SHA 与产品 prompt manifest 相同。历史是导入元数据，provider 是 `call_llm` 边界上的进程内替身；这不是历史研究执行、真实模型或真实后端进程验收。没有真实账号、GPU 或既有服务变更。

## 回归、核验与剩余项

归档 52,685 个文件。预核验通过，SHA-256：`8dfca90865817bb7d1d36dbdfd5f74b0d64aabeda62cf36756c21b0f0d38a377`。这是独立进程机械检查，不是另一位审阅者；核对 282 个未改 Core 源／524 个既有测试文件、94 个未改 Pro 源／147 个既有测试文件原件，全部归档与两个 worker 证据关联一致。最终机械核验通过，SHA-256：`8adbb1324af91218dbc54120ac992f959a926edd286567d2a40bd0910ce0f904`。Core 一次全量 5,021 通过、7 可选跳过、2 既有 warning，1,059.43 秒；Pro 一次全量 1,180 通过，304.80 秒；配对 31 通过，0.73 秒。集合有重叠，不能相加。
