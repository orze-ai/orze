# CephFS 上可实际执行的清理与归档

显式 `gc.storage_mode: guarded` 支持当前 CephFS 上的检查点删除、结果文件删除和
结果归档。默认原子模式保持原有行为。使用与中断处理见[配置文档](../gc-guarded-storage.md)。

## 可核对的变化

原版本在本机 CephFS 的三次清理调用中均被原子重命名预检拒绝，四个候选没有完成。
新模式在同一文件系统的新建隔离项目上完成四个候选：检查点目录、结果文件，以及
归档的单文件和嵌套目录。每项均核对剩余文件、归档字节、计划哈希和完成记录；
保留任务的 `metrics.json`。这些是实际文件操作，未调用模型或运行生产项目。

协议在任务短事务锁内发布持久清理记录，再释放短锁进行大文件 I/O。新的任务认领和
受控写入检查该记录；异常退出保留待完成状态。归档独占创建目标，复制并校验完整内容，
确认后删除源文件。没有普通覆盖重命名，也没有跨设备复制后删除的回退。

另一个新进程在清理期间确认认领被阻止，且短事务锁已释放；清理完成后恢复普通任务规则。
完成的旧任务仍因已有结果而不可再次认领，不能将此误报为清理后新任务成功启动。

## 成本与适用范围

成本样本为每棵树 64 个文件、共 32 MiB，内容固定，数据准备不计入清理耗时。
本地原子／新模式采用两轮相反顺序；CephFS 测量新模式。报告完整操作时间、短锁时间
和 Python 分配峰值；分配峰值不等于完整进程内存。历史读取另用只读合成记录测量，
不能计作真实执行或成功清理。

最终候选的两轮完整操作耗时（秒）：

| 存储与模式 | 删除 32 MiB | 归档 32 MiB |
| --- | --- | --- |
| 本地 ext4，原子模式 | 0.599／0.598 | 0.385／0.381 |
| 本地 ext4，guarded | 0.699／0.696 | 2.864／2.846 |
| 当前 CephFS，guarded | 0.539／0.540 | 2.916／2.875 |

本地新模式短锁约 63–64 ms，CephFS 约 29–30 ms；完整归档在短锁之外完成。
首次新模式删除的 Python 分配峰值约 4.23 MB（含首次模块载入），第二次约 1.09 MB；
归档约 2.16 MB。不得用较低的 CephFS 数字推断两种存储的一般性能优劣。
`stat -f` 对本地输出通用的 `ext2/ext3` 标签，挂载查询确认 `/tmp` 为 ext4。

只读历史的三次样本中位数：0／1／128／1,024 条，本地约 0.039 ms／1.22 ms／
0.114 s／0.905 s，CephFS 约 0.048 ms／1.92 ms／0.177 s／1.402 s。
这些数字包含测量分配的开销，不是所有任务准入的固定耗时；无清理历史走常数路径。
成本测量与全量／定向测试分开运行，但未控制共享机器的其他负载，也不是生产规模验证。

归档需要额外内容复制、校验和暂存空间，成本高于同设备原子重命名。清理历史增加后，
准入读取也变慢。此功能解决当前存储上的可用性，不宣称速度提升或研究收益。

## 保留的失败

- 最初版本的原子操作拒绝保留在基线记录中，未作为支持完成。
- 中间测试的两处夹具预期错误保留：完成旧任务不应再次认领；短文件名的 600 项清单
  尚未超过 64 KiB。修正夹具后验证对应实际行为。
- 实际异常探针发现归档目标父目录打开失败时漏关源父目录句柄，以及历史超限检查前
  先完整枚举目录。首份目录观测脚本漏接 Python 3.10 已绑定的 `listdir`，第二版确认
  2,000 项全部被物化；两份探针均保留，不能将第一版空观测算作没有问题。
- 新增七个边界用例先在未修复源码上全部失败，额外覆盖清单发布前后收到停止请求、
  GC 日志目录替换和清单目录替换。修复后持续检查到源文件删除阶段；最终再覆盖最后
  一份清单写入后的停止与替换，避免只检查循环的下一次迭代。
- 第一份独立核验脚本误将归档的两个候选按一个错误计数，失败输出保留，第二版修正。

## 尚未完成

角色释放仍依赖原子不覆盖重命名。该模式没有完成角色的 CephFS 支持、实际 systemd
部署、机器重启、迁移备份或回滚。多机器并发、混用不识别清理记录的旧运行包，以及
实际模型研究效果均不在本次验证结论内。原 P1／P2／P3 目标继续开放。
