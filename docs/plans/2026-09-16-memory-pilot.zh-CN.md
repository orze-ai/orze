# 下一次研究实验：记忆开／关的小规模对照

状态：**实验设计，尚未运行真实模型，也不是可直接执行的 campaign specification。**
模型／接口、账户、许可及调用或费用上限等待用户指定。此前授权只包含本地开发与
隔离 CPU／离线替身。不能用离线预设回答替代本实验。

上一次 [24 对运行版本对照](2026-09-16-research-runtime-comparison.zh-CN.md)没有发现一致提速。
本次只检验一个问题：开启持久记忆的额外调用与上下文成本，是否换来更好的选择或更少重复失败？
先做小样本筛查，再决定是否值得扩大；不以继续完善工程作为默认下一步。

## 固定的实验设计

| 项目 | 约定 |
| --- | --- |
| 规模 | 两个任务，各两次配对；共 4 对、8 个新项目，每项目 4 轮、每轮请求 2 个候选 |
| 顺序 | 每任务第一次 A→B，第二次 B→A；评价顺序种子分别 17、41；种子不控制远端模型采样 |
| A | 关闭持久记忆，保留正常历史访问和证据分页 |
| B | 相同代码、模型、历史访问、分页与预算，开启 `research_memory: {version: 2, max_updates: 1, resume_prepared: false}` |
| 共同证据设置 | `research_evidence: {version: 2, page_size: 16, proposal_page_size: 16, max_snapshot_bytes: 32768, max_requests: 3}` |
| 初始信息 | 无历史、无预先编写的研究结论；两边都显式建立同样的空记忆文档，A 不消费它 |
| 评价 | 现有 `schedule-feasibility-v1` CPU 评价器；从实际候选计算价值，并独立复验最终选择 |
| 样本处理 | 保留全部计划样本、失败、超时、缺失与成本；不在看到结果后换任务、重抽样或增加轮次 |

任务输入见 [固定实例](2026-09-16-memory-pilot-inputs.json)。目标任务有相互竞争的时间窗口、
前置依赖和价值取舍；负面对照的时间窗口互不冲突，预计记忆很少有帮助。
这些是本次新编写的小型调度题，不是独立盲测集，也不代表跨领域实际研究。
题目与评价规则给模型；穷举得到的最优分数和排程答案不加入模型提示词。

本地 CPU 准备核验：完整枚举合法时间窗口内的安排及可选任务的省略，目标题共 864 种，
其中 136 种有效、最优分数 27；负面对照共 8 种，全部有效、最优分数 10。
输入文件 SHA-256 为 `121b4dbf815800578018a41d437c70eabf2b22e5016662772687902f00f05c6f`。
另外在一次性临时 SQLite 中核对空记忆的 prepare／publish／read，读回版本为 1、条目为空，
状态仍为 pending_verification；没有调用 Pro 消费者或模型。这些只证明题目可解和初始化 API
可用，不是研究效率或模型能力实验。

两边使用同一指令：满足必选、时间窗口、依赖和容量约束，最大化已选任务的总价值；
根据实际评价修订方案，避免重复已经证实无效的排程；通过现有提案接口提交候选。
不强迫 B 写记忆，也不禁止 A 从正常历史学习。若 B 从未写入／读取后续记忆，照样计入
功能开启的总体结果，但不能声称已经测到了记忆内容的复用效果。

## 研究结果与效率一起报告

1. 每轮独立确认的最好有效分数、达到最优分数的项目比例；未成功项目不能从分母删除。
2. 达到相同分数的首次有效证据时间、最终独立确认时间、完整项目时间。固定四轮的总成本
   仍全部报告，不将事后发现的较早好结果当作系统当时已经停止。
3. 实际请求与重试、输入／输出 token、供应商费用、CPU 动作和累计预留。
   记忆写入所需的额外模型请求计入 B；初始化时间两边计入。
4. 无效提案率，以及在先前同项目已经评价为无效之后，再次提交相同规范化排程的次数。
   规范化按 job_id 排序 `(job_id, start)`；这种定义只能测完全重复，不替代语义层面的重复错误。
5. B 各轮实际使用的记忆版本、条目及来源；将模型的自述与评价器确认的事实分开。

逐对列出质量和成本，不只比较总体均值。仅在质量不下降的对内解释时间／费用差异；
另列全部样本的失败成本。供应商计费未知时标记未知，不填零，不宣称完整成本改善。
现有采集器不提供已核实的美元费用或远端 GPU 秒，需与获准接口的用量／账单核对。

四对样本不足以证明稳定的能力提升。若短上下文中两边都一次成功，只能说明本设置没有
产生记忆收益的机会；若 B 更慢或质量下降，明确报告。此实验不关闭长历史反例保留、
跨领域研究收益或生产上线的剩余验收项。

## 已确认的执行缺口与最小处理

当前 campaign 强制 `initial_history=[]`、`initial_memory=null`，然后从空项目直接运行
research；记忆 v2 则要求事先存在已发布文档。因此只添加 B 的配置会在模型调用前失败。
Core 已有 `prepare_memory_update`／`publish_memory_update`，无需再实现记忆存储机制。

实际执行前，仅需在公共初始化完成后、第一轮 research 之前，对 A/B 各自数据库显式发布
`{"schema":1,"project_scope":实际 results 路径的作用域哈希,"entries":[]}`，
保存初始文档和逐轮记忆快照供核对。实验采集入口必须显式承认这一非 null 初始状态，
共同输入哈希绑定初始化约定，并保留现有拒绝未声明状态的行为。
**该接入尚未实现；本设计不冒充现有执行器已经可以直接运行的参数文件。**
待模型与预算确定后，围绕这一实验接入做最小改动及针对性核验。

当前每个 campaign 子步骤有 60 秒时限。接入真实模型前，应结合获准接口确定是否适合，
两边一致；超时样本及已发生的调用继续记账。两边设置同样的请求／token 约束，
供应商重试计入实际尝试数。32 次 research 进程不等于 32 次模型请求；每轮最多 3 次
逻辑请求，而传输可能重试。不能将协议里的费用字段当作账户侧账单硬上限。
