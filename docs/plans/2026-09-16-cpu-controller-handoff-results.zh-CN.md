# 原生 CPU 控制器交接：实现与验证

新增显式 `controller_control: {version: 2, profile: local_cpu_handoff_v1}`。
同一配置与预算作用域内，旧控制器完成关闭并实际退出后，通过既有一次性交接协议
启动一个后继。主入口仍是原 CLI／Orze CPU 循环。[配置与用法](../cpu-controller-handoff.md)。

## 资源与历史

CPU 在原初始化中绑定实际预算，再进入 PREPARED／COMMIT；不会调用两次初始化。
两个阶段都检查实际 Lake、绑定作用域、空动作集合、全历史与策略 Stop，随后才进入
策略／动作循环。STARTED 单独记录 CPU 作用域，不使用伪造的 GPU 租约或 PID 文件。

新预算 ACK schema 2 只摘要本控制器的精确预留；新实例追加合法工作后，旧摘要仍成立。
关闭与交接准入另核验完整库存，未结算或没有 attempt 的预留阻止交接。
历史读取核验原 AttemptRef、终态和 effect；当前结算入口继续要求当前代际。
旧 wall 预留不退款，旧任务的 claim 不清除，交接不提供失败任务的隐式重试。

## 实际产品案例

九项新增检查包括七个 CLI 产品案例、一个声明检查和一个“不执行”回执机制检查。
最终定向运行的产品案例总计六次原生 CPU attempt：四次 completed、两次 interrupted。
另两份 NOT_STARTED 回执没有启动 worker，单独计数。全量回归重复运行的次数不再累加。

| 案例 | 实际内容 | 结果 |
| --- | --- | --- |
| 有总预算／持续授权，各一组 | 每组三代控制器、两个正常准入的任务、同 key 重放、第二次不同 key 交接及最终停止 | 旧 worker、后代和控制器先退出；无额外后继；各保留 120 秒预留 |
| COMMIT 后插入孤立预留 | 实际预算 reserve，没有 attempt | PREPARED 保留，后继不进入策略；同 key 重放拒绝 |
| COMMIT 后记录策略 Stop | 实际预算决策事务 | Stop 保留，不进入策略；同 key 重放拒绝 |
| 最后 STARTED 回复丢失 | 真实接收后抛出故障 | 首次未知，相同 key 核验既有后继成功，不重复启动 |
| writer 内修改旧结算哈希 | 历史核验借用同一个实际写事务 | 看到未提交修改并拒绝；不提交调用者事务，回滚后原证明有效 |
| 修改旧 effect 回执 | 对真实已提交回执追加字节 | 历史核验拒绝；故障原件保持损坏 |

损坏回执另存修改前原字节。机械检查器只用其作对照，未修复归档。
代际机制检查用两份真实 NOT_STARTED 回执验证：旧记录仍可只读核验，结算所用的
当前终态核验继续拒绝 StaleAttempt。这不等于交接获得了旧任务重试权。

子解释器禁止 GPU/provider/旧停止入口，许可发现采用离线替身。实际 CLI、SQLite、
CPU worker、后代、pidfd 与交接通道保持真实，没有调用账号、模型、GPU 或已有服务。

## 回归与保留的失败

- 基线 164 项通过。旧代码面对两项新要求实际失败，原因是尚未支持新 profile；不是两个历史缺陷。
- 首实现 1 通过／3 失败：CPU action 状态未纳入交接历史；空闲停止被策略包装成通用异常。
  第一个失败的诊断信息还因 successor.log 尚未创建而被 FileNotFound 遮蔽；日志和候选原件保留。
- 第二轮 3 通过／1 失败：新夹具误认为 FAILED→QUEUED 就能释放旧 claim；实际预算预留后 claim 拒绝。
  没有放松 claim。产品案例改为正常入口的新任务；旧代际读取与结算拒绝由单独回执检查覆盖。
- 中间定向 171 项通过；最终定向 173 项通过，包含全部九项新增检查。既有测试没有修改。
- 最终 Core 全量 5,366 通过／6 跳过，JUnit 汇总 1170.97 秒；
  Pro 1,647 通过，457.69 秒；配对 31 通过。集合有重叠。

输入冻结，所有终态、失败、五份源码快照和原始产品目录均保留。独立 stdlib 进程核验
原始记录、归档字节、当前／冻结／Git 源码及六个原生终态的成员／预算／交接摘要。
这是机械复核，不是第二位审阅者。Pro 源码、测试、示例未改，完整配对库存留在私有仓库。
归档明确列出已关闭 UNIX socket 端点的省略记录；这些端点没有可复制的文件载荷。

## 剩余范围

本片完成本机 CPU 单后继交接，不代表 service/watchdog 已接线。匹配路由下裸 PID
仍可能被旧 watchdog 当作终止目标的既有反例，尚未由本片修复。
外部发起者与服务 cgroup 的生命周期、服务隔离、状态兼容、备份迁移和回滚仍待验证。
原停止模式与现有 GPU 模式保持各自声明；不允许改配置接管旧登记。

历史最多 64 代、4096 个跨代成员，超限保留拒绝；本片没有测量研究提速或真实模型质量收益。
原始 P1／P2／P3 总目标继续开放。
