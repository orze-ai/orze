# 已关闭服务的一致备份与非执行数据恢复

新增 `orze service backup create／verify／restore`，为已完整关闭的注册 CPU 服务保存
一致数据，并恢复到新的核验目录。原预算、动作历史、路径及所有权记录保留；复制品不取得
执行权。这补齐原 P2 迁移准备中的一个组件，跨路径／版本迁移、上线和实际回滚仍未完成。
使用方法与边界见[服务备份](../service-backup.md)。

## 实际验证

本地与当前 CephFS 都执行了实际 CPU 动作、服务关闭、备份、核验和恢复。数据库全部 SQL
与备份时刻一致，文件内容、权限及链接文本保留。复制的旧服务配置启动被拒绝；原项目按
现有协议恢复后完成第二个动作，代次 0→1，累计预算作用域没有重置。旧备份仍保留第一个
动作的时点，不能拿它覆盖恢复后的新支出。

额外核对外部已声明输入、真实公共 CLI、SQLite 写入竞争以及不支持的 WAL 状态拒绝。
注册控制器仍要求 DELETE 日志模式；备份入口不改变原策略。复制期间持有写锁，另一个
SQLite 写入者不能开始写事务；生成的数据库镜像保留额外已提交表及全部业务记录。

独立标准库脚本没有调用产品 verifier，直接核对 8 组成功产品记录、5 组失败边界和
6 组成本样本的摘要、数据对象、恢复树、SQL 及预算记录。保存的关闭元数据不等于迁移后的
当前执行授权；实际跨机器竞争、真实模型／账号、GPU、现有服务和部署均未执行。

## 失败与修正

- 初始模块缺失探针退出 1，记录新增能力在基线中不存在。
- 初版恢复末尾只重新验证备份源，恢复文件被同大小内容改写仍得到完成标记。失败测试
  保留；修正版在发布前重新检查整个恢复树、文件摘要、权限与链接。
- 初版漏记原来不存在的外部已声明输入。该文件在复制期间出现，备份仍完成且漏掉内容。
  失败保留；修正版记录缺失路径，并在最终发布前再次核对它们仍然不存在。
- 一项初始测试期待 WAL 关闭状态成功，与既有共享数据库策略不符。本地和 CephFS 的失败
  均保留；后续分别验证 WAL 原样保留且拒绝创建，以及 DELETE 下的一致镜像与写入门控。
- 首版独立审计误以为成功 CLI 的 stderr 必为空，实际含既有安装提示和配置日志。
  v2 保留并摘要核对 stderr，成功判断仍来自执行记录、结构化结果和独立数据核验。

所有已执行脚本、候选版本和原始失败均保留；没有将失败原件改写为成功。

## 当前完整命令成本

每个样本运行三个实际 CLI 进程；包含启动、关闭状态审计、复制及内容核验。源项目各已有
一个结算完毕的实际 CPU 动作，成本测量没有启动新 worker。每种容量只有一份样本；32 MiB
是新增数据载荷，此外还有项目原有数据。备份对象未压缩。

| 存储／新增载荷 | 创建（秒） | 核验（秒） | 恢复（秒） |
| --- | --- | --- | --- |
| 本地／0 | 0.526 | 0.203 | 0.628 |
| 本地／1 MiB | 0.535 | 0.204 | 0.641 |
| 本地／32 MiB | 0.630 | 0.242 | 0.795 |
| 当前 CephFS／0 | 0.455 | 0.205 | 0.308 |
| 当前 CephFS／1 MiB | 0.469 | 0.206 | 0.312 |
| 当前 CephFS／32 MiB | 0.561 | 0.244 | 0.487 |

这是当前版本功能成本，没有旧版成功实现可作提速对照。样本使用已读过的源及规则载荷，
不能作文件系统排名、生产吞吐量或研究效率结论。原记录包括 CPU 时间和累计 RSS 高水位；
后者不等于单个样本的独立内存峰值。

## 回归与封存

最终 candidate-v5 的专项 28 项、CephFS 实际产品 6 项、配对 47 项通过。配对包含 Core
独立运行时跳过的 16 项 Pro 研究集成断言。最终 Core 全量 5,539 项通过、23 项可选跳过、
2 个既有 warning；Pro 全量 1,681 项通过。所有最终运行的两仓源码／测试库存相同且前后冻结。
各集合有重叠，不相加成独立研究实验数。

12 次运行（其中 5 次预期失败）、11 份原始目录归档、9,067 个归档条目完成独立核验。
首版独立审计脚本异常也保留。公共包 35 个载荷、私有包 129 个载荷，两者各另有文件索引。
完整运行日志、两仓原始库存和含运行包清单的项目数据保存在私有仓库；公共记录仅投影
Core 库存。全量测试临时目录留在本地，完整日志与 JUnit 已归档；原始项目归档范围见摘要。
