# sidecar 名称窗口与标题 lookahead

本片基于 Core `a952321b33e6973d6c580f5593139bebdce19e30`、Pro `8e556ddc88f1e78a625585683b84de3c04ed6022`。续页在同一已复核目录版本内保留一个名称窗口；单文件解析只保留相邻标题匹配。5,000 个独立文件的完整遍历两轮改善约 2%；大量无 YAML 定义的单文件控制有完整 ingress 峰值收益。普通有效载荷的内存峰值基本持平，小规模有轻微退化。

## 实现与保留边界

SidecarPrefix 仅保留最多 512 个候选文件名、一个起点键及窗口容量。向后定位、容量变动或窗口用完时重新枚举；原 scope／PID／目录及先前文件身份复核、当前 payload 读取和异常 clear 继续执行。没有保存 YAML、raw、准入结果或执行权。没有取消每页前后对已缓存前缀的 lstat。

`_sidecar_sections` 用相邻两个合法标题匹配保留原 raw 区段边界，不再先建立所有匹配的列表。没有改变标题正则、未知标题如何落入前段 raw、YAML／配置处理、标题过滤、excluded IDs 或首个有效定义优先。旧 public overlay 路径返回结果保持一致。长无效前缀仍须扫描全部标题，不能把“前 128 个合法记录”的局部匹配数量当作任意输入的扫描硬上限。

部分文件仍重新读取全文并重新解析前缀 YAML；完整遍历 seen 集合、目录总枚举、重复身份复核与提示容量之外的 fresh fallback 成本仍在。单条配置／YAML 展开也没有获得新的硬界限。

## 基线、业务验证与实际执行

- 92 项既有检查在原件上通过，59.28 秒。两个新成本检查分别失败于同一 300 名称窗口枚举 3 次、取前 128 条前匹配全部 10,000 个标题；原始失败保留。
- 最终定向 104 项通过，71.15 秒。新增 12 项覆盖成本、future 文件改写／改名／删除、消费期间 namespace 变化写入前拒绝、raw 边界、坏 YAML／重复／excluded 优先级和空／未解析定义。
- 正式 64 个混合输入分别取全部／前三项，共 128 对 parser 输出和 seen 结果一致。包含损坏 YAML 的跳过，未出现向外抛出的异常；独立的既有注入测试继续验证 parser 异常导致整批保留。每个输入原件、脚本及结果摘要保留。
- 新建独立文件和单文件两个 CPU 项目，各导入 299 条 completed 元数据。真实 ingress 三批为 128／128／45，只有第三批接受 `idea-tail`，其重复提案保留。两个真实 worker 分别生成 `[1, 3, 5]`，完成 `TREE_CLOSED/ECHILD_WALL`、SETTLED 与 SHA 核对；六次新 Core CLI 启动含初始化、执行和回放。回放不新增执行／扣记／产物，全部作者源不变。导入历史不是已执行研究。

## 两轮普通完整路径成本

每种布局／规模先预热，再旧／新交替三次；双方使用同一当前 ingress、source lock 与正常 writer，仅替换保存的旧 prefix／parser 与当前实现。第一轮和第二轮普通运行均在本片全量回归前结束；内存单独运行，不把 tracing 时间混入表内。所有完整数据库和作者源摘要相同，完整提案内容／顺序与批次数一致。

| 布局／记录数 | 首批第一轮旧→新 ms | 完整第一轮旧→新 ms | 完整第二轮旧→新 ms |
| --- | ---: | ---: | ---: |
| 独立文件／100 | 85.28→85.17 | 82.59→82.38 | 81.97→82.49 |
| 独立文件／1,000 | 101.35→101.88 | 846.54→848.99 | 838.92→839.18 |
| 独立文件／5,000 | 104.13→105.15 | 5461.95→5333.79 | 5382.77→5275.41 |
| 单文件／1,000 | 93.30→90.79 | 1215.36→1205.37 | 1205.90→1202.60 |
| 单文件／5,000 | 107.29→95.37 | 17748.57→17563.00 | 17768.19→17624.02 |

首批第二轮及所有逐次样本也保留。5,000 独立文件的两个完整改善约 2.35%／1.99%；单文件约 1.05%／0.81%，幅度小。1,000 独立文件和部分首批样本略慢；非独占主机与少量样本不能支持普遍时延保证。

独立计数，5,000 独立文件的目录枚举 40→10 次，返回目录项 200,000→50,000；5,039 次新鲜 payload 读取、214,719 次文件身份检查和 5,000 次 BEGIN／ROLLBACK 均不变。1,000 文件的目录枚举 8→2，100 文件不变。单文件 5,000 条仍读完整 payload 40 次、正常 writer 5,000 次；YAML 解析次数不减少，标题匹配减少不等于已关闭单文件前缀解析成本。

独立完整遍历 tracing，5,000 独立文件峰值约 3.15→3.14 MB，结束时分配 2,282,217→2,320,247 字节，额外保留 38,030 字节；1,000 文件结束时约增加 16 KiB。单文件 5,000 条峰值约 4.28→4.24 MB。这些普通有效载荷没有与孤立 parser 相同幅度的内存收益。表中的 heap 计数不是 RSS，也不是完整 SQLite／进程预算。

## 无 YAML 定义控制：完整 ingress 的分配收益

单个文件含大量无 YAML 定义，最后有一个有效提案。尾项实际到达当前 writer，并按既有同 ID 标题冲突规则保留；不是在解析前截断，也不是新增 worker 的证明。每次重新开始遍历、读取全部当前源，数据库和文件不变。

| 无 YAML 定义数 | 第一轮旧→新 ms | 第二轮旧→新 ms | Python peak 旧→新 bytes |
| --- | ---: | ---: | ---: |
| 500 | 18.22→18.07 | 18.19→18.34 | 104,676→85,466 |
| 5,000 | 29.65→29.79 | 29.36→29.64 | 947,625→412,435 |
| 50,000 | 156.32→145.94 | 151.56→145.50 | 9,404,884→4,058,251 |

50,000 个无 YAML 定义时两轮 Python peak 都约 9.40→4.06 MB；5,000 个第二轮新值为 412,490 字节，时间略退化。双方必须匹配 50,001 个标题，只解析两次 YAML，并各做一次 BEGIN／ROLLBACK。局部 lookahead 消除了匹配对象的集中保留，没有跳过未知内容或提前宣称枚举完成。有效载荷与这组无 YAML 输入的结果分别报告。

## 回归与证据范围

Core 一次全量 4,983 项通过、7 项可选跳过、2 个既有 warning，1,104.64 秒；Pro 全量 1,152 项通过，302.35 秒；配对 31 项通过，0.79 秒。源／测试及回归输入前后指纹一致，集合有重叠，不相加。

[证据目录](../evidence/runs/2026-09-15-sidecar-scan-windows/)归档 24,936 个文件，包含两轮普通运行、独立内存、无 YAML 控制、正式 parser 差分、两个真实 CPU 项目，以及明确标记的探索过程。探索计时与前片回归重叠、部分计时含观察器，不用它替代正式普通样本。原型分别尝试名称和标题优化，未把它们当作联合产品验收。

归档首次因探索报告名称非标准、缺少索引而在预检停止，未生成压缩包；保留失败观测及原脚本，补充指向原始报告的索引后成功。失败观测明确标记为工具输出观察，不冒充独立 stderr 原件。

预核验与最终机械核验均通过。最终 `verification.json` SHA-256：`3b0da7ed95b1af10758dde42358ba886a393635f91237f57550e0992b0d64177`。核对 281 个未改 Core 源文件、520 个既有 Core 测试文件及私有 Pro 95 个源／146 个测试文件原件，全部运行与归档字节关联一致。它是另一个进程的机械检查，不是另一位审阅者，也不表示整个产品目标完成。Pro 完整源／测试清单和原始日志保留于私有仓库，公共[私有证据索引](../evidence/2026-09-15-sidecar-scan-pro-private-index.json)仅固定提交、文件摘要及 Git blob。
