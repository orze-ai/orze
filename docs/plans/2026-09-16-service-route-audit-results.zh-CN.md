# 服务当前配置与结果目录的一致性核验

安装后若同一路径的项目配置把结果目录从 A 改为 B，旧服务审计仍只检查已保存的 A，可能允许启动并漏掉 B 的停止标记。本片修复这条当前配置读取路径：配置实际解析出的结果目录必须与服务保存的目录一致；不一致时拒绝，不自动改写服务或接管新目录。

## 实现与保证范围

`resolve_project_results` 复用 Core 的 YAML 默认值、`.env` 选择与解析、空环境变量回退以及 `${VAR}` 展开规则，以服务的工作目录解析路径。它使用独立环境副本，不改变审计进程的 cwd 或 os.environ，也不启用角色或代替完整项目配置验证。

运行时审计在其他核验前后读取当前路由，比较配置／所选 `.env` 的文件身份与元数据、路径父目录、结果目录和进程环境。读取期间变化、不可读取或非法输入均拒绝；未知路由不会回退成保存的 A。沿用现有 watchdog 入口、陈旧进程终止前、最终启动前三处合约检查和故障计数。

这是当前观察进程环境下的时点检查。没有持久绑定安装时的全部 inode，没有保证检查结束到执行之间绝不变化，也没有证明 systemd 主服务和 watchdog 的实际环境一致。符号链接／文件在两次独立审计之间被替换但仍解析到同一路由，不因此获得或失去所有权认证。本片不授予裸 PID／PGID 的终止或重启权限；现有所有权与完整服务隔离缺口仍需修复。CPU-only 的普通配置加载流程保持原有行为。

## 反例与产品验证

- 原有 140 项定向基线通过。固定当前旧提交上，配置 A→B 且 B 有 Stop 的真实只读审计仍返回允许；相同不可变脚本在修正版返回拒绝，安装元数据保持原样。
- 新增检查在旧实现上 17 失败／1 通过，另 10 项新纯读取接口差分不作为旧产品缺陷计数。最终相关检查 169 项通过，旧测试未修改。覆盖配置、`.env`、继承环境、配置／结果符号链接、非法 YAML／类型、审计期间身份变化及三个进程边界。
- 10 组纯路由结果与在实际服务 cwd 中运行 `load_project_config` 的独立 Python 子进程一致，包括默认／相对／父／绝对路径、dotenv 优先级、空变量、未设置变量和配置链接；审计者环境及 cwd 未变。
- 一个真实自有 sleep 子进程在错误路由与陈旧 PID 标记下保持存活、未收到 watchdog 信号，最后由夹具父进程回收。
- 三个隔离 Core CPU 项目验证配置改址、dotenv 改址和正常控制：共 3 个实际 worker、6 次 CLI 调用。前两者在进程检查前拒绝，正常控制只探测精确自有控制器。恢复夹具原配置后完成原生关闭、结算、产物检查和新进程重放，无新增业务记录或扣记。

服务安装的 systemd／crontab 管理动作均由收集器替换，未操作现有服务。CPU 控制器不写传统服务 PID 标记，产品夹具为其精确子进程显式写入该标记，不能据此宣称 CPU 服务接线完整。真实包内容身份、控制器、worker、SQLite、产物和进程回收保持实际执行；外部模型、账号与 GPU 调用为零。

## 新增成本

同进程新旧交替 8 次，每版 4 个样本，包含真实 Core 包哈希和完整审计；另测 Python 分配。合法稳定输入的审计输出一致。

| 配置 bytes | 完整审计 wall 中位数 ms，旧→新 | Python peak MB，旧→新 |
| ---: | ---: | ---: |
| 31 | 37.43 → 39.66 | 4.78 → 4.80 |
| 65567 | 37.39 → 112.25 | 4.78 → 5.99 |
| 262175 | 37.62 → 324.82 | 4.78 → 4.80 |

新增配置解析与身份复核有成本，尤其较大 YAML。样本数量有限、共享机器存在波动；分配峰值不是 RSS。本片没有研究提速声明，未通过削弱边界换取更小的耗时。
