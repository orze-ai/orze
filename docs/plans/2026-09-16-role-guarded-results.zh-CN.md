# CephFS 上的显式角色锁协议

本片补齐角色释放的存储兼容路径：显式 `roles.<name>.storage_mode: guarded` 使用
独占创建、持久协议标记与不可按超时抢占的过渡目录，释放时不需要目录 no-replace rename。
默认 `atomic` 不变；当前 CephFS 的默认原子模式仍被实际探针拒绝。

详细配置、所有权和恢复限制见[角色存储协议](../guarded-role-storage.md)。
本片不调用真实模型、账号、GPU、现有服务或部署，不增加研究能力或研究质量的证据。

## 实际链路

实际 Pro 角色启动、预算、触发器 SQLite、子进程监督和收取流程使用新协议：
正常结束、后台子进程退出后结束、显式停止三个场景均在当前 CephFS 上完成。
仍有后台写入者时不会发布完成或释放锁；停止保留中断结果，不记为成功。
进程已关闭但触发器尚未结算时，底层释放函数同样拒绝。
预算拒绝发生在准备进程之前时，只取消该进程刚取得、尚未绑定的锁。
另一次只读观察器运行保留了三次实际释放的 `TREE_CLOSED`／`ECHILD_WALL` 回执。
独立进程将回执、触发器终态、attempt ID、预算预留、usage 结果和产物哈希逐一核对；
正常释放后的启动检查无未决角色，关闭但未结算的案例仍明确要求恢复。
这些产品测试使用隔离配置；`/proc` 枚举限制在测试捕获的自有 PID 集合内，包含实际后台
写入者，通知关闭。没有替换进程树关闭或触发器结算证明，也没有验证整机其他进程干扰。

本地与 CephFS 的两个竞争进程各只得到一个所有者；当前 generic 锁即使使用负超时，
也不能抢占 guarded 命名空间。角色协议与提案源协议也互相拒绝已声明的命名空间，
取得所有权后出现冲突标记会使当前所有者失效。释放后可再次取得新 lease。
这里没有验证跨机器竞争。

## 保留的失败

- 初始 Core 基线命令引用了不存在的测试文件，退出码 4；修正测试路径后另行运行。
- 第一版底层释放函数只依赖上层已验证的调用顺序。真实睡眠子进程仍存活时直接调用该
  函数，确实错误删除了锁。失败测试保留；修正版复用同一关闭／结算核验，底层也不能绕过。
- Pro 停止测试最初在进程停止后立即要求锁已消失，漏掉正常收取与结算步骤；本地和
  CephFS 两份失败均保留，修正后通过原有收取循环确认关闭、结算和最终释放。
- 首版独立审计脚本把 pytest 的 `current` 符号链接误当作第二个项目而失败；v2 只选择
  实际项目目录，原脚本与异常保留。此修正没有改变产品或测试源码。

- candidate-v5 的实际探针发现角色锁与提案源锁能交叉取得空闲命名空间；原始失败保留。
  修正版双向检查持久标记，并拒绝所有权取得后出现的冲突声明；同一探针复跑不再交叉取得。
- candidate-v5 的 Core 独立全量有 5,507 项通过、7 项跳过及 16 项初始化错误。安装环境
  中的 Pro 占位模块被误识别为完整 Pro 包；修正测试发现条件，独立 Core 明确跳过这些可选
  项，再在真实 Core/Pro 配对中执行全部业务断言。原全量错误记录没有删除或改写。

## 完整生命周期成本

最终 candidate-v6 在回归空闲期间由同一独立脚本运行 12 个实际 Core CPU 角色；每次计时包含两次存储预检、
获取锁、INTENT／READY／GO、CPU 执行、树关闭与释放。输出均为相同排序结果。
本地两轮采用 atomic／guarded／guarded／atomic 顺序，共各四份样本；CephFS 另四份
guarded 样本。预检并不是所有权缓存，正常用户循环仍需当前核验。

| 当前模式／存储 | 完整生命周期（秒） | 准入与获取（秒） | 释放（秒） |
| --- | --- | --- | --- |
| atomic，本地 | 0.363–0.371 | 0.209–0.214 | 0.0315–0.0366 |
| guarded，本地 | 0.259–0.261 | 0.0966–0.0977 | 0.0385–0.0390 |
| guarded，当前 CephFS | 0.134–0.145 | 0.0240–0.0255 | 0.0128–0.0140 |

这是同版本两种协议在这台主机上的测量；本地完整路径较快主要来自较便宜的预检，
释放自身稍慢。CephFS 原子模式只有拒绝结果，没有可比较的成功生命周期。
这些样本不能推广为文件系统性能排名、整轮研究提速或生产吞吐量保证。
记录还包含控制器／子进程 CPU 时间和进程 RSS 高水位；高水位不是各个样本的独立内存峰值。
该 Core 成本脚本没有触发器，Pro 触发器结算由上面的实际产品验证覆盖。

## 回归与证据

最终源码和测试为 candidate-v6，已修复跨协议命名空间冲突与可选 Pro 测试发现条件。
Core 相关 123 项通过／16 项可选跳过，Pro 相关 19 项通过；真实配对 47 项全部通过，
其中包含全部 16 项可选 Pro 研究集成。最终 CephFS 产品 5 项及 12 个完整成本 worker
通过，独立审计 v3 核对当前回执与账本。最终 Core 全量 5,511 项通过、23 项可选跳过、
2 个既有 warning；Pro 全量 1,681 项通过。23 项跳过中包含上述 16 项 Pro 专属研究集成，
真实配对运行已执行对应业务断言。所有最终运行的两仓源码／测试清单相同且前后冻结。

修复前的 candidate-v5 Pro 全量 1,681 项通过；Core 全量的 16 项初始化错误见上文。
早期各次定向、失败及成本运行均保留版本清单，不能替代最终源码的验证结果。

角色 CephFS 路径的局部验收不关闭整个 P2：旧控制器迁移、备份／回滚、实际 systemd、
机器重启与异常所有者恢复、真实许可／模型和受控上线仍开放；P1／P3 也保持原范围。
