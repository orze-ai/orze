# 优先缩短达成研究目标的时间

用户明确：**研究效率，即多快搞定研究目标，是第一目标。** 创造性探索服务于达标；省钱、调用数量、测试数量和工程复杂度都不是替代指标。

三方长测与独立效率审计均已完成。组合事后封顶发现时间均值为 14.33 分钟，均匀探索为 15.89 分钟；这不是在线提前交付提速。完整结果与限制见[结果报告](2026-09-22-combined-results-and-lessons.zh-CN.md)。以下保留已冻结的审计规则。

## 固定目标与计时

这轮五类合成问题统一以**确认 RMSE 相对共同基线降低 50%**为目标，观察 60 分钟研究窗口。50% 是参照上一轮约 55% 平均收益设定的实质性门槛，不是 Orze 的全局默认验收线；真实项目使用项目自己的目标。

- 主指标：每次研究首次找到达标候选的时间，未达标计满 3600 秒；先平均题内两次重复，再对五题等权。只报告成功者耗时会掩盖失败，因此禁止删去未达标运行。
- 同时报 15／30／60 分钟内达标率、原来完整预算下的最终确认质量，以及问题层面的配对差异和不确定性。
- 每个完成批次只按**当时开发分数**选择最佳候选，平局保留较早者。不能因后来确认成绩好就挑出当时没有被选中的方法。
- 计时使用原始 `online/response-NNNN.json` 发布时刻减去该次研究开始时刻，保存纳秒时间戳、原文件哈希与完整研究起止记录。模型等待、失败、程序执行、策略决策开销均在时钟中；不能用各 worker 耗时之和代替墙钟。
- 共同基线准备时间、整轮研究时间、确认运行时间和新增审计交付时间单列。首次发现候选不等于当时已经知道它可靠，也不等于完整用户目标已交付。

## 独立确认与范围

所有前缀选择由已冻结的确定规则产生。原始三方研究结束并核验后，先物化全部选择，再进行新增确认。相同运行的最终源码或共同基线若完全相同，复用原确认；其余每份不同源码只执行一次，失败计不达标，不重试。最多三个隔离 CPU 容器并发，各 1 CPU／2 GiB／240 秒，无网络、无 GPU；最多 420 次新增程序评价，实际仅需确认一小时内出现的开发最优方法。没有新模型请求或新增模型费用预留。

确认结果不回流到研究分支，不重新发明、修改或挑选策略。原实验的 420 次调用、全部失败和最终质量比较保持原样。原先按最终质量均值自动解释默认的文字，须结合本补充协议：**先按目标达成效率比较默认**，主指标观测均值较低者优先；精确平局依次比较 60 分钟达标率、最终确认质量，仍平局保留旧策略。完整核验前不切换；默认集成仍需依据两份完整报告处理。

这是**独立确认前、运行中补充冻结**的分析，冻结前已经见过部分开发输出。不能称为研究启动前的完整预注册。它审计“当时选出的有效候选何时已经可用”，不是实际在线提前停止实验，也不能声称已经测得完整端到端提速。只有五类合成问题、一个研究模型，不能推出所有真实研究的最快策略。

## 可复用的小接口

Core 新增 `orze.research.goal_efficiency`：

```python
from orze.research.goal_efficiency import incumbent_checkpoints, time_to_goal

checkpoints = incumbent_checkpoints(trace, measured_batch_completion_seconds)
# 独立评价每个选中候选；分数越高越好，确认失败用 None。
result = time_to_goal(checkpoints, confirmation_scores,
                      target=project_target, horizon_seconds=3600)
```

接口不提供新的调度器或停止策略；要求调用者提供实测批次时间、独立确认结果和任务目标。10 项 Core 检查覆盖失败耗时、批次可见性、无效时钟、未来分数不改变选择、截止时间与未达标处理。追加审计另有 3 项离线集成检查，实际读取轨迹并重算保存预测，仅替换容器执行边界，验证源码复用、基线篡改检测与禁止重跑。
