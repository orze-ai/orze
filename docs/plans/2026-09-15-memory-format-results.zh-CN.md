# 有界记忆格式与重启读取

基于 Core `88ad4ab17d22c0039c5f045d440a0c29badaf48a`、Pro `dbdfc4c11e90d1b35d088c65fcb720183efd5a3c`。Core 新增 `orze.research.memory_format`，提供严格的版本化格式检查和固定项目路径的新鲜读取。有效记录统一返回 `pending_verification`，保留作者／派生器填写的状态。

本部分完成格式和只读恢复接口。持久写入、并发更新、来源解析器、研究 prompt 消费与真实多轮研究仍须继续实现；现有 digest、笔记和研究调用未自动接入此接口。

## 格式合同

文档为 schema 1，绑定绝对 results 目录的 SHA-256，固定路径为 `knowledge/research_memory.json`。整份 UTF-8 至多 64 KiB、最多 32 条记录、每条至多 8 个源引用、总引用至多 64 个。容量超限或任一记录非法时整份不可用，不静默丢弃记录或反例。

每条记录包含 ID、question、hypothesis、rationale、claim、claimed_state、origin 和 sources。claimed_state 为 confirmed／refuted／unknown，origin 为 authored／derived。源引用明确包含 kind=report、binding_schema=1、idea_id 和 binding_sha256；这里只检查版本、类型和哈希语法。绑定的当前有效性仍需版本化解析器核实。

claimed_state 不是当前证据资格。即使语法正确、作者填写 confirmed，甚至预期哈希看似有效，格式层仍返回待核实；它没有查询来源，也没有验证自然语言结论。格式数据不能提供 permit 或旧执行接管权。

文件读取逐级持有目录描述符并拒绝重定向，检查普通文件与单链接身份，读取量至多上限加一字节，并复核文件和命名空间代次。特殊文件以非阻塞方式打开后拒绝。空文件、错误 UTF-8、重复 JSON 键、未知字段／版本、非法 ID、越界、多项目复制和读取中变化均整份不可用。这里的格式容量不是研究整轮 I/O／内存或 RSS 上限。

## 基线与边界验证

既有 digest／上下文基线 30 项通过、6.05 秒。随后保留旧版本缺少新模块的恢复失败：1 项失败、0.25 秒；隔离子进程明确返回 `format_not_available`。安装候选后，39 个新边界与既有测试合计 69 项通过、6.35 秒，源码／测试输入冻结。

首次 Core 全量保留 1 项失败、5,085 通过、7 跳过：重启测试子进程返回 `format_not_available`。受控诊断证明，从其他工作目录使用相对 `PYTHONPATH=src` 会加载已安装旧包；绝对源码路径可加载当前模块。原失败进程没有记录 cwd 与模块路径，因此不声称复原了它的全部环境。

只修正这个新测试的启动参数：显式在临时目录工作，并使用当前 Core 源码的绝对路径。断言和产品模块字节不变。修正后定向 69 项通过、6.56 秒，再完成两轮成本、独立内存采样和全量回归。早期 69 项、首轮全量失败及诊断各自保留，重复运行不相加。

新测试覆盖记录与引用容量临界值、恰好 64 KiB 和超限、多字节文本、未知权限字段、缺少引用、重复键、递归 JSON、symlink／hardlink／FIFO／目录、父目录或文件在读取期间替换、原位变化以及两次新解释器恢复。缺少源文件不会使声明变成已验证证据。

## 实际 CPU 产物、导入与恢复

两个隔离项目分别让真实 CPU 动作产出一份带 confirmed／refuted 声明的 JSON 文件。执行正常关闭并结算后，由验证程序显式模拟操作员把产物字节导入固定记忆路径；产品尚无自动记忆发布器。

每个项目依次进行两次新进程读取、错误 schema 读取、恢复原字节后的读取，再用新 Core CLI 重放。合计 2 个实际 CPU worker、4 次 CLI、8 个记忆读取进程，无 provider 调用。有效版本均为待核实，错误版本整份不可用，恢复后重新读取当前字节。四张执行相关表在全部读取与重放前后相同，执行引用、TREE_CLOSED／ECHILD_WALL、SETTLED、产物 SHA 均核对。

CPU 证据的范围是声明文件的产出、关闭和结算。声明内容、其虚构源引用和科研结论仍为待核实。该验证没有替代研究角色的多轮记忆消费或生产存储验收。

## 原型与来源代次反例

最初只读格式原型通过 31 个格式边界、7 个文件边界和两次重启。它使用较早的 `evidence_sha256` 引用草案；正式格式改为显式绑定版本与绑定哈希，早期格式未发布为兼容合同。

来源探索复用已有报告分页器，固定目标、策略、完整当前报告记录，排除 invocation 的临时 scan_id／cursor。第一版的八个场景表明：内容哈希能识别指标、污染、删除、生命周期、策略与原生代次变化，却漏掉同字节文件替换。第二版加入文件与命名空间代次，在首个重启比较中因元组／JSON 列表表示差异失败；初始 JSON 和日志保留，但该版未在断言前保存子进程 stdout，不能补造原始输出。第三版将返回值规范化成 JSON 类型并提前保存子进程输出，八个场景通过，同字节替换可识别。

这些探索尚不是已采用的来源解析器。原生 evaluation 代次 1→2 使用元数据夹具，没有真实 worker；不能与上节两个真实 CPU 产物混算。
