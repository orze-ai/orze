# 记忆发布前的完整必需提示词容量检查

本片修复显式记忆 v2 的发布顺序：合法的存储文档，不一定能连同规则、来源诊断、证据与预算装入研究提示词。此前普通更新会先发布修订，下一轮才报告超限；恢复待发布记忆也会先发布，再在首次提示词打包时失败。最后一次请求还可能发布超限记忆并正常返回请求额度耗尽。

修正版在 prepare 之前，以及恢复 pending 的 publish 之前，用原有打包器检查完整必需内容。候选文档使用实际操作 ID、修订、哈希、更新计数和全部来源诊断；没有裁剪反例或静默增加上限。独立只读分页预览保留可见 ID 和同一调用的预算观察器，不发布实际 provider manifest，不改变真实 context→完整 ID 捕获→谱系→可选来源的顺序。可选内容仍仅使用剩余空间。

预览读取逐次核查真实旧修订或精确 pending，预览后再次比较完整来源诊断。初稿对“恢复时、未显示的引用在预览后变化”检查不足，真实失败已保留并修正。两项停止测试使用了无效的 STOP 夹具名，另行记录为测试错误；修正为项目实际识别的停止标记。产品脚本首次通过恢复后读取了公共 API 不返回的 document_json 字段，改为只读 SQL 比较精确原字节，旧脚本与原根目录均保留。

已完成结果：基线453；旧版容量反例3失败；首候选80通过；新增边界首轮3失败9通过（1真实缺口、2夹具错误）；修正边界16通过；完整定向469通过。最终 Core 全量5,171通过、7项可选跳过、2项既有warning；Pro全量1,563通过；配对31通过。各阶段来源与测试指纹冻结，原始JUnit、stdout/stderr及命令均保留。

最终 CPU 产品链：两个作者声明场景，每个执行源任务与后续任务，合计4个CPU worker、6次Core CLI、22个新研究消费进程、24次离线传输调用、4次初始记忆管理进程、2次来源捕获进程。外部模型调用为零。完整关闭、结算、产物哈希、provider扣记和重放均由独立核验复查。普通／末请求的超限更新保留旧修订；超限恢复保留精确 pending且不调用provider；测试操作员显式提高隔离配置容量后，同一意图的原始JSON字节、operation和hash均原样恢复，未替换操作或删条目。此步骤不会由产品自动执行。

容量边界用实际捕获的完整预览进行UTF-8打包验证：中文、emoji、<>&转义、规则、全部来源诊断和联合预算均纳入；恰好相等通过，少一字节拒绝。在普通／待恢复 × 证据v1／v2的四组稳定夹具中，预览与实际发布后的消费记忆逐字段相同。普通拒绝保留其此前已发生的传输扣记，不退款、不重启调用。
