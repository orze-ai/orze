# 实际研究决策：入口修复与仍未解决的判断错误

本轮从排程提案转到两个已有研究决定：ASR 候选的测量口径，以及是否采用上一轮的简明证据视图。
目标是辨认可比结果、明确缺口并选择最小确认实验。七次真实请求、所有失败和原始响应均保留。
**有可复现的入口改进和新增测量；尚未证明整体研究判断或等质量效率提升。**

## 发现与最小修改

1. **读取整个 JSON 响应。** 原解析器会优先选中配置内部叫 `ideas` 的列表，或把单个提案内部的空列表当成空批次。
   现在先解析最外层值，兼容完整数组、明确的单个提案和已有的代码块／前后说明形式；
   不从损坏的外层结构中捞取内层提案。既有决策契约、来源与准入检查继续执行。
2. **最后一次响应不再提供无用的证据读取动作。** 联合快照已表明没有后续请求额度时，
   移除读取模板和动作提示；说明可基于已有证据提案，证据不足可返回空数组。请求限制仍由原执行代码强制检查。

保存的原始 Sonnet 单提案响应在旧入口被判为空。修复后原样重放，通过实际 consumer 和原生 CPU 路径保存了
完全相同的决策文件，没有新模型调用。最后一次请求的真实后续检查也从“读取后达到请求上限”变为生成并保存决定。
这些是消费与交付改进，不能把保存决策文件算成所提实验已执行或科学结论有效。

## 实测范围与结果

| 阶段 | 固定请求 | 结果及边界 |
| --- | ---: | --- |
| 当前入口基线 | 两案例 × Haiku／Sonnet，共 4 次 | 没有决策产物；包括解析错误、无效执行格式和最后一次响应请求读取 |
| 完成新测量后的 ASR 决策 | Haiku／Sonnet 各 1 次 | Haiku 仍混用分数且格式无效；Sonnet 正确读取共同口径的分差，保存 1 份决定，但统计计划缺少所需数据 |
| 修复后复查视图决定 | Sonnet 1 次 | 保存 1 份决定，但混淆历史反例覆盖和新候选失败率，未正确使用共同质量目标 |
| 原响应离线重放 | 0 次远端请求 | 修复后原样保存原先被误丢弃的 Sonnet 决定；不是新模型样本 |

基线计划在调用前冻结。第三项模型响应改变了要求的执行格式，使诊断校验抛错并停止启动；
随后仅执行原计划尚未运行的第四项，没有替换已有样本。后续阶段分别冻结新计划，属于根据失败进行的探索。
Haiku 使用 8192 输出额度、Sonnet 使用 16384／medium，各进程共享 200000 token、单次请求，无回退。
不同模型配置及每项仅一个样本，不能据此作模型能力排名。

## 实际测量与科学判断

根据模型提出的统一复算方向，使用 Orze 原生 CPU 执行器重新评分现有 ASR 输出。
全量覆盖预先指定的八个数据集、128 份文件，两候选参考文本按分片位置一致，文件哈希前后不变。
比较存储归一化文本与用同一已固定归一化器处理的存储字段；没有运行音频、训练或改变研究项目。
首轮控制器因继承的 60 秒外层超时中断，确认记录的进程已消失后，在新目录修正控制器时限并完成。
原件、预算和失败记录全部保留，没有假定旧数据库的 RUNNING 状态已经变成成功或自动续跑旧任务。

新测量后，Sonnet 能正确读出共同口径的差异，但提出仅凭汇总错误数与胜负计数做配对 bootstrap。
这些聚合量没有逐条参考长度和配对错误幅度，不能完成所要求的宏平均 WER 重采样。
因此先从原文件重建逐条三元组，再执行固定种子、2000 次配对重采样；每次使用相同抽样位置对应两候选和参考长度。
这符合[配对重采样的基本操作](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)，
但语句独立假设未经验证，分组身份不全，所得范围仅作为条件敏感性检查，不能代替群体推断或因果证明。
具体项目分数、逐条计数、全部响应和执行原件只存于私有 Pro 证据中。

另一个真实后续决定暴露了不同错误：模型把“初始展示的历史无效观察”当成“本轮产生的新无效候选”，
认为两个不同总体的计数互相矛盾，并计划重算一个无需解决的差异。
所以**数值来源正确、流程顺畅和计算能力都不能代替正确选择比较对象**。
