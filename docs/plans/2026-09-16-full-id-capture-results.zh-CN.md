# 完整 ID 捕获、SQLite 转换回退与实际调用成本

## 改变了什么

正常读取时，研究消费者在模型调用前仍捕获全部已有 ID，保留作者 ID 在先、数据库原扫描顺序、交集去重和完整结果列表。查询中断仍沿用原有部分结果及日志语义；此接口没有新增完整性认证或执行授权。对于原生默认 SQLite 连接，同一读事务先确认单列 `idea_id` 主键，再扫描 ID；数据库已保证唯一时，不再把每个数据库 ID 同时保存在 Python `seen` 集合中。作者 ID 集合仍保留，用于排除两种来源的交集。

基线 Core `d501654d1186989b19981e6bfef00cab16194c44`、Pro `ae0a585dfe80ca602abe2bab40f395371577d91c`。Core 产品代码没有改变；Pro 仅修改 research-context 内的完整 ID 读取、展示摘要和共享私有检查，新增 31 项测试。其他已有源码／测试逐个核对 Git blob，三个相关函数之外的 AST 完全一致，原 schema 检查代码 AST 保留。

主键保证不能直接用于任意 Python 读取器：启用 declared-type converter 的包装连接，可以把不同 SQL 值转换成同一个普通 Python 字符串，连接类、行工厂和文本工厂却仍表现为原生默认值。因此只有标准 builtin `sqlite3.dbapi2.connect` 的默认调用能采用此优化；包装连接、自定义工厂、特殊 schema 和观察失败都保留真实 Python 去重。参见 [Python sqlite3 的类型转换说明](https://docs.python.org/3.10/library/sqlite3.html#sqlite3.connect)。

完整读取遇到包装连接时直接沿用旧查询，不新增 BEGIN／PRAGMA，以免消耗其自定义执行步数预算。展示摘要保留原有 schema 观察及事务边界，但修复转换后 ID 碰撞的计数错误。没有跨调用缓存，没有将完整集合缩成提示尾窗，没有在模型返回后重新捕获历史。

## 原始失败与测试

基线 57 项通过。初始探针一项通过、两项失败：旧摘要把三个转换后相同的 ID 计为三项；20,000 条固定短 ID 的完整捕获 peak 为 4,116,217 字节，超过此夹具的 2 MiB 目标。最后一项同时检查完整 20,001 项结果的哈希，不能通过截断返回值满足内存断言。

首候选通过 60 项，扩展后通过 195 项。复查随后发现实际回退回归：即便不采用主键优化，首候选仍执行额外元数据查询，消耗包装连接 progress handler 的步数额度，中断前比旧路径少返回五个 ID。原失败与首候选成本保留；修正版对完整读取的包装连接不发新增元数据 SQL。

两个新并发测试最初误用 Python 3.10 的连接审计事件，在连接初始化完成前安装 trace callback，得到 `Base Connection.__init__ not called`。这次为 194 通过、2 失败；原测试、输出及单独诊断保留，未将它算作并发验证通过。最终测试在真实原生连接完成唯一性检查后、实际 ID SELECT 前发起另一个原生连接的 schema 更换：DELETE 阻止写入，WAL 允许提交；当前读取仍为原快照，后续读取看到新表并正确去重。检查结果、连接构造器和唯一性返回值均未替换。

最终定向 196 项通过，含类型转换、默认／特殊 schema、NULL／二进制 ID、作者交集、顺序、工厂、PRAGMA／BEGIN 拒绝、查询中断、缺失／损坏输入、并发快照及既有记忆读写路径。固定大历史完整捕获 peak 为 1,520,626 字节，原结果列表哈希保持一致。这是固定样本的 Python 分配指标，不是任意 ID 长度或整轮内存上限。

- Core：5171 passed, 7 skipped, 2 warnings in 1128.59s (0:18:48)。
- Pro：1496 passed in 426.70s (0:07:06)。
- 配对：31 passed in 0.74s。

集合存在重叠，不能把计数相加。每次测试使用唯一 basetemp；记录器确认源码／测试前后不变，进程关闭后才修改输入。许可检查仅在隔离测试进程使用替身，产品许可逻辑未修改。

## 真实 CPU 和捕获时点

最终源码复用既有、未改动的两历史产品 harness：每个项目有 5,021 个已有 ID，同一 HTTP 响应包含两份 A／B 提案。已有 A 的项目只接收 B，已有 B 的项目只接收 A；各拒绝三条重复项。观察到的顺序保持完整捕获→provider 开始→provider 返回→过滤，过滤使用原完整快照。

两个实际 CPU worker、八个 CLI 进程、两次本机 HTTP 请求完成；核对原生 attempt、`TREE_CLOSED`／`ECHILD_WALL`、SETTLED、producer／内容哈希及重放无重复写入。CPU 产物分别是 A／B 的对应数据。前候选同规模链路另行保留，不能合并成更多科研场景。没有真实模型、GPU 或账户调用。
