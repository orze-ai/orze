## 当前优先采用的十条经验

最新依据是[数据覆盖反馈与解析简化](2026-09-17-research-coverage.zh-CN.md)。额外诊断未提高真实案例质量；已有预测却能直接判定一个猜测系数更差，省掉不必要的新拟合。解析方法也必须通过留出确认，不能默认收缩。当前累计 **791次准备／772次返回／19次费用未知，已知估算$91.899562，预留$4940/$5000**；历史费用保持原口径。

1. **用便宜的替代办法检验价值。** 本轮C在两个真实油耗案例略有改善，同例128配置传统搜索仍更好；房价扩大搜索却退化。此前16配置单划分也曾与三折选择完整预测相同、成本更低。先给强基线，再为超出它的质量或效率付费，省钱和扩大搜索都受最终质量约束。
2. **先计算已有证据能回答的问题。** 给定开发预测，线性收缩系数可以精确求解；实际模型猜0.6更好，已有预测却证明[0,1]内应取1.0。仅这一数值问题无需新生成或重训。精确开发最优仍让两个真实案例留出退化，不能升格为默认科研结论。特征、目标与组合共同变化时，也不能单独归因。
3. **可见性要落实，收益要另测。** 覆盖事实确实进入提示并被引用，D仍无新候选改善初始选择；真实留出两差两同。更多统计不要默认堆进每轮。错误反馈和原始比较定义要可见，模型对误差方向、估计器类型与分组单位的解释仍需核对。
4. **按实际预测识别研究冗余。** 不同合法配置可给出完全相同结果。新对照 A／B 分别有 12／13 次，B 还精确重复了一个已评配置；存在记忆不证明避免了无信息增量的实验。
5. **消费已经返回的研究成果。** 编排失败后补齐现有计划的 CPU 评价，不重新付费生成同一阶段。保留失败、等待和原始响应，让恢复成本可见。
6. **让收益决定追加工作。** 上一轮9个新训练程序未显示稳定整体收益，其中一个开发改善45%的代码在留出严重退化。7秒CPU诊断定位了外推风险，本轮把覆盖信息提供给模型后仍未改善质量。发现问题、解释问题和采取有效实验是不同步骤；后续工作应验证最后一步，不继续累计更多诊断字段。
7. **执行必须保持处理定义。** JSON 数值 `1e-05` 送入当前 YAML 读取接口会变成字符串。按接口格式写出，并核对从声明到实际执行的类型；不能通过放宽参数校验掩盖变形。源码清单还要包含实际导入的 example 驱动。实验声明也要核对：声称单因素的四个候选，其中一个实际改了两个字段；允许联合探索，不能据此作单因素归因。

8. **先检验已有收益，再扩大结论。** 96次便宜的固定拟合发现：原翼型配置只在3/8个新划分上改善，混凝土为5/8；单次收益没有变成稳定规律。这是同数据的敏感性检查，不能替代独立确认或完整策略评价。两条提醒也没有稳定纠正后续计划：下一步应核对实际比较对象和数据关系，不继续加提示。

9. **把确定的计算交给可复核工具。** 四个真实案例中，逐样本数据改为原生计算结果后，可记录判断由2/8升至7/8，后者结构化事实全部正确且项目耗时／费用更低。这支持计算辅助读取；后续方案仍会提出不支持的参数或不存在的新样本，不能把事实正确当作研究成功。对照同时改变计算与呈现，也不是最佳现有分析流程的比较。

10. **先检查新结果还能改变哪个决定。** 研究目标、模型说明和实际选择器应由同一规则定义。明确同分规则后，两项零错误任务B均停止，其中一项A仍做八次无效追加；但八对完整结果B为0好、5同、3差，规则更清楚不等于质量更高。可选MinimumLoss示例在两个真实CPU项目中各约21秒、零模型调用，保持相同配置及完整留出预测。只对任务已证明的精确下界跳过搜索，保留确认；六个未打乱案例的模型追加研究没有改善留出；随后单划分／三折对照也没有稳定解决该问题，继续加提示或加折都不能替代新研究假设。

## 接下来的工作规则

1. **先提出研究问题。** 写清触发条件、预计减少的浪费、质量约束和失败判据；冻结对照、顺序和预算后再调用模型。
2. **做最小的有效修改。** 优先删除无用选择、重复内容和矛盾规则。只有实际瓶颈需要时才引入新基础设施。
3. **完整计算一次研究的成本。** 从输入准备到独立评价，计入失败、重试、记忆操作和本地时间；另外记录首次有效改进时间。
4. **以结果选择下一步。** 有效改进数、确认质量、等质量时间／费用和重复失败是主指标；测试数、笔记数和提交数不是研究收益。
5. **区分探索和验证。** 小任务机制诊断可以指导修复；更难任务、长历史和跨领域对照决定通用结论。不要不断在同一道小题上调提示词，再称之为泛化。
6. **保留必要的可信边界。** 来源变更、预算、所有权和恢复语义不能靠猜测跳过。先定位开销，再删除重复工作。

## 最新：先审查输入定义，再解释模型差异

[16 次真实校准](2026-09-17-research-calibration.zh-CN.md)揭示两类问题：模型确有计算／统计错误，
我们构造的案例摘要也把首轮可见历史写成含混的 initial_reports，且省略指标定义。
较强模型因此正确算出质量差距，却安排无必要的初始历史匹配。修正事实标签后该伪冲突在两次 Opus 响应中消失。
这修正了上一轮“全是模型混淆总体”的过强归因，原始数据和失败仍完整保留。

- 先核对输入是否给足对象、范围、分母、指标方向和缺失含义；不能用哈希替代这些科学定义。
- 模型价格不是科学判断质量；先测当前可调用配置，再决定是否值得改变，Sonnet 5 的 thinking 默认已开。
- 算法名称正确仍可能输入不足：统计区间不能自动解决分组相关性、训练种子变化或模型身份绑定。
- 不同候选的 checkpoint 本来可以不同；应核查每份结果绑定其声明的权重，不能要求候选权重相同。
- 下一步让模型提出分析并获得真实 CPU 结果，再评价决定；继续做只保存建议的同题诊断已不足以推动能力。

## 最新：计算反馈能传递错误，二次复核也可能退步

[两道新案例的真实计算反馈](2026-09-17-research-loop.zh-CN.md)已完成。独立 CPU 分析不再被训练父节点配额拦截，
计算结果确实进入下一轮提示；但计算组照抄了跨任务均值，直接复核组把首次达标时间除以成功轮次后错误地撤回原判断。

- 来源核验、执行通过、组内算术正确、聚合合理、最终判断正确是不同检查。工具结果仍须允许质疑。
- 二次复核应指出具体改变及根据；没有数值变化却声称“纠正算术”，不算改进。
- 不通过修改分母消除失败等待，不凭已返回请求构造未知费用上界。
- 小样本限制可信推断，但不意味着样本方差或所有统计计算在数学上不可能。
- 负对照同分仍能检查开销和伤害，不因本次没有分差就删除。
- 让模型复写固定配置增加无科学价值的输出；下一步先简化必要输出，在新案例验证，避免重复调已知题。
- 人工案例转写也会出错。task1 目标在首次相关调用前由 37 更正为 45，保留原件，后续直接从源结果派生。

本阶段累计 **291 次准备／272 次返回／19 次费用未知**；已知用量估算 **$10.621312**，保守预留 **$571 / $5000**。

## 最新：先给强基线、可见最佳结果和真实运行环境

[24 次真实代码研究](2026-09-17-research-codec.zh-CN.md)得到有限保留集质量收益，同时暴露研究效率瓶颈。

- 更换已有压缩器贡献了大部分提升：相对 zlib 的约 11%，在标准 xz 参照下收窄为 0.56%／1.02%。先测廉价标准基线，再为剩余差距付费。
- 试验自设的较小容量隐藏了已有最佳结果，模型于是重做次优方案。先删除不必要的配置覆盖并验证结果利用，不因一次不利输入立即新增检索机制。
- 提示未写 Python 版本导致两份 API 调用不兼容；评价器仅返回异常类型。输入充分性与模型判断共同决定失败，不能把本方遗漏归咎于模型能力。
- 负对照仍有价值：两字节长度使有限集省 206 字节，却在大记录失败。边界诊断不改写原有限集有效性，也不把未到达的递归案例计作已发现失败。
- 可选记忆开着却未被使用，不能把组间分差归因于记忆。评价计划要求六轮，不能把后续微小优化直接判成自主停止失败。
- 仅压缩研究文件可以用成熟工具：相同原件标准 xz 比 gzip 小约 59%，额外约 18 秒压缩时间；未删原件，未将其当作研究决策提速。

## 最新：有结果之后，还要问是否比廉价方法值得

[实际 ML 研究](2026-09-17-research-ml.zh-CN.md)得到真实留出集收益，也否定了“少调用／有摘要就更高效”的假设。
普通多轮研究在两组低标注识别中得到 10／9 个错误，初始最佳为 17／15，固定随机参照为 10／15。
滚动摘要更便宜却全部更慢，一次批量则有两对提升、两对持平、两对退化。保留按任务选择的空间，不直接改全局默认。

- 先给廉价常规搜索机会。只有超过它的质量或完整成本，才支持模型研究带来额外价值；优于弱初始方法不够。
- 预检覆盖实际状态更新和最终确认。一次干跑漏掉派生摘要替换合同，只跑开发集又漏算留出动作预算；扩大测试数量不如跑通最小完整研究链。
- token 预算包含全部证据读取；CPU 预算按每个动作声明的 timeout 永久计入。不要用单次请求或实际短耗时估算整个流程的准入额度。
- 类型是实验定义。ExtraTrees 的整数 1 是一个特征，浮点 1.0 是全部特征；哈希正确、预测复算正确仍不能证明执行了文字所述处理。保留原件，独立审计影响，再明确新输入语义。
- 能低成本合并的实验可以批量规划，但这会放弃中间反馈。不要以一次批量的低费用掩盖另一组完全没有质量改进。
- 被引用报告定向读取可删除无用扫描；本地 52.85% 加速仍没有让摘要组整体更快。工程收益与研究收益分别报告。
