# 长程研究信息访问：下一实施片

起点：Core `94dd2f7e2e30e31fe4a1740906abb7add5bf4bae`，私有 Pro `15a7c2823649c026dfc1623365c9a1655d99f6da`。本文件是实施／验收合同，不是完成声明；在 `feat/research-production-validation` 分支继续，不合并 main、不切换生产、不修改 ASR 项目。

## 要解决的两个可复现问题

1. 当前 CPU proposal 回执视图固定返回按 request ID 排序的前 32 条，长期研究无法通过该视图看到后续接纳、重复和冲突结论。
2. Pro 的 authored retrospection 只读文件前缀，并在 prompt 装配时再次按前缀压缩。长期追加的新结论可能一直不可见。它是未验证笔记，不是当前实验事实或指令权限。

## 实施边界

- Core 在自定义 `action_policy.version: 2` 下增加可选 `proposal_page_size: 1..32`，显式启用 proposal 分页与定向查找；不静默更改旧 v1／旧 v2 的视图或默认行为。
- 同一 policy 决策循环支持 `ReadProposals`、`SelectProposals`。与证据读取共享进程／连接／路由／数据库读版本约束，分别维护有界页状态与单次游标。读取不重复 ingress、不预约预算、不消费 `--once` 的执行机会、不启动 worker。
- 只读历史回执仍完整校验原有封印格式、scope 与 database。缺失 ID 明确表示缺失，损坏行拒绝；不合成新拒绝记录、不把旧 source snapshot 变成当前输入授权。正常 Propose／Replicate／Execute 继续经过原准入路径。切换读取通道时重新校验当前展示的证据，不把过期产物视图当成新鲜事实。
- 不改 proposal 表结构、不改四类持久 outcome、不引入永久扫描缓存。分页结束只表示本次有界视图遍历结束，不代表研究收敛。
- Pro 增加显式 `retrospection_window=head_tail`，默认仍为 `prefix`。新模式最多读取头部 8 KiB 与最新尾部 8 KiB；短文件只保留一个不重复的块。同一 FD 检查文件身份，准确记录 UTF-8 字节区间、hash 与省略原因。尾块优先于头块但低于必需规则与当前证据，尾块空间不足时整体省略并如实记录，不声称任意预算都能保留最新结论。
- Pro 复用现有 manifest schema 1，不放宽区间验证；不自动改写笔记、不引入持久摘要。本片不改 knowledge 目录的前缀策略。
- 不增加研究总时限。单动作资源界限、Stop、HOLD、预算不退款和真实执行闭合证明仍保留。

## 验收要求

先保留真实旧行为的失败／正控，再实施。未知配置或缺失 API 的失败不能替代行为缺陷证据。原有测试不删改。

- Core：正常 admission 产生超过一页的回执；真实 policy/CLI 能读取后页并据此作出后续决定。证明只读链不启动额外动作，正常 native 执行仍取得真实闭合与账本证据。回执夹具不得冒充 worker 实验。
- Core 负控：旧游标、跨扫描游标、数据库修改、回调变更、损坏回执、缺失请求、只读与持久 Stop 顺序；历史回执不授予新的输入权限。
- Pro：实际 role 参数 → CLI → research cycle → prompt 装配路径；头尾皆可见、默认兼容、UTF-8 边界、短文件、读失败／文件变化、预算不足、manifest 区间与 hash。provider 只用测试替身，不称为线上模型验证。
- 冻结源与测试指纹，跑相关回归和完整回归；所有失败如实保留。若构建新制品，使用新的隔离环境核对源码／wheel／安装内容，不覆盖原有环境。
- Core 公开、Pro 私有；Pro 完整源码快照、原始私有包清单和测试明细只进私有仓。公开仓只记录结果、哈希和私有原件引用。

## 单独保留的性能工作

本轮只读诊断已定位 budget 的逐行 N+1 查询，以及空 ingress 仍扫描历史 ID／配置缓存的问题。合成元数据诊断不等于真实生产负载。本片先归档测量，不用 SQL SUM／缓存替换原账本完整性与整数精度检查；后续单独做共享原校验器的查询合并和 ingress 有界化，再给出等价性及规模证据。
