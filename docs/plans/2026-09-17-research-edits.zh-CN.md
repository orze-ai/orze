# 执行真实实验：不推广改动清单，先消除无法改变选择的搜索

## 本轮结论与采用范围

已完成 18 个有实际拟合和留出评价的研究项目，以及 2 个零模型调用的补充对照。24 次真实模型请求全部返回。

1. **完整配置改成“已有配置＋改动清单”，没有稳定提升研究质量。** 六对留出结果，B 对 A 为 1 好、3 同、2 差；项目时间合计多 8.3%，调用费用多 4.3%。保留实验实现和原件，不新增产品默认动作格式。
2. **普通研究有具体收益，但成本更高。** 船体阻力两划分中，A 相对初始参照的留出 MSE 分别改善 12.59% 和 4.23%，也都优于追加 64 次常规随机搜索的选择；约 91–102 秒、$0.29–0.31，对照随机搜索约 45–51 活动秒、零调用费。它支持具体质量／成本取舍，不是普遍策略提升或独立物理发现。
3. **有一项可以明确简化的研究步骤。** 当错误率已为 0，且实际选择只接受严格改善、同分保留原候选时，任何新候选都无法改变选择。两个新 CPU 项目跳过搜索，仍执行初始训练和留出确认，最终配置及逐样本预测与 A/B 完全一致；每项约 13.8 秒、零模型调用，原流程约 91–103 秒并追加 8 个实验。
4. **把重复明细从模型观察移入产物。** 大批次重复元数据先超出 JSON 节点上限，研究被阻断；投影成必要的逐候选事实后，后续四候选批次实际进入模型第二轮提示，完整明细仍有产物。保留项目适配器的这个简化，不扩大 Core 限制或添加新的调度框架。

第三项有关键限定：原模型提示没有明确告知控制器的同分规则。模型其实都读出了“不能比 0 更低”，转而提出寻找更稳健的零误差区域；这可能有另一个研究目的，却不能改变本实验实际执行的选择。
因此不能把额外计算全部归咎于模型能力。以后先说明**实际选择规则、同分处理，以及何种结果会改变决定**；需要研究稳健性时，应另设可执行目标及评价。
达到某个有限样本目标不证明科学收敛，也不替代后续确认、外部数据或其他研究问题。

## 精确达到目标下界时的 CPU 对照

本项是在观察到无效搜索后追加的两个已知适用案例，不是盲测新策略。两项重新运行相同 16 个初始抽样，再由可信的选择逻辑检查：

- 目标是最小化同一开发集的分类错误率；有效参照恰好为 0。
- 错误率是逐样本 0/1 错误指示的均值，数学下界为 0。
- 选择只接受严格改善，同分保留较早候选；没有其他次级选择目标。

这些条件意味着继续产生候选不可能改变当前选择。流程记录这个决定，随后实际重新拟合并确认原选择；没有查看留出结果后改选。
两个项目分别用时 **13.80 和 13.78 秒**，零模型调用、零追加搜索拟合。
独立核对了相同初始配置／分数、相同最终配置和完整留出预测字节；两项留出错误率都为 0。
原 A/B 对应每项 8 次追加拟合、2 次模型调用，耗时 90.82–102.52 秒，费用 $0.2931–$0.3206。
这是先前运行与追加运行的时间比较，未随机化同时测量；保持选择的结论来自选择规则和实际复核，而不是耗时差本身。

不能将“接近 0”、无改善若干轮、调用额度耗尽或模型自称收敛替代上述条件。
若选择器允许同分时换更简单的模型、目标包含稳健性，或参照不合格，就必须重新判断可达范围；本次快捷路径不适用。

## 执行与输入定义

最初 3 任务 × 2 划分 × A/B/R 三方案，数据、分组、搜索列表和额度在拟合前固定。每项目先六个常规方法加十个冻结随机抽样。
A/B 各两轮、每轮最多四候选，Opus 5 high、8192 输出、每轮至多三次证据请求、420000 token 预留，无重试或 fallback。
实际每轮均只用一次 HTTP，请求正常签名 Pro 许可及原生动作入口；没有模型生成的任意程序执行。

B 只提交 `base_id` 和 `changes`；同家族参数逐项合并，更换家族时整套参数替换。有效候选空间与 A 相同，480 个冻结配置的两种展开结果一致；错误基础 ID／参数仍拒绝。
两边都有经原生预测核验的完整可用配置／分数表，完整请求只能改变候选输入。不同配置产生相同预测与精确配置重用分别计数。
精确重复在所有方案中复用已有绑定预测；失败或重复候选不补发新的槽位。
分数和下一轮选择均来自真实拟合反馈，最后按有效开发损失最低者选取，同分保留较早者。
**这个同分规则写在计划和控制器中，却漏写进模型实际规则。** 八份 banknote 假说都承认误差已到下界，再设想按平台宽度／平滑性换选；当前控制器没有实现这种次级选择。
这限制了对模型无用探索的归因，也说明配置格式不足以修复研究目标与实际动作不一致。

## 输出过大、恢复与尚未结算记录

原私有工作器在每个候选里重复完整比较元数据。`yacht-1-R` 第五批的结果文件约 25 KB，观察记录本身可编码，但通用 Domain JSON 复制超过 **2048 节点**，CPU 发布无法完成，控制器进入 HOLD。
只读重放分别验证了这个差异；没有把文件字节小误认为内部结构一定在界限内。
相同重复结构还超过 Pro 单证据记录的 **12288 字节**，四份原始模型提示均没有配对明细，尽管完整配置／分数表存在。

新工作器将完整信息单独保存在 `details.json`，观察仅保留必要配置、分数、变化路径、配对差和重用量。源代码及输入分别冻结，重新走 A/B 原生预检。
新五对的十份第二轮真实提示都能读到四候选的比较事实；第一轮八候选初始记录仍有单条容量诊断，不能声称历史明细全部可见。两边始终有完整可用配置／分数表。
选择更少 ID 只可能缓解总快照容量，不能消除单条记录上限；原始产物存在也不证明模型看到了它。

原批次完成 A/B/R 的 yacht-0，R 的 yacht-1 中断，其余 14 项未启动。保留原停止标记及全部原件，在新目录完成 15 个项目。
中断的随机项目复核原已完成历史及第五批的 8 份原始预测，将它们明确导入新的历史产物，只继续原定第 6–8 批及确认；没有重新拟合既有批次或重新请求模型。
**原第五批仍为未结算 RUNNING／HOLD 记录，预算预留保留。** 外层控制器有完整进程树关闭回执，捕获的子监督器和工作器身份已不存在；不能据此把原发布事务伪装成成功。
本次导入是数学核对后的新来源，原生终态和原产物发布仍未确认；将其单列，六项原交接验收继续开放。
