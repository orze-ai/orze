# 完整持久记忆进入研究提示词、消费复核与实际 CPU 后续提案

## 本片结果

Pro 的实际 `run_research_cycle` 现在支持显式 `research_memory: {version: 1}`。需要有效的 `research_evidence` v1／v2 和调用方提供的可信规则 SHA；缺失或 null 保持原行为，其他非法声明不会关闭检查后继续。记忆缺失、pending、损坏或读取接口不可用时，本次调用明确 blocked，不创建空记忆，也不改读旧 JSON。

基线为 Core `102d9accaa05ecec9902c8b76048a73dc6c9570f`、Pro `3c6453daa9db2bf0185d15ce76f21fa15134d46d`。Core 产品代码／测试不变；Pro 增加 122 行 `memory_consumer.py`，`research.py` 增加 48 行、替换一行签名，新增 49 个测试。

记忆块是完整的必需提示词内容，包含全部作者／派生声明、修订号、操作 ID、文档 SHA 和当前来源诊断。来源失效的反例仍保留，零引用笔记仍为 unconfirmed，所有声明仍为 `claim_verified: false`。JSON 对 `<`、`>`、`&` 作等价转义，防止作者文本中的闭合标签造成标记混淆；解码后的声明不变。必需内容装不进现有总上限时，整次调用返回超限，不能静默截掉反例。

调用先捕获原配置／独立 report 参数和有效数据库配置，按同一报告数据库权威解析完整记忆；每次复核重新读取规则、配置来源文件和数据库记忆，并比较完整来源状态及修订元数据。复核点位于提示词构建后、原生清单发布后／provider 前、provider 后，以及提案过滤后和最终格式化后／追加前。规范化数据库路径或补入 report 配置可能使旧引用失效，必须显式重新绑定，不能改写旧哈希冒充当前来源。

本片只消费已有记忆。它不发布或压缩记忆，不授予旧执行接管权，也不改变分页的本次请求预算、provider 预留或既有提案准入。多个复核点是可观察变化检查，不是跨 provider、数据库、文件来源和队列追加的原子事务；相同字节配置内容不等于任意命名空间 ABA 或备份回滚检测。

## 保留的失败与修正

固定基线 174 项通过（34.75 秒）。实际旧研究调用完成持久记忆设置后，provider 收到的提示词缺少记忆块，探针失败一次（0.50 秒），原件保留。

首候选 211 通过、8 失败（48.12 秒）：八个测试提案缺少成熟研究所要求的父节点，被既有谱系规则提前拒绝，未到预期过滤／格式化检查点。只修正测试的合法父节点后，45 项通过；新增边界探针发现一个真实产品缺口：无引用笔记在格式化后遇到配置文件变更，候选仍追加了一条提案。失败的队列、配置文件、数据库和原始日志均保留。

修正版为记忆上下文单独捕获并复核 `_config_path`，沿用报告分页的 4 MiB 有界规则文件读取及路径检查，核对 `_research_config_sha256`（如提供）；读取前后检查原配置、有效配置、配置文件 SHA 和可信规则。因此零引用路径也无法跳过配置来源复核。最终定向 223 项通过（50.43 秒），包括该失败探针、合法提案正对照、两个新消费进程恢复同一份完整记忆，以及相同 16 KiB 提示词上限下禁用记忆可通过、完整 31 条反例记忆明确超限的对照。

Core 全量 5,148 通过、7 可选跳过、2 既有 warning，1113.46 秒；Pro 1,406 通过，386.77 秒；配对 31 通过，0.73 秒。测试集合重叠，不能相加。两仓输入冻结，Core 既有源码／测试及 Pro 未改文件与基线逐个 Git blob 核对，改动模块、新模块与新增测试均与候选快照一致，移除明确新增的记忆逻辑后，研究模块 AST 与固定基线完全一致。

## 实际消费链与执行

两个隔离项目各先运行一个 CPU worker，生成相同的合成报告；操作员分别保存 confirmed／refuted 作者声明。驱动完成 38 次 Core 记忆子进程（14 读、14 prepare、10 publish）、八次来源捕获、16 次数据库来源解析与两次冲突旧文件读取；保留提交后退出 73 的丢失确认与精确重试。

另有 22 个新进程运行实际研究消费者，16 次调用确定性的进程内离线 provider，外部 provider／模型调用为零。缺失或 pending 时未调用 provider；可读取的失效来源与未知笔记完整进入提示词。provider 中途改动来源时，生成的提案被拒绝，队列未追加。

修订 3 中的原声明和后加 unknown 均进入最后的提案提示词。每个项目追加一个合法父节点的 `native_cpu_action`，再由真实 Core CLI 执行和重放。总计四次 CPU worker、八次 CLI；后续产物逐字记录修订 3、作者状态、`claim_verified: false` 和两条保留记录 ID。核验检查 action attempt、`TREE_CLOSED`／`ECHILD_WALL`、SETTLED 预留、producer 与产物哈希、原四表记录保留及重放不重复执行；执行后的新消费进程仍恢复同一完整记忆。

所有原始提示词、响应、提示词清单、数据库及产物在私有证据中。离线 provider 证明消费与执行链连通；作者状态影响合成产物字段不证明声明为真，也不构成真实多轮研究质量或 P3 收益验证。
