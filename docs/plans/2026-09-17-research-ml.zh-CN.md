# 实际 ML 研究：有质量收益，怎样少花时间得到它？

## 当前结论与决定

**正常研究链已产生可核验的模型选择收益；本轮仍不支持通用研究能力或整体效率稳定提升。**
普通历史组 A 在两个低标注数字识别划分中，把留出集错误从 **17／15 降到 10／9**。
固定廉价随机参照得到 **10／15**，所以 A 只在第二个划分优于该参照；不能把优于初始方法直接等同于优于常规搜索。
这是熟悉公开数据上的有界调参，不能叫作新架构、独立科学发现或未见任务泛化。

本轮作出三个实际决定：

1. **不默认启用滚动摘要记忆。** B 在六对留出结果中 1 对更好、2 对相同、3 对更差；六对都更慢。调用与费用下降没有补偿完整时间和部分质量退化。
2. **保留按需批量实验的使用方法，保留自适应研究能力。** D 用一次模型决定安排最多八次训练；对 A 的结果为 2 对更好、2 对相同、2 对更差。数字识别一组保住 9 个错误，另一组停在基线的 17 个错误。一次批量不能普遍替换多轮反馈。
3. **保留两个针对已见阻断／开销的小修复。** 派生摘要可替换，人工撰写条目仍受保护；来源验证直接读取被引用报告。它们有正确性与局部性能证据，不能据此声称科研质量提高。

下一优先级是决定何时需要下一轮自适应实验：在新任务先给廉价常规搜索同等训练机会，再检验模型是否能针对实际缺口提出有价值的改变。
本轮没有把该策略写成产品默认，也没有在已看过的划分上反复微调提示后宣称泛化。原定九项验收继续开放。

## 实验设计和核验边界

- 真实 CPU 训练，正常签名 Pro 许可和研究 CLI；Opus 5 high、输出上限 8192，每决定最多三次请求、共享 420,000 token 预留，没有自动重试或 fallback。
- A／B：3 个任务 × 2 个划分 × 2 个条件，每项目八轮；默认 v2 报告分页与 32 KiB 联合快照。B 每次评价后通过现有 prepare／publish 接口重建最多四条“最佳有效结果＋最近三个不同观察”派生条目。没有额外模型摘要调用；原观察和完整历史保留，不能声称四条笔记保住了所有旧反例。
- 初始十一配置包括 dummy、线性模型、近邻、RBF SVM、ExtraTrees 和 HistGradientBoosting，均实际训练。随机参照按预先保存的八配置列表训练，不根据结果调整。该列表在 V2 启动后、检查其响应／新配置前冻结，当时已有三份返回与一轮结果；所以不称为启动前预注册。
- D 在同样原始数据上增加一个明确的全特征树参照，未改变任一划分的最佳初始损失；一次提案可安排 1–8 个有界配置。模型没有收到 V3 模型提案或留出成绩。D 同时包含参数语义修正和批量规划，是探索性组合修改，不是只改变批量的严格因果实验。
- 模型仅给声明式配置。训练前核对完整展开动作，只允许配置内容改变；固定 worker、数据、分割、协议、输出和超时。每个训练单线程、4 GiB 地址空间、45 秒警报；批量原生动作 480 秒、外层等待 510 秒、440 CPU 秒。固定八轮是实验边界，不是产品收敛或总期限。
- CPython 3.10.12、NumPy 2.2.6、SciPy 1.15.3、scikit-learn 1.7.2。拟合与标准化只用训练行；模型选择只用开发集。评价后独立读取预测，逐行复算分类错误或 MSE，不接受模型自报分数。

数据来自 [scikit-learn digits](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_digits.html) 与 [UCI Wine Quality](https://archive.ics.uci.edu/dataset/186/wine%2Bquality)（Cortez 等，2009，DOI 10.24432/C56S3T，CC BY 4.0）。
Wine 合并红／白酒 6497 行，十一项测量加酒类型。按完整特征行 SHA 分组后分训练／开发／留出，完全相同特征不跨集；未证明物理样本或书写者独立。
数字识别每个划分按固定行哈希仅取 256 个有标签训练行，选择发生在任何模型分数之前；未取用的训练行不转入评价集。
两个 digits 开发／留出样本数为 368／329、347／373；wine 训练／开发／留出为 3793／1377／1327、3907／1332／1258。
独立审计重新核对分组、低标注选择、未用行、负对照置乱与边际分布。熟悉的公开数据可能已在模型预训练中出现。

## 保留的错误与研究经验

1. **工作流预算不能只算一次请求。** 首批 V1 的 100,000 token 不足以容纳多次证据读取，九次真实请求后停止；费用 $1.158970。随后改为三份最大输入与输出合计 417,984 的保守需求，420,000 覆盖完整决定。
2. **干跑没有验证状态更新。** V2 首次滚动摘要被旧存储合同拒绝：原实现连派生条目也不许替换。保留十九次实际请求与 $2.516375，修复后预检两次实际训练／发布／再读取。中断不计作完成的 A/B 对照。
3. **数字类型是处理定义的一部分。** 原 worker 将整数 `max_features=1` 直接传给 ExtraTrees，实际表示每次切分考虑一个特征；`1.0` 表示全部特征。这符合 [ExtraTrees 参数定义](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.ExtraTreesRegressor.html)，却暴露我们“允许整数和浮点的比例范围”说明含混。十二次独立开发集训练核对了六个划分，修正没有改变任一最佳初始方法；最终扫描 V3 的 92 份提案，没有整数形式的树参数。保留原 worker 和实际分数，D 统一新输入为浮点并增加真实全特征参照。哈希与损失复算不能代替处理语义核验。
4. **预检必须走到最终确认。** D 的最初数值预检通过，但编排只预留 1320 秒：13 个标量动作×60＋批量480＋两次留出60，需要 1380。原生预算永久计入完整 timeout，即便实际训练很快；最后一个留出动作正确拒绝。原停机项目、费用和配置完整保留；新范围补完已有两份提案，没有重调模型，没有改停机数据库。新预检实际走完两次留出，再运行尚未开始的四份决定。
5. **批量节省的是反馈机会，也可能丢掉它的价值。** 一组 digits 的八配置集中于树与标准化 SVM，没有超过近邻初始方法；另一组包含未标准化 SVM，实际得到九个留出错误。此事后解释指向下一步实验，不证明我们已经找到适用于新任务的选择规则。
6. **降低局部开销后仍需检查整体。** 摘要来源读取更快，但完整 B 仍更慢，且更好的开发集结果没有稳定转成更好的留出成绩。保留失败和廉价参照后，才能判断哪些工程值得继续。

## 已提交的产品改动

Core `f1a1143`：允许派生摘要快照正常轮换；此前存在的 authored 条目和它们的来源身份仍受原有保护。
`origin` 是调用方声明，不是作者身份认证。Pro `dea00ea`：直接按被引用 ID 读取报告，复用已有来源资格与可见性检查，删除无关首页资格扫描。
常规分页与游标、来源改变拒绝和发布时二次核验均保留；没有新增全局默认摘要策略。

365 项相关验证通过（Core 64，Pro 301）。早期缺少许可的收集失败及一次误加载原主线导致四个新增回归失败均保留；最终确认加载隔离改动路径并用正常许可运行后通过。
真实完成项目上的 ABBA 四次非剖析读取，平均 **16.678 → 7.864 秒（减少 52.85%）**，四次返回内容完全相同。
剖析中的报告捕获从 88 次降到 40 次。这是来源读取的局部效果，不能乘到总耗时或当作研究质量指标。
