# 提案入口的逐条标题边界扫描

基于 Core `64cd017ed427f3c6dbcca54a01dbaa3d4842c072`、Pro `e7e7479045cfd85c2cf92abf15b56648b0dc96de`。主提案文件的 `_blocks` 原先同时保留所有正则 Match 对象和完整段落索引。现在复用已有的 `_sidecar_sections` 迭代器，只暂存相邻标题，仍返回原来的全部段落边界。

## 保持的语义

未知／格式错误标题仍分隔段落，重复 ID 的原文仍保留。读取完整新鲜源文件、现有 4 MiB 文件限制、全部段落索引、ID 次数统计、候选列表、分页、配置解析、旁文件优先级、锁、数据库准入与源文件确认删除均未改变。没有缓存解析结果，也没有跳过新鲜读取。

因此本片只减少临时匹配对象。完整源文件和索引仍保留，每页和每轮的再次读取、目录扫描及其他内存开销继续存在；不能称为整轮 I/O／内存硬上限。

## 基线与冻结失误

首次指定的既有基线测试本身为 110 通过、113.80 秒，但在它尚未结束时，代理过早加入新测试文件，破坏了整份输入冻结。原记录明确为 frozen=false，子进程退出 0、记录器退出 99，**不计入有效基线**。机械核对确认唯一差异是新增 `tests/test_ingress_heading_window.py`，既有源码／测试内容均未改变。

保留现场和说明后，在独立目录重跑相同既有测试：110 通过、113.93 秒，输入冻结一致。之后才修改实现。新增的独立解释器固定夹具包含 20,000 个合法标题与 2,858 个未知标题，原文 1,117,833 bytes。旧扫描峰值 7,077,103 bytes 超过该夹具的 5 MiB 阈值；保留 1 项失败、0.43 秒。该阈值只约束固定文本的扫描，不含读取、准入、执行或 RSS。

最终定向 111 通过、115.05 秒。28 组正式差异比较保存完整段落、重复次数、候选、分页窗口和各段原文字节 SHA；覆盖空文本、未知标题、重复 ID、CRLF、Unicode、代码围栏及 20,000 条输入。原型的独立比较和成本记录另行封存。

## 真实 CPU 执行与源文件保留

两个独立项目各含 20,000 个无关标题、两个同 ID 的冲突定义，以及唯一合法的 CPU 提案；合法段落分别位于文件中间和末尾。真实 Core CLI 各执行一次后，再以新进程重放。

共两个实际 CPU 动作、四次 CLI 调用。仅合法段落被确认删除；前言、无关标题、冲突定义和混合 CRLF 字节均与预定保留原文一致。被动观察器记录实际扫描文本 SHA、20,003→20,002 个段落及 ID 列表。执行引用、TREE_CLOSED／ECHILD_WALL、结算、产物 SHA 与四张表重放均核对。

这验证了入口与原文边界，不代表模型或科研收益。没有 provider 调用；Core-only 子进程禁用 Pro 导入时的可选扩展诊断保留。
