# 服务自然结束与已关闭服务管理：验证结果

控制器完成研究策略后，常驻宿主现在能够核实完成状态并关闭自身；已关闭服务可查询记录、
卸载选中的 unit。后继在 STARTED 回复送达前就结束时，原交接请求仍能确认和重放。
本片解决三个已复现的生命周期缺口，**没有完成冷恢复、旧服务迁移或生产部署**。

基线 Core `196d9409af6f0300ea4c47aecdc6d4532ac0958e`、Pro
`ea071a42dffa72c11ee3fd714e888c6f25bef01a`。Core 修改五个既有源码文件，新增一个源码模块、
两个测试文件；Pro 产品源码和全部既有测试保持原件。

## 行为与依据

- 宿主持有实际 Popen 与原 pidfd，可在子进程退出后继续确认这个具体子进程。
  不重新打开历史 PID；普通外部 observer 仍要求当前活进程。
- 完成确认核对原请求、ACK、成员、执行产物、预算、完整控制器历史和内核退出。
  空队列、实际 CPU 动作，以及首次观察前就完成的初始控制器均覆盖。
- 宿主在自然结束后仍存活，status 显示 stopped，watchdog 不再发起交接；stop 写入
  完整关闭记录后退出。缺 ACK、损坏 ACK、未结算孤立预算或其他进程身份均拒绝。
- 后继在 STARTED 回复送达前自然结束，甚至该回复丢失时，仍核实同一已完成交接。
  其他请求不能替换待确认请求；原请求重放、watchdog 复核都不增加第三个控制器。
  PREPARED 阶段与独立外部交接仍要求活的后继，新增能力只用于持有实际子进程的宿主。
- 宿主退出后的 status 通过单独只读进程加载原项目，核验配置、运行包、登记和关闭历史。
  存盘关闭记录只提供信息，不提供新的进程控制或启动授权。
- 已关闭卸载还核验三个选中 unit 的有效文本、路由、inactive 状态、MainPID=0 与空 cgroup，
  每次管理动作前复核。仅发出 disable（不带 --now）及最终 daemon-reload，保留项目状态、
  配置和其他项目 unit。仍活跃、存在 PID／cgroup、timer 路由或 Install Also 变化、记录损坏，
  以及首次 disable 后服务又活跃，都阻止后续删除。

所有产品子进程均为本测试创建的真实 CPU CLI／worker。systemd 属性和管理命令使用替身，
没有调用现有服务、实际模型、许可、账户或 GPU。unit 状态核验是逐次观察，不能抵御同 UID
任意恶意并发改写；实际 systemd／特殊路径的属性格式仍需部署验证。

## 验证与保留的失败

最终定向 111 项通过，包含 21 项新增场景。独立 stdlib 检查器完整核对 7 个正向作用域的
出生记录、注册、请求／ACK、成员、effect 与预算，其中有 5 次实际 CPU 动作；另外核对
14 个异常场景留下的损坏状态和管理调用。瞬时退出顺序与无关进程存活由产品测试验证，
静态检查不能替代这些运行观察，也不是额外的研究实验。

原自然结束行为有三项失败；首版快速结束夹具挂钩了错误的模块实例，修正版强制等待真实
子进程退出后才执行首次观察，仍复现失败。已关闭卸载单项失败来自原入口必须连接活宿主。
另两项真实失败覆盖 STARTED 送达前结束和同情况下丢失回复，候选版本修复后通过。

baseline 的 exit 4 来自测试文件名写错，未执行测试，不计作产品退化。targeted-v3 的唯一
失败来自新测试尝试向已经停止的预算正常预留动作；产品正确拒绝。v4 改为明确注入未结算
损坏记录以验证完成检查，产品代码与 v3 相同。所有失败和夹具修正前后的输入均保留。

## 仍然开放

关闭记录不能代替冷启动授权。停止后重新安装、原作用域冷恢复、旧 raw-PID 服务迁移、
状态备份／回滚和真实 systemd 部署仍未完成；不得删除登记来强制重启。
本片没有新增端到端研究提速或质量对照，不能从新增测试或生命周期可靠性推导科研能力提高。
当前已有收益与缺失证据见[研究进展评估](2026-09-16-research-progress-assessment.zh-CN.md)。
原 P1／P2／P3 目标仍开放。
