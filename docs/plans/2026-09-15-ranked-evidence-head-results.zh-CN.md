# Pro 代码演进：只保留当前合格排名前十

基于 Core `c3b3159df7bbb87e3a80b134ca70f10e59320068`、Pro `b1a87dbe6c45670f7a4ad1f03bb169c11badbacd`。代码演进上下文原本读取全部完成 ID、保留所有合格行并排序，然后只展示前十。本片沿用当前资格与完整 Objective 排序键，分批读取生命周期，扫描结束后返回前十。全历史资格核验和家族统计仍执行，完整上下文两轮耗时基本持平。

## 范围与行为

新增排名头部读取 API，接受 1–256 的整数上限；实际代码演进调用固定十条。每个生命周期页最多 128 个 ID，每个候选仍调用原有带来源身份的资格函数。主指标、次指标、缺失值与稳定 ID 顺序保持一致；缓存榜单只提供显示标题，不提供分数或资格。只有扫描正常退出才发布选中结果，扫描期间的数据库变化拒绝整个临时排名。

公共全量排名、其他研究上下文、家族统计、失败检查、prompt 格式、provider 调用、决策合约、提案写入与 Core 执行源码均保持原件。研究上下文的底部对照和统计仍需要完整列表，不能直接换成前十。当前优化限制排名中间结果和生命周期 ID 的保留，不限制完整资格工作量、上游单条来源大小或整个进程内存。

## 行为验证与保留的失败

- 123 项既有基线通过，20.75 秒。
- 新成本检查在旧实现上失败：实际演进上下文仍读取全局完成 ID。保留 1 失败、10 未选择，1.90 秒。
- 新增 11 项检查，定向合计 134 通过，24.90 秒。包括后页最优项、完整排序与身份一致、非法上限和扫描期间晚到提交的整体拒绝。
- 64 对固定当前输入差分覆盖 1／10／64／256 的排名长度、升降序、并列、缺失指标、taint、损坏／删除产物、生命周期冲突、伪造显示榜单和缺失数据库。新旧完整选中输出一致，包括资格与内容身份，读取前后数据库及作者源不变。归档保留一个可恢复基线、逐项精确变更计划与双方输出，不声称保存了 64 个独立数据库。
- 私有原型保留旧成本失败、新旧契约检查，以及将原有 54 项报告契约显式导向新头部读取的通过记录；默认公共全量入口未改动。

实际产品路径使用确定性本地 provider 读取真实演进 prompt，由正常决策合约／源锁写入一条提案，再由 Core CLI 执行。两个项目均导入 260 条完成元数据；第三页的最佳来源正常时选择第 259 项，该项 taint 时选择第 258 项。两次真实 CPU worker 输出 `[1, 3, 5]`，核验关闭、结算、产物 SHA 和新进程重放。每个演进调用的排名阶段核验 260 条、成员集合最多 128、全局 ID 读取零次；这些计数不包含另行保留的家族资格扫描。共两次本地 provider、六次独立 CLI；导入历史不等于研究执行，本地 provider 也不等于真实模型。

第一版产品夹具曾把 CPU v2 与 legacy evolution preset 放进同一配置，Core 按现有规则拒绝。保存了成功的 Pro proposal、Core 错误日志、零 CPU worker 和外层失败；内层退出码未独立保存，文档不补造。修正仅将两份合法配置在启动前固定，分别用于演进与 CPU 队列，之后重跑两个完整项目。
