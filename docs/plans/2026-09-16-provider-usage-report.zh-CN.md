# 研究用量核验：按独立请求清单保留未知与缺失

新增只读用量核验 API／CLI。输入为独立请求清单与固定 SHA-256 的日志，输出逐请求／逐尝试结果、已知 token 小计以及仍未知的完整用量。它不调用模型，不改变预算或研究决策。原 Core 产品源码、两仓既有测试均未修改。

**本片完成计量工具，没有新增科研收益证据。** 日志结构完整不表示研究成功、覆盖整个项目或费用已知。费用 USD 始终未知；失败传输可能已经计费，不能把缺失用量换成零。

## 行为与边界

- 预期请求来自捕获的控制器身份与 prepared prompt manifest，不从现存成功日志反推分母。辅助函数核对 native 身份，但调用方仍须核对完整任务范围、模型／输入和评价器。
- 缺失请求、重复／歧义调用、无法归属的记录及未绑定旧响应均保留。调用开始／结束、尝试顺序、身份、写入失败与终态不一致会阻止完整结论。
- 可用 token 总量从保留的 provider 数值字段重新归一化，逐字段比对；坏类型、缺失、矛盾及不支持的用量保持未知。已报告的失败成本仍进入已知小计。
- CLI 以新文件输出，退出 0／2／1 分别为结构完整／不完整／不可用；任一退出码都不证明账单、质量或预算合格。
- 读取前捕获调用方提供的有界元数据；调用方后续修改清单不能重标已选中的日志。固定普通文件身份与完整摘要，拒绝链接、FIFO、读取期间替换、部分行和非法 JSON。
- 上限为 128 份日志、10,000 个预期请求、64 MiB 日志总量、100,000 条记录、每行 16 KiB；CLI 清单不超过 1 MiB。超限明确不可用，不静默截断。不是原子多文件快照或持久化保证，也不限制产品自主研究时长。

## 实际产品链与缺失对照

两轮各建立一组新的隔离项目：重试路径经历两次离线 HTTP 替身传输，产出提案并启动一次真实 CPU worker，随后新进程重放；拒绝路径一次替身传输，不启动 worker。最终轮独立核对数据库、产物 SHA、TREE_CLOSED 与 SETTLED。每轮均为 1 次实际 CPU、3 次离线传输、0 次外部模型调用；两轮不是两组科研实验。

重试路径结构完整，但首次异常的用量未知，所以完整 tokens、provider calls 和 USD 均未知，已知 token 小计为 5。拒绝路径完整 tokens 为 5、返回调用为 1，USD 仍未知。API 与新进程 CLI 输出一致。

这两条 A 臂记录进入 Core 对照归约器，计划 4 项、提供 2 项，缺失的 2 条 B 臂仍为 missing。没有独立科学评价，因此 quality.valid／confirmed 为 false、score 为 null；没有合格配对或组中位数。协议是事后接线控制，输入摘要中含明确的替身标识，不能当成预注册研究。

## 完整命令成本

## 失败、修复与回归

1. 功能不存在时收集失败，退出 2；这是新增功能缺失，不冒称旧产品错误。
2. 首版调用方清单可在解析回调期间被修改，结果曾以 complete 输出不一致的请求／调用绑定。只读复现退出 1，两项输入捕获检查均失败；原件保留。
3. 隔离修复原型 36 项通过；后续补充非法 UTF-8 路径处理，37 项通过。正式版在 I/O 前复制有界清单、记录及绑定，原复现通过，最终定向 141 项通过。
4. 初版 Pro 全量 1,644 项通过仍未发现该缺口，不能用测试总数代替正确性结论。修复后 Pro 全量 1,647 项通过，最终配对 31 项通过。Core 全量 5,278 通过、6 可选跳过、2 既有 warning；它早于仅 Pro 新审计模块的修复，Core 完整输入始终不变，配对和最终 Pro 回归覆盖修复后的两仓输入。没有把 Core 全量描述成修复后重跑。

所有有效运行输入前后一致；执行句柄已明确结束。6 份私有归档、288 条文件／链接记录与原目录逐字节核对；保留 12 份 Git 基线和 9 份候选／原型快照。独立进程机械核验不等于另一位审阅者，重叠用例不相加。

## 对研究收益的判断

此前 24 对 CPU 示例中，两个默认任务动作 5→4、完整 CLI 约 4.9→3.4 秒，两个反事实无同样收益；有效观察 72→60，首次有效证据没有一致改善。5,000 条单文件历史导入约 17.8→3.8 秒是特定处理路径的收益。这些结果不能证明近期累计改动提高了真实模型的假设质量、反例利用或等预算研究产出。
