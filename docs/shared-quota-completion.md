# 共享配额与角色自身等待（V1-03A1）

本切片只修正共享配额被角色完成记账覆盖的问题，不代表 V1-03 或整个 V1 完成。

配置 `rate_limit_group` 才会共享配额黑窗；框架不根据模型、backend 或凭据猜测账户相同。当前同一控制器中已配置且启用的成员接收绝对 `rate_limited_until`，新的限流只能延长相应成员已有的期限。已经运行的角色不因配额通知被杀死，训练/评估数据面不受这项角色门控影响。

普通成功、空输出退出、超时或错误都不是共享配额恢复的证明，不能清掉黑窗。配额期限也不能写入 `cooldown_override`，否则另一个角色较晚完成、更新 `last_run_time` 时会把同一配额等待重新计时。

角色自身失败策略与正常 cadence 保持独立的既有语义：超时、持续空输出与错误阈值仍设置自身退避；正常成功可清自身退避。既有 GOAL 修改可绕过自身相对退避的行为在本切片保留，但不能绕过配额。这里没有声称已将所有失败策略改为 `failure_retry_at`，也没有改变研究队列/证据节奏策略。

## 旧状态迁移

旧 `rate_limited_until` 与 `cooldown_override` 同时存在时，无法从历史字段确定后者有多少来自配额、有多少来自真实失败。迁移在覆盖旧完成时间之前进行：将混合相对等待按原 `last_run_time` 固定为一次兼容绝对期限，最多保留迁移时起 24 小时，记录来源不明的诊断并标记 schema。不能在后续 tick、较晚完成或状态重新加载时重新起算。只有角色的新自身结果策略会替换这个兼容等待。

没有配额的普通旧失败状态保留原相对策略。无法验证的旧配额数值（例如 NaN、Infinity 或 bool）转成一次有界等待；不是静默放行，也不是永久无限等待。旧 quota 字段的测试预期已显式迁移，完整原文件和行为红测均保留。

## 持久性与范围

`save_state/load_state` 的真实检查点往返已测试；现有状态文件按主机保存，保存周期不因此变成每个结果即时同步。这里不提供跨主机配额一致性、崩溃前尚未保存状态的恢复保证，或动态改组/新加入成员自动继承旧黑窗的账户级服务。

[机器证据](evidence/2026-09-10-v1-03a1-shared-quota.json)记录固定旧提交重放、未改变的测试哈希、兼容迁移、独立复核、最终源码验证与修复提交。共享预算预约竞争、持久需求和默认角色组启动继续按 V1-03 后续切片收口；没有真实 provider、GPU 或研究效率收益声明。
