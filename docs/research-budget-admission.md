# 角色预算准入契约（V1-03C）

本项只关闭已有角色启动预算的并发与故障边界，不代表整个 V1、实际 provider 费用或科研收益已验收。

## 权威与启动顺序

Pro 的 `research_budget` 模块保留 `_reserve_research_attempt` 兼容入口。实际角色派发先校验配置，在 Popen 和持久 trigger 的 lease/ACK 之前预约。无预算仍返回独立 unbudgeted ID，不创建预算账本。启动失败、启动结果不明和控制器崩溃不自动返还已经预约的额度。

`.orze/state/agent_attempts.jsonl` 保留合法旧 baseline/reserved 记录与旧完成次数导入。新增预约须同时满足全局次数、该角色次数和适用后端的 token/美元包络。Token 包络只约束 native research，美元包络只约束 Claude；其他角色仍适用配置的次数上限。账本不是 provider 的实际账单，也不与 subprocess 创建组成事务。

预算独占 `agent_attempts.lock`，复用 Core 已审计的 owner nonce、目录身份和持久 namespace marker；不修改其他通用锁，不按 120 秒年龄抢占现存 owner。未知/死亡 owner 不自动重放，需要先核实账本和未确定操作再显式恢复。

## 写入确认与拒绝

- 只读完整、有界、非重定向的单链接常规账本。重复 JSON key、未知事件、重复 baseline/attempt ID、负数或歧义计数均拒绝，观察不会修复、截断或重置历史。
- 追加前验证当前 owner、文件身份和包含新增记录的完整约束；追加后核对写入、fsync、close、父目录同步、精确字节读回及 owner。
- 零字节写不重试。部分写及发布结果不确定时保留实际字节和不确定 owner，不退款、不进入 trigger lease、不启动进程。
- 必须完成 owner 释放确认才能返回成功。释放失败时不发放本次启动许可；已记录扣费保留。若最后父目录同步失败，owner 目录可能已经删除，因此不声称所有释放故障都必然保留目录。
- 预约拒绝或异常会释放本次尚未启动的角色锁；不会确认或修改待交付 trigger。额度耗尽、owner 不可用与异常账本有稳定诊断原因。

计数必须是非 bool 的非负整数；美元值必须是有限非负整数/浮点数，且可准确表达整数 microUSD。不把亚 microUSD 正上限四舍五入为“无限制”。Claude 的实际命令参数从整数 microUSD 精确格式化，不经浮点数重新舍入。

## 有界性和兼容范围

当前限制为 8 MiB 账本、32768 个非空记录、16 KiB 单行、256 个角色、计数不超过 `2**63 - 1`。新增记录不能把合法账本变成下一次无法读取的账本。达到容量会拒绝，需要显式维护；没有自动压缩、截断或退款工具。

本项不承诺对任意不遵守 owner 协议的外部写入提供原子隔离，也不是跨主机 provider 配额服务。旧合法 baseline 可缺诊断 timestamp；非法配置/历史不再通过宽松数值转换获得额度。共享账户冷却和需求门控分别见 A1、B 契约。

首次冷启动新建的所有祖先目录没有逐级 fsync 的验收；本项不宣称任意存储掉电下的整条新目录链原子持久性。已测的是常规控制目录下的预约写入、读回、进程故障与并发边界。
