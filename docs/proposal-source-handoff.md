# 提案源交接与不可覆盖入队

本契约覆盖原生 `ideas.md` 消费、加法 sidecar 入队，以及 Pro 通过 `append_ideas_to_md → locked_append` 写入的提案。SQLite 是已接纳任务的持久存储；源文件只有在对应区块被确认后才可清除。

## 提交与确认

消费者使用与生产者相同的 `results_dir/.ideas_md.lock` 源协议。持锁后才读取新鲜文件字节，不使用旧 mtime 缓存作为入库或删源的依据。主文件单次读取上限为 4 MiB，每轮最多处理 128 个候选；超限或未处理的源内容保留。内存游标用于轮转同一源的候选，不是持久任务/观察账本。sidecar 仍按既有接口读取，不声称本项已经解决全部 sidecar 输入预算。

`IdeaLake.insert(..., if_absent=True)` 是显式的 queued 提案入口，旧默认 import/update API 保留。新入口在自有 `BEGIN IMMEDIATE` 内先检查同 ID，再核查当前配置去重策略。返回结果明确区分：

- `inserted`：本次新建并核实 ideas、QUEUED 状态和实际入队事件。
- `already_present_exact`：源身份字段精确匹配，不改任务、指标、状态或时钟。
- `conflict`、`config_duplicate`、`rejected`：不授权删除源内容。

源身份字段包括标题、配置 YAML、原始 Markdown、优先级、类别、父任务、说明、方法族与任务种类；不把后续执行状态、指标、耗时或时钟纳入精确源重放比较。后续合法编辑了这些源身份字段时，旧源可能保守地成为 conflict，需要显式处理，不覆盖新记录。

只有 `inserted` 与 `already_present_exact` 对应的原始区块可以 ACK。同 ID 多个源区块有歧义时保留；未知标题、解析失败、未接纳区块及原有 header 字节均保留。sidecar 从不被消费删除。

数据库先提交，再以临时文件、fsync、原子替换和回读确认发布删源结果。发布失败不撤销已接纳任务；下一轮精确重放仍可 ACK，不能因为“本轮新增数量为零”而永久滞留，也不能改写已完成任务。提交未实际生效、孤立生命周期、写入回读不符或事务故障均拒绝 ACK。已有调用者事务不会被接管、提交或回滚。

可选 Elo/reflection 只针对已提交的新任务，并在源锁释放之后运行；源 ACK 发布失败不等于数据库未提交。它们不在本项获得新的默认启用权或科学判决权限。

## 源锁与不确定性

源锁不是 60 秒自动到期的执行权限。持久的 `.ideas_md.lock.source-lock` marker 在创建 owner 目录前发布，声明该命名空间必须使用源协议。它不授予任何 owner 权限。generic `_fs_lock` 不能再接管这个命名空间；其他普通角色锁保留旧行为。

源 owner 使用 nonce、目录身份和元数据摘要核实持有权；释放只处理匹配 owner，不递归删除未知内容或替代 owner。已有锁——包括本地进程已死、远端状态未知或初始化不完整——不会仅因时间流逝被抢占。自动删除 marker/锁不是恢复方法；需先核实源、finalizer 的持久结果与 owner 状态。

追加与 finalizer 失败时，能确认恢复原始文件则返回失败并释放；恢复本身失败则保留不确定 owner，拒绝后续自动消费。部分写入不能在释放锁后被误当成完整提案。

## 明确边界

协议只协调使用相同源锁的生产者和消费者。消费者会拒绝已经观察到的源替换或所有权变化，但不承诺防御任意不合作写入者的所有 TOCTOU 窗口。Pro 旧直接 API 未提供 `results_dir` 时保留邻近源文件的 fallback 锁路径；需要与原生消费者协调的调用必须传入同一 results 目录。

配置相同的跨 ID 自动去重是保留的旧策略，不等于复验无价值，也不是科学拒绝收据。本项不删除这样的源区块；显式 replicate、独立 attempt/observation 身份属于后续验收。旧 archive/update、portfolio 生成等其他调用不因本项自动获得不可覆盖入队语义。

持久 marker、未确认源锁及冲突源的运维清理尚无自动裁定工具。没有跨主机 exactly-once、跨文件与数据库原子提交、付费 provider 集成或科研效率收益声明。
